## 三、课程报告修改意见

### 3.1 必须修正：BGE-M3 前缀的术语

报告讨论部分将 BGE-M3 的结果描述为“官方前缀提升 +0.0065”。这不准确：本项目 BGE-M3 对照实验使用的是自定义查询前缀，不能称为官方推荐前缀。

建议改为：

> 对 Qwen3-Embedding，按照其推荐的 Instruct 格式构造查询指令后，NDCG@10 提升 0.0243；对 BGE-M3，实验中的自定义查询前缀带来 0.0065 的提升。不同模型应采用各自适用的查询编码配置。

同时统一全文术语：
- Qwen3：使用“按官方推荐格式构造的 Instruct 查询指令”或简写“官方推荐 Instruct 格式”。
- BGE-M3：使用“自定义查询前缀”。
- 不要将两者统称为“官方前缀”。

### 3.2 必须修正：加权 RRF 曲线的数据来源与内容

报告中的加权 RRF 曲线需要重新核对数据源。当前图表存在不同实验结果混入同一条 DuRetrieval 曲线的迹象，图中部分权重位置出现重复/不一致的纵坐标。

请不要手工修补图片，应从对应实验 JSON 重新生成图表，并逐点核对：
- 数据集：DuRetrieval dev。
- BM25 权重：0.1、0.2、0.3、0.5，以及等权基线 1.0。
- 对应 NDCG@10：
  - 1.0：0.7233
  - 0.5：0.7529
  - 0.3：0.7696
  - 0.2：0.7794
  - 0.1：0.7871
- Dense 单路参考值：0.7900。

图表建议：
- 横轴为 BM25 权重，明确标出五个离散配置。
- 纵轴为 NDCG@10。
- 只展示 DuRetrieval 权重实验，不混入 SciFact 数据。
- 可添加 Dense 单路 NDCG@10 = 0.7900 的水平参考线。
- 在 BM25 权重 0.1 处标出 0.7871。

### 3.3 必须修正：加权 RRF 参数集合的口径

报告方法部分写出的扫描集合为 `{0.1, 0.2, 0.3, 0.5}`，但结果表还包含等权配置 1.0。

建议统一写成：

> 在 DuRetrieval dev 上扫描 BM25 权重 0.1、0.2、0.3、0.5，并与等权配置（1.0）进行比较。

不要写成“连续扫描 0.1～1.0”，因为目前记录的是离散参数点，不是连续搜索。

### 3.4 必须核验：实验环境版本

报告中记录 PyTorch 版本为 `2.15.0`。请对照实际运行环境、实验记录或依赖文件核验版本号后再定稿，不要凭记忆填写。其他环境信息（Sentence Transformers 版本、设备、模型 revision）也应以实际实验记录为准。

### 3.5 建议修改：Hybrid 适用条件的结论边界

报告中“RRF 融合的收益依赖两路检索器信号强度接近”容易被理解为普遍规律。当前实验只覆盖两个数据集，建议限定为本项目观察到的现象。

建议改为：

> 在本项目的实验中，当 BM25 与 Dense 的检索效果差距较小时，RRF 融合取得了较好的结果；当两路检索器性能差距较大时，等权融合可能削弱较强检索器的排序表现。

这样与 SciFact、DuRetrieval 的结果相符，同时避免把有限实验提升为普遍定律。

### 3.6 建议改善：图表可读性

- 图 1 同时展示大量方法和两个数据集，横轴标签拥挤。建议拆成英文、中文两张，或只保留核心方法。
- 图 2 质量-延迟散点图的标签重叠。建议只标注 BM25、Dense、等权 Hybrid、最佳加权 Hybrid 等代表性配置。
- 图 3 按 3.2 节重新生成。
- 图表应优先保证字号、图例和轴标签在普通屏幕/打印尺寸下可读，不要为了展示全部数据牺牲可读性。

完整实验结果可以留在表格或附录，正文图表不必承载所有配置。

### 3.7 保留现有的限制说明

以下内容应保留，不要为了让结果更漂亮而删掉：
- DuRetrieval 使用 dev split，权重 0.1 是当前搜索范围内的最佳配置，不是独立测试集结果。
- 当前错误分析案例按 Query 原始顺序抽取，仅用于定性说明，不具有统计代表性。
- 少量案例对术语歧义、领域漂移等原因的解释属于定性分析，不能写成全体错误的统计规律。
- 当前最佳加权 RRF 的 NDCG@10 = 0.7871，仍略低于 Dense 单路的 0.7900；不能写成已经超过或追平 Dense。

## 四、PPT 修改意见

### 4.1 优先补充：程序/实验流程图

课程评分标准明确要求模型框图或流程图。PPT 当前的文字流程描述不足以充分展示程序结构。

建议增加一张简洁的流程图，至少包含：

1. 数据输入：Corpus / Queries / Qrels。
2. BM25 分支：分词、倒排索引、候选排序。
3. Dense 分支：Embedding 编码、向量检索。
4. Hybrid 分支：BM25 与 Dense 结果进入 RRF 融合（可选分支）。
5. 统一评价：P@K、R@K、MRR、NDCG@K、耗时。
6. 结果输出：JSON、图表、错误分析。

重点是体现程序模块和数据流，不需要把每个函数或类都画进去。

### 4.2 建议压缩：适配 3 分钟讲演

当前 PPT 共 17 页。若每页都讲，3 分钟内很难充分解释实验结果。建议将主要讲演内容压缩到约 10～11 页；详细公式、完整模型列表和补充图表可以放到附录页，现场不逐页讲解。

可参考以下结构：
1. 封面与研究问题。
2. 程序/实验流程图。
3. 数据集与实验规模。
4. BM25、Dense、Hybrid 方法概览。
5. 实验设置与评价指标。
6. SciFact 关键结果。
7. DuRetrieval 关键结果与加权 RRF 曲线。
8. 错误分析：三类分布及 Hybrid 收益/损失。
9. 讨论与局限。
10. 结论与致谢。

不要求机械地按此结构删页，重点是让讲演主线清楚，并把时间留给关键结果。

### 4.3 必须同步修正：加权 RRF 图

PPT 中对应的加权 RRF 图也需要按报告 3.2 节的正确数据重新生成。报告和 PPT 应引用同一份数据/图表，避免两份材料各自手工维护导致不一致。

### 4.4 建议修正：SciFact 结果说明

PPT 中 SciFact 的加权 Hybrid NDCG@10 = 0.7220 对应 BM25 权重 0.5。建议在图表标签或口头讲解提示中明确这一点，并与等权 Hybrid 的 0.7165 区分。

建议结果表述为：
- Qwen3 Instruct 使 Dense 的 NDCG@10 从 0.6766 提升至 0.7003。
- 等权 Hybrid 达到 0.7165，高于 Dense 单路。
- BM25 权重 0.5 时，加权 Hybrid 达到 0.7220。

### 4.5 建议改善：质量-延迟图

只保留少数代表性配置的文字标签，避免标签互相遮挡。其余点可以保留，但不必全部标注名称。完整图可以留在报告中。

### 4.6 建议改善：错误分析案例

错误分析页的 79 条 Top-1 收益、166 条损失很适合口头解释。建议增加一个具体 Query 的简短对照案例：
- Query 内容。
- Dense 的排序结果。
- Hybrid 的排序变化。
- 该案例说明的问题。

案例只用于解释，不应暗示其具有统计代表性。一个清楚的案例即可，不需要塞入大量文字。

### 4.7 建议增加：程序运行状态证据

评分标准单独包含程序运行状态。可考虑在流程图或实验设置页放一张真实终端运行/结果落盘截图，展示程序成功运行、结果文件生成或实验汇总输出。截图必须来自实际运行，不要制作仿真输出。
