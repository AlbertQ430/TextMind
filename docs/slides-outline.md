## 逐页台词（可直接照读）

### P1 封面与研究问题

> 本项目在统一数据集与评价口径下，比较 BM25、Dense Retrieval 和 Hybrid 三种检索方法，回答「算法与 Embedding 模型差异有多大」这个问题。

### P2 程序/实验流程图

> 程序分三条路径：数据加载后进入 BM25 和 Dense 两个分支，两路结果可经 RRF 融合；统一评价后输出 JSON、图表和错误分析。核心模块是数据加载、检索器、评价指标和结果落盘。

### P3 数据集与规模

> 英文用 SciFact，300 条测试查询；中文用 DuRetrieval 的 C-MTEB 子集，10 万篇文档、2,000 条 dev 查询、9,839 条标注。

### P4 方法概览

> BM25 是关键词基线；Dense 用 bge-small-zh 和 Qwen3 编码后按余弦相似度检索；Hybrid 用 RRF 融合，融合权重可调。

### P5 实验设置

> 评价用 P@K、R@K、MRR、NDCG@K；耗时拆成文档编码、查询编码和向量检索；结果 JSON 记录模型 revision 与参数，保证可复现。

### P6 SciFact 结果

> Qwen3 按官方 Instruct 格式构造查询后，Dense 从 0.6766 提升到 0.7003；等权 Hybrid 到 0.7165；BM25 权重 0.5 的加权 Hybrid 到 0.7220。

### P7 DuRetrieval 结果

> 中文上 Dense 无前缀时 NDCG@10 为 0.7949，明显高于 BM25 的 0.5931；但等权 Hybrid 只有 0.7233，反而低于 Dense——因为 BM25 较弱，融合稀释了 Dense 的排序。

### P8 加权 RRF

> 降低 BM25 权重后，Hybrid 从 0.7233 提升到权重 0.1 时的 0.7871，接近但仍略低于同前缀配置的 Dense 0.7900（无前缀 Dense 为 0.7949）。这是 dev 集上的参数探索，不代表测试集泛化。

### P9 错误分析与案例

> Dense 的 Top-1 命中率 82.6%，召回失败只有 4.3%；错误主要是排序校准。例如「360wifi 密码错误」被检索成 SSL 证书警告页，属于术语歧义与领域漂移。Hybrid 相对 Dense 的 Top-1 收益 79 条、损失 166 条。

### P10 讨论与局限

> 实验观察到：两路信号接近时融合有效，差距大时等权融合被稀释，加权只能缓解。局限是 dev 调参、未做 Reranker、只覆盖两个数据集。

### P11 结论与致谢

> 结论：Dense 优于 BM25；查询指令值得配置；Hybrid 需要按子路质量调权。谢谢，欢迎提问。
