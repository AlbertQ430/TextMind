# TextMind MVP SRS 需求评审记录

> 评审日期：2026-11-21
> 评审对象：SRS 草案 v0.1（历史版本）；当前修订见 [SRS v0.2](SRS.md)
> 评审时结论：**有条件通过，未立即冻结**
>
> 后续状态：D-01 至 D-16 已确认，SRS v0.2 已于 2026-11-21 冻结。

第 2、3 节保留评审时发现的问题和建议，最终执行规则以第 8 节决策记录为准。

## 1. 评审结论

SRS 对产品定位、MVP 边界和已有实验成果的表达总体准确：

- 产品目标仍是将已有 BM25、Dense 和 Hybrid 检索实验封装成本地 Web 实验台，没有偏离到知识库、问答或通用研究平台。
- 预设方案、预置结果、单任务执行、结果记录、历史比较和局域网访问等主要内容与已确认决策一致。
- SciFact、DuRetrieval 的数据划分和现有实验配置能够对应到 SRS 的三类预设方案。
- 当前不纳入 MVP 的查询级结果、错误分析、自由配置、自动调参、云端部署等边界清楚。

但 SRS 仍存在若干会影响结果模型、任务状态和验收口径的歧义。解决本文第 2、3 节的问题前，不宜冻结 SRS，也不宜直接进入 SDS 或实现。

## 2. 必须解决的问题

### R-01 “实验方案”“实验运行”“实验变体”的关系未定义

**位置：** 1.3 术语、2.4 预设实验方案、3.3 任务调度、3.5 结果文件、3.6 历史比较。

**问题：** SRS 将实验方案定义为“一组实验配置”，但没有说明用户点击“运行”时执行的是：

1. 方案中的一个实验变体；还是
2. 整个方案中的全部实验变体。

这会影响一次任务的状态、一个结果 JSON 的内容、取消和失败记录、历史列表粒度以及同方案比较方式。当前现有 JSON 每个文件只保存一个实验变体，而 SRS 的“一次运行一份 JSON”更像是整个方案运行一次生成一份记录，两者尚未统一。

**建议基线：**

- 实验变体（Variant）是一个固定配置，例如“SciFact + Dense + Qwen3 Instruct”。
- 实验方案（Plan）是一组有序实验变体。
- 用户提交方案后，一次实验运行（Run）执行该方案的全部变体。
- 一次运行对应一个运行 ID、一个结果 JSON、一个结果目录和一组方案级图表。
- 结果 JSON 中包含 `variants[]`，每个变体具有稳定 `variant_id`、配置、状态、指标、耗时和错误信息。
- 历史列表以方案运行记录为粒度；比较时按 `variant_id` 对齐两次运行的变体结果。

如果选择“每个实验变体单独运行”，则必须重写当前方案选择、历史归组和比较流程，不能继续将“方案运行”作为唯一任务粒度。

### R-02 等权 RRF 结果同时属于两个 DuRetrieval 方案，归属规则未定义

**位置：** 2.4 方案表、5.2 记录标识、3.6 同方案比较。

**问题：** `duretrieval-comparison` 包含等权 Hybrid，`duretrieval-rrf-weight-sweep` 也包含 BM25 权重 1.0 的等权 Hybrid。现有结果中这两项是同一个实验测量，但 SRS 假定每个运行记录只有一个方案 ID，没有说明该结果应：

- 复制到两个方案；
- 允许一个结果属于多个方案；
- 由一个方案引用另一个方案的预置结果；
- 或在其中一个方案中取消 1.0 基线。

直接复制会让历史记录出现两个含义相同但运行 ID 不同的结果；常见的一对多方案归属又与当前单一 `plan_id` 语义冲突。

**建议基线：**

- 保留两个方案各自完整的变体列表。
- 预置结果可通过来源关系复用同一原始实验结果，但各自运行记录中的变体由稳定 `variant_id` 标识。
- 用户重新运行方案时，将每个方案视为独立运行；可通过缓存复用计算，但不合并运行历史。
- 预置结果若复用原始 JSON，应保留来源标识，不能伪造为另一次独立运行。

### R-03 “当前运行生成的图表”与现有全局汇总图不一致

**位置：** FR-043、FR-051、FR-053。

**问题：** 现有 `data/evaluation/figures/` 下的图表是由多个结果 JSON 全局汇总生成，部分图表跨数据集合成，并不是某一次运行产生的单次产物。SRS 同时要求：

- 每个运行目录包含该次运行图表；
- JSON 用相对路径引用图表；
- 结果页只展示当前运行产生的图表，不得错误关联其他方案。

当前存量图表不能直接作为单次运行图表使用，否则方案归属和数据口径会产生错误。

**建议基线：**

- 每个方案定义图表清单及其数据来源范围。
- 用户重新运行方案后，从该次运行的全部变体生成方案级图表，并写入本次运行目录。
- 预置结果使用按同一规则生成的预置图表，不能直接引用跨方案或跨数据集的全局课程汇总图。
- 失败、取消或指标不完整的运行可以缺少图表；完成运行中，方案声明为必需的图表应存在。
- 现有全局汇总图继续作为课程材料，不作为 MVP 运行记录图表。

### R-04 方案版本和比较对齐规则不完整

**位置：** 5.2 记录标识、FR-072、FR-073、NFR-001。

**问题：** SRS 只说“方案 ID 在方案版本范围内稳定”，但没有定义方案版本变化后的行为。如果方案增加、删除或修改某个变体，继续用相同方案 ID 比较新旧记录，可能把不同实验集合误判为同一方案。

同时，SRS 要求比较多次运行，但没有说明按实验顺序、模型名还是稳定变体 ID 对齐。依据顺序对齐容易因配置调整而错配指标。

**建议基线：**

- 方案记录同时保存 `plan_id` 和 `plan_version`。
- 方案定义发生语义变化时提升 `plan_version`；不得静默改变已有版本的定义。
- 历史比较要求 `plan_id` 和 `plan_version` 相同。
- 两次运行中的变体按稳定的 `variant_id` 对齐；缺少对应变体时明确显示不可比较。
- 显示指标原始值和差值，但不生成自动分析报告或因果结论。

### R-05 服务重启后的等待队列行为未确定

**位置：** FR-029、FR-030、NFR-011。

**问题：** SRS 明确异常退出后将未正常结束运行标记为 `Interrupted`，但没有规定未开始执行的 `Pending` 任务在服务重启后是：

- 恢复为等待任务继续排队；
- 从队列移除；
- 保留记录但标记取消或中断；
- 或直接丢失。

“等待任务不应被误记为已完成”不足以形成可验收行为。

**建议基线：**

- 已开始执行的任务在异常退出后标记为 `Interrupted`，不支持续跑。
- 尚未开始执行的等待任务持久化并在服务重启后恢复为 `Pending`，继续按原提交顺序排队。
- 等待任务在恢复前被用户取消时，移除并不生成运行记录。
- 正常关闭时同样保存等待队列；当前运行任务按取消规则处理或明确标记中断。

### R-06 “安全取消”没有可完成性和超时规则

**位置：** FR-024、FR-029、AT-008。

**问题：** 当前检索流程中的模型加载和批量编码没有天然协作取消检查点。SRS 要求先进入 `Cancelling`，在安全停止点完成后变为 `Cancelled`，同时规定不得将强制终止底层进程作为常规取消方式。但没有定义：

- 等待安全停止的最长时间；
- 超出时间后任务状态；
- 底层操作无法响应取消时用户如何处理；
- 强制终止是否允许作为最后手段。

按当前文字，任务可能长期停留在 `Cancelling`，且没有可验收的退出路径。

**建议基线：**

- 实验执行放在独立子进程中，取消时先发送协作停止请求。
- 在固定等待时间内完成安全清理并标记 `Cancelled`；超时后允许强制终止子进程，仍标记 `Cancelled`，并记录“强制终止”。
- 强制终止作为最后手段，不是常规取消步骤。
- 若暂不引入子进程隔离，则应放宽 SRS，明确查询编码等不可中断阶段只能等待结束，并提供“无法及时取消”的说明。

## 3. 应修正或补充的问题

### R-07 耗时名称存在内部矛盾

**位置：** FR-042。

SRS 将“向量检索均值”定义为“单条查询端到端检索耗时，不包含查询编码”。该名称对 BM25 不成立，对 Hybrid 也不准确，因为 Hybrid 单条耗时包含 BM25、Dense 检索和 RRF 融合。

同时，现有结果还包含 `bm25_search`、`dense_search`、`rrf_fusion` 等阶段，SRS 的阶段清单只列出了“向量检索”。

**建议修正：**

- 将“向量检索均值”改名为“单查询检索耗时”或“端到端检索均值”。
- 保留各子阶段耗时：BM25 检索、Dense 检索、RRF 融合。
- 明确该均值不包含查询编码，但不能把子阶段耗时重复加到总耗时中。
- Dense 方案的检索耗时等于向量检索耗时；BM25 和 Hybrid 按各自实际流程统计。

### R-08 方案整体失败、部分成功的结果语义未定义

**位置：** FR-025、FR-027、FR-030、FR-075。

如果一次方案运行包含多个变体，必须定义：

- 某个变体失败时是否继续后续变体；
- 已成功变体的指标是否保留；
- 方案级状态应是 `Failed` 还是部分完成；
- 取消时已完成变体是否可用于查看。

**建议基线：**

- MVP 采用失败即停止后续变体，已完成变体结果保留。
- 方案运行为 `Failed`，并记录失败阶段、失败变体和已完成变体。
- 不增加“部分完成”这一顶层状态，避免状态体系膨胀；结果页明确展示变体完成情况。
- 用户再次运行创建新的方案运行记录。

### R-09 资源可用性检查的粒度需要明确

**位置：** FR-013、FR-014、FR-084。

SRS 当前以“方案是否可用”为粒度，但缺少模型或数据集时，方案中的一个或多个变体会不可运行。需要明确是：

- 任一必需资源缺失时整个方案不可提交；
- 还是允许只运行资源齐全的变体。

**建议基线：**

- 预设方案作为完整比较集合运行；任一必需资源缺失时，整个方案标记为不可运行并列出缺失资源和受影响变体。
- 预置结果仍可浏览，不受当前资源缺失影响。
- 不提供裁剪方案或选择部分变体运行的入口，保持 MVP 范围。

### R-10 导入记录遇到未知方案或未知变体时的行为未定义

**位置：** FR-054 至 FR-058、FR-075。

格式版本兼容不代表当前应用认识记录中的方案和变体。需要明确：

- 未知方案 ID 是否允许导入；
- 未知变体是否允许查看；
- 未知方案记录是否参与历史比较；
- 缺少原始设备环境时是否仍允许导入。

**建议基线：**

- JSON 结构与格式版本兼容时允许导入和只读查看。
- 未知方案或变体显示为“未知方案/变体”，不伪造名称。
- 无法确认同方案和同版本时，禁止参与历史比较。
- 可选环境字段缺失时显示“未记录”，不阻止导入；核心指标和运行状态仍须符合 Schema。

### R-11 预设方案的“完整映射”尚未形成可冻结配置

现有结果可以完整映射三套方案，但 SRS 只给出了建议方案 ID 和自然语言配置。进入设计前，应把以下内容固定为方案定义的一部分：

- 数据集名称、语言和划分；
- 每个实验变体和稳定 `variant_id`；
- 算法、模型、revision、查询前缀；
- `top_k`、评价 K、BM25 参数、RRF k 和权重；
- 预置结果 JSON、图表和来源；
- 方案版本。

仅靠自然语言描述和文件名不足以作为稳定接口。

### R-12 文档间仍有一处直接措辞冲突

**位置：** [已确认决策第 2 节](confirmed-decisions.md)。

该处写实验结果页会查看“指标、图表、检索结果及详情”，而 SRS 和产品范围明确说明 MVP 不展示查询级检索结果。应将“检索结果”改为“运行结果”或明确为“聚合指标结果”，避免将 query-level 结果误认为 MVP 功能。

### R-13 产品范围中仍有失效的阶段描述

**位置：** [当前产品范围第 6 节](../project-scope.md)。

该处仍写“服务重启时的任务恢复策略仍待确定”，但已确认决策和 SRS 已规定运行任务在异常退出后标记为中断。该文档应随 R-05 的最终决策一起更新，避免修订后仍保留旧描述。

### R-14 重复导入同一运行 ID 的处理规则缺失

**位置：** FR-050、FR-054、FR-055、5.2 记录标识。

SRS 要求运行 ID 唯一，并允许用户反复导入 JSON，但没有定义当导入记录与已有记录具有相同 `run_id` 时如何处理：

- 覆盖已有记录；
- 拒绝重复导入；
- 为导入副本生成新运行 ID；
- 保留相同运行 ID 但增加导入实例 ID。

覆盖会破坏已有记录，直接接受重复运行 ID 又会违反唯一性要求。

**建议基线：**

- 按 JSON 中的 `run_id` 检测重复。
- 相同运行 ID 已存在时拒绝本次导入，并提示已有记录位置或运行 ID，不覆盖任何文件。
- 若用户确实需要保留另一份文件副本，应通过修改来源记录获得新的唯一运行 ID，而不是由导入过程静默改写原记录。

### R-15 验收场景没有覆盖全部关键需求

**位置：** 第 7 节验收标准。

当前 20 个验收场景覆盖主要闭环，但以下关键行为没有直接验收项：

- 多客户端看到一致的任务队列和历史记录；
- 服务正常关闭时等待队列和当前任务的最终状态；
- 单查询检索均值与分阶段耗时的口径；
- 方案运行中部分变体完成、后续变体失败时的结果保留；
- 同方案、同版本记录按 `variant_id` 对齐比较；
- 导入 JSON 的路径越界防护；
- 自动下载模型或数据集的负面验收；
- SciFact 来源、署名和许可证随包提供；
- 资源缺失时列出具体缺失项和受影响变体。

验收标准应至少覆盖这些高风险行为和不可接受结果，而不必为每条非功能需求机械增加一个场景。

## 4. 约束必要性评估

### 建议保留

- 本地 Web、默认仅本机访问、局域网访问需显式开启和临时访问码。
- 同一时间一个运行任务、单份 JSON 导入、无账号体系。
- 不提供 query-level 检索结果、自由实验配置、自动调参和通用插件系统。
- 不自动下载或整理模型和数据集。
- 结果 JSON 使用相对图表路径并限制目录边界。

这些约束与产品定位直接相关，能控制 MVP 复杂度，未发现明显范围漂移。

### 建议放宽或重新确认

1. **禁止实验中心展示数据集规模**

   “禁止展示”本身不能直接服务用户目标，且数据规模对判断运行成本有帮助。建议改为：数据集规模不是方案选择的主信息，但可在方案详情或运行预估中显示；不必在 SRS 中禁止。

2. **完全不提供应用内删除记录**

   该约束可以保留，但会给用户带来文件系统操作负担。若坚持保留，应在结果说明和错误提示中明确记录目录位置及删除影响。该约束已经过确认，不属于 SRS 内部矛盾。

3. **Windows 与 macOS 同时作为 MVP 验收要求**

   当前开发与验证环境是 macOS。双平台脚本和浏览器验收会显著增加交付量，但这是已确认的分发目标。建议保留目标，同时在验收计划中明确哪些功能必须在两平台实机验证，哪些允许共用 Python 逻辑。

4. **等待中的任务取消后不生成任何记录**

   该规则与运行中任务保留记录不同，用户可能无法追溯“曾经提交过但已取消”的任务。可以保留现有决策，但建议在界面上明确区分“等待任务取消后立即消失”，避免误以为记录丢失。

## 5. 三套预设方案映射核对

### 5.1 SciFact 对比方案

共 9 个唯一变体，现有结果均可对应：

| 实验变体 | 关键配置 | 现有结果 |
| --- | --- | --- |
| BM25 | k1=1.2，b=0.75，simple tokenizer | `scifact_bm25_20261120_002601.json` |
| Dense Qwen3 无前缀 | Qwen3-Embedding-0.6B | `scifact_dense_20261120_131030.json` |
| Dense Qwen3 Instruct | Qwen3-Embedding-0.6B，官方推荐 Instruct 格式 | `scifact_dense_prefix_eec03840_20261120_131037.json` |
| Dense BGE-M3 无前缀 | BAAI/bge-m3 | `scifact_dense_20261120_131044.json` |
| Dense BGE-M3 自定义前缀 | BAAI/bge-m3 | `scifact_dense_prefix_9c844c72_20261120_131052.json` |
| Dense all-MiniLM | all-MiniLM-L6-v2 | `scifact_dense_20261120_131056.json` |
| Hybrid 等权无前缀 | BM25 + Qwen3，RRF k=60 | `scifact_hybrid_20261120_132149.json` |
| Hybrid 等权 Instruct | BM25 + Qwen3，RRF k=60 | `scifact_hybrid_prefix_eec03840_20261120_132157.json` |
| Hybrid 加权 Instruct | BM25:Dense = 0.5:1.0 | `scifact_hybrid_prefix_eec03840_w0.5_1_20261120_213538.json` |

另有一份重复 BM25 运行 `scifact_bm25_20261120_004326.json`，指标与首选 BM25 记录一致。预置结果只能指定一份作为该方案的来源，不能在方案中重复列出。

### 5.2 DuRetrieval 方法对比方案

### 5.4 结果覆盖结论

- 三套方案合计需要 18 个变体条目。
- 其中等权 Hybrid 在 DuRetrieval 两个方案中复用，因此对应 17 个唯一原始实验结果。
- 现有 17 个唯一配置均有结果 JSON，另有 1 份重复 BM25 运行，不构成配置缺失。
- 当前结果 JSON 是单变体原始产物，不具备方案运行所需的运行状态、方案版本、变体 ID、图表路径和时间字段，不能未经转换直接作为 MVP 运行记录使用。

## 7. 冻结条件处理结果

首轮评审列出的阻断项已通过第 8 节 D-01 至 D-16 完成决策：

1. 确定每次任务只执行一个变体，每个变体运行生成一份 JSON。
2. 确定等权 RRF 结果只在方法对比方案中拥有运行记录，在 RRF 方案中只读参照。
3. 确定单次运行与比较页面各自负责的图表范围。
4. 增加方案版本、变体 ID 和同版本比较规则。
5. 确定正常关闭和重启均清空等待队列。
6. 确定取消采用阶段边界停止，不强杀 Python 进程。
7. 修正耗时名称、字段层级和验收口径。
8. 确定单变体失败和资源缺失只影响对应变体。
9. 确定未知记录、重复运行 ID 的导入规则并补齐关键验收。
10. 删除 JSON 中的结果来源和导入时间，改由结果目录区分来源。

SRS v0.2 已按上述决策完成修订并冻结，作为 SDS、任务拆分和开发验收的基线。

## 8. 评审决策确认记录

### D-01 实验运行粒度

**状态：已确认。**

- 每次任务只执行一个实验变体。
- 实验方案用于组织和归组一组相关变体，不是一次任务的执行单元。
- 每次运行生成独立的运行 ID、结果 JSON 和结果目录。
- 结果记录同时保存 `plan_id`、`plan_version`、`variant_id` 和 `run_id`。
- 历史列表以单个变体运行为记录粒度。
- 同一方案内可以比较不同变体或同一变体的多次运行；比较时必须使用相同的指标口径并明确对应变体。
- 现有单变体结果 JSON 与这一粒度一致，后续可扩展为正式运行记录。

### D-02 DuRetrieval 等权 Hybrid 结果归属

**状态：已确认。**

- 等权 Hybrid 的正式运行记录归属 `duretrieval-comparison`。
- 在 `duretrieval-rrf-weight-sweep` 中，该结果作为只读参照指标和图表参考线展示。
- 加权 RRF 方案的历史可比较运行只包含 BM25 权重 0.5、0.3、0.2、0.1 的变体。
- 参照结果不复制成新的运行 ID，也不伪造成加权 RRF 方案中的独立运行。

### D-03 单次运行与比较图表

**状态：已确认。**

- 单次结果页只展示该变体自身的指标、分阶段耗时和本次运行实际产生的图表。
- 单次运行目录中的图表不得引用其他变体的数据。
- 算法、模型和 RRF 权重对比图在用户选择多条同方案记录后，由比较页面生成。
- 比较图表是查看时生成的派生视图，不写回任何单次运行 JSON。
- 现有跨结果全局汇总图不直接关联到单次运行记录。
- 预置方案可以使用单独生成的方案级参考图，但必须标明数据来源和适用范围。

### D-04 方案版本与历史比较

**状态：已确认。**

- 每个运行记录保存 `plan_id`、`plan_version`、`variant_id` 和 `run_id`。
- 方案中的变体集合或关键配置发生变化时提升 `plan_version`，已有运行记录保持原版本。
- 历史比较只允许方案 ID 和方案版本均相同的记录。
- 同一方案版本内可以比较不同变体，也可以比较同一变体的多次运行。
- 指标按指标名称和 K 值对齐；缺少对应指标时明确标记不可比较，不填零或推断。
- 配置差异用于解释运行条件，不自动生成因果分析。

### D-05 服务关闭与重启时的等待队列

**状态：已确认。**

- 正常关闭时停止接受新任务，并取消等待队列中的全部任务。
- 服务重启后，不恢复任何旧等待队列；服务停止前仍处于 `Pending` 的任务全部取消并移除。
- 等待任务被取消时不生成运行记录，沿用已确认的等待任务取消规则。
- 已经执行但未正常完成的任务仍标记为 `Interrupted`，不支持断点续跑。
- 当前运行任务在服务关闭时未完成，不得标记为 `Completed`。

### D-06 运行中任务取消

**状态：已确认。**

- 采用阶段边界取消，在主要阶段之间检查取消请求。
- 模型加载或批量编码等不可中断阶段不强制结束进程，状态保持 `Cancelling`。
- 当前不可中断操作结束后立即停止，不再进入后续阶段。
- 成功停止后保存已产生信息，并标记为 `Cancelled`。
- 界面说明长时间编码阶段可能需要等待当前阶段结束。

### D-07 耗时展示口径

**状态：已确认。**

- 使用“单查询检索均值”取代“向量检索均值”。
- 该均值表示每条查询完成检索所耗时间的宏平均，不包含查询编码。
- BM25 统计 BM25 检索，Dense 统计向量检索，Hybrid 统计 BM25、Dense 检索与 RRF 融合。
- 同时保留适用的分阶段耗时，并明确各阶段的层级，避免重复累加。

### D-08 单个变体运行失败

**状态：已确认。**

- 失败只影响该变体的本次运行记录，其他变体和已有历史不受影响。
- 失败记录标记为 `Failed`，保存失败阶段、错误摘要、技术详情和已完成阶段。
- MVP 不自动重试。
- 用户再次运行时创建新的运行 ID，原失败记录保持不变。
- 不存在方案级“部分完成”状态，每个变体运行的状态相互独立。

### D-09 资源缺失时的运行范围

**状态：已确认。**

- 资源可用性按变体检查。
- 资源缺失时只禁用依赖该资源的变体，同一方案中的其他变体仍可运行。
- 不可运行状态必须列出缺失资源及原因。
- 预置结果不受当前资源缺失影响。
- 应用不自动扫描、下载或修复资源。

### D-10 未知方案和未知变体的导入

**状态：已确认。**

- 格式版本兼容且核心字段有效时，未知方案或未知变体允许导入和只读查看。
- 页面显示原始方案、版本和变体标识，不伪造名称或配置。
- 只有方案 ID 和方案版本均可确认一致时，记录才可参与历史比较。
- 原始环境信息缺失时显示“未记录”，不阻止导入。
- 指标、状态、运行时间等核心字段不符合 Schema 时拒绝导入。

### D-11 预置方案标识与配置

**状态：已确认。**

- 继续使用 `scifact-comparison`、`duretrieval-comparison` 和 `duretrieval-rrf-weight-sweep` 三个方案 ID。
- 三套方案初始版本统一为 `v1`。
- 17 个唯一变体使用稳定的 kebab-case `variant_id`。
- 每个变体保存完整配置：数据集及划分、算法、模型及 revision、查询前缀、BM25 参数、`top_k`、评价 K、RRF k 和权重。
- 每个变体关联已有结果 JSON；预置图表单独标识数据来源，不冒充单次运行产物。
- DuRetrieval 等权 Hybrid 使用同一 `variant_id`，只在方法对比方案中拥有正式运行记录，在 RRF 方案中作为只读参照。

### D-12 结果页措辞

**状态：已确认。**

结果页展示单次变体运行的指标、图表、运行配置、运行环境和状态详情；不展示 query 级检索结果。相关已确认决策文档按此措辞修正。

### D-13 重复运行 ID 导入

**状态：已确认。**

- 按 JSON 中的 `run_id` 检查重复。
- 相同运行 ID 已存在时拒绝本次导入，不覆盖已有记录。
- 提示冲突的运行 ID 和已有记录信息。
- 导入过程不静默生成新运行 ID，也不修改原 JSON 内容。
- 文件内部运行标识不同时，允许作为独立记录导入。

### D-14 关键验收场景

**状态：已确认。**

SRS v0.2 增加或细化以下验收场景：

- 多客户端任务状态、队列和历史记录一致。
- 正常关闭时停止接收新任务并清空等待队列，重启后不恢复旧等待任务。
- 运行中取消按阶段边界生效，不可中断阶段显示 `Cancelling`。
- 单变体失败只影响该运行记录，重跑生成新的运行 ID。
- 单查询检索均值及各分阶段耗时口径正确。
- 资源缺失只禁用受影响变体，并列出缺失项。
- 同一方案和版本的不同变体可以比较，不同版本不可比较。
- 导入图表路径不能越出运行目录。
- 重复运行 ID 被拒绝且不覆盖记录。
- 未知方案或变体可以只读导入，但不能参与比较。
- 应用不会自动下载模型或数据集。
- SciFact 的来源、署名和许可证随软件提供。
- 等待任务取消后不生成运行记录，并向用户明确提示。

### D-15 数据集规模展示

**状态：已确认。**

- 数据集规模不作为方案列表的主要选择信息。
- 方案详情和结果页可以展示数据集规模、标识和划分，以帮助用户理解实验范围。
- SRS 不再禁止展示数据集规模。

### D-16 JSON 来源与导入时间

**状态：已确认。**

- JSON 不保存结果来源和导入时间。
- 结果来源由 `results/presets`、`results/runs`、`results/imports` 顶层目录区分。
- 导入时将 JSON 和可用图表复制到 `results/imports/<run_id>/`，保持原 JSON 内容不变。
- 原始实验时间、配置和设备环境继续保留。
- 用户将单个 JSON 移出结果目录后导致的来源识别问题由用户自行负责。
