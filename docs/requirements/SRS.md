# TextMind 软件需求规格说明书（SRS）

> 文档状态：草案 v0.1，待需求评审  
> 适用范围：TextMind 实验演示型 MVP（A 阶段）  
> 依据：课程实验成果、`docs/project-scope.md`、`docs/requirements/confirmed-decisions.md`、`docs/requirements/retrieval-lab.md`  
> 本文描述产品必须提供的行为与质量要求，不预先限定 Web 框架、前端框架或具体数据库等技术实现。

## 1. 引言

### 1.1 编写目的

本文定义 TextMind 实验演示型 MVP 的产品需求，作为后续系统设计、任务拆分、实现和验收的共同基线。开发过程中如需改变已确认需求，应先更新本文及相关决策记录，再实施变更。

### 1.2 产品范围

TextMind 是一个本地运行的文本检索实验台。用户通过浏览器选择预设实验方案、运行整套基准实验、查看指标与图表，并管理实验运行历史。

MVP 的目标是把已有 BM25、Dense Retrieval 和 Hybrid Retrieval（RRF）实验能力封装成可交互、可观察、可比较的软件。MVP 采用预设方案，不提供自由组合算法、模型或参数的入口。

### 1.3 术语

| 术语 | 定义 |
| --- | --- |
| 实验方案（Experiment Plan） | 稳定定义的一组实验配置及其执行内容，具有稳定方案 ID |
| 实验运行（Experiment Run） | 用户对某一实验方案发起的一次执行，具有独立运行 ID 和结果目录 |
| 预置结果（Preset Result） | 随软件提供、由项目已有实验生成的结果记录，供用户直接浏览 |
| 运行记录（Run Record） | 一次实验运行生成的 JSON 主记录及其附属图表 |
| Corpus | 待检索文档集合 |
| Queries | 用于检索的查询集合 |
| Qrels | Query 与相关文档之间的相关性标注 |
| 主机 | 启动 TextMind 服务、持有数据集和模型文件的计算机 |
| 客户端 | 通过浏览器访问 TextMind 的本机或局域网设备 |

## 2. 总体描述

### 2.1 产品视角

TextMind 是围绕现有 Python 检索实验核心构建的本地 Web 应用。浏览器负责展示和交互，主机服务负责实验调度、资源访问、执行、结果存储和局域网访问控制。

系统不依赖云服务。关闭浏览器不应终止已提交的实验任务；服务退出则会按任务生命周期规则处理正在执行的任务。

### 2.2 用户与使用环境

- 主要用户：希望演示、观察和比较文本检索算法实验的课程项目使用者。
- 主机环境：Windows 或 macOS；用户自行准备 Python 环境、DuRetrieval 数据集和所需 Embedding 模型。
- 客户端环境：通过现代浏览器访问主机提供的 Web 页面。
- 局域网访问面向用户信任的私人局域网，不面向公共网络或互联网。

### 2.3 产品路线与范围边界

本 SRS 只覆盖 A 阶段实验演示型 MVP。后续 B 阶段可以在稳定基础上增加有限的算法、模型和参数配置，但不属于本版本验收范围。

**本版本包含：**
- 本机 Web 服务与可选局域网访问。
- 预设实验方案和可浏览的预置结果。
- 实验提交、单任务执行、等待队列、阶段状态与取消。
- 指标、耗时、图表、配置和运行环境展示。
- 运行历史、单份 JSON 导入、同方案历史比较。
- 数据集与模型资源检查。
- Python 环境检查、依赖安装和启动脚本。

**本版本不包含：**
- 个人知识库、文件管理、文档编辑或文件同步。
- AI 问答、摘要、笔记生成或聊天功能。
- 单条 Query 即时检索作为主要工作流。
- 查询级检索结果、错误分析案例或实时详细日志流。
- 任意算法 / 模型 / 参数自由组合、自动调参或自定义指标。
- 批量 JSON 导入、导出导入记录或应用内删除记录。
- 多任务并行、断点续跑、自动重试或任务优先级调整。
- 用户账号系统、公网访问、云端部署或互联网协作。

### 2.4 预设实验方案

MVP 预设实验必须沿用课程实验已完成的配置和结果，不新增研究内容。实验中心不展示数据集规模，但必须展示足以解释结果适用范围的数据集划分信息。

| 方案 ID（建议稳定标识） | 名称 | 数据集与划分 | 主要实验内容 |
| --- | --- | --- | --- |
| `scifact-comparison` | SciFact 英文检索方法与模型对比 | SciFact test | BM25；Qwen3-Embedding-0.6B（无前缀 / 官方 Instruct）；all-MiniLM-L6-v2；BGE-M3（无前缀 / 自定义查询前缀）；已有 Qwen3 Hybrid / RRF 组合 |
| `duretrieval-comparison` | DuRetrieval 中文检索方法对比 | DuRetrieval dev | BM25（jieba）；bge-small-zh-v1.5 Dense（无前缀 / 检索指令前缀）；等权 Hybrid / RRF |
| `duretrieval-rrf-weight-sweep` | DuRetrieval 加权 RRF 参数探索 | DuRetrieval dev | BM25 权重 1.0、0.5、0.3、0.2、0.1；Dense 权重固定 1.0；RRF k=60 |

> 表中方案 ID 是本 SRS 建议采用的稳定标识，正式冻结前应与实际配置文件和结果文件核对。方案内的具体实验变体必须逐项映射到已有实验配置，不能将不同前缀或权重配置混为同一条实验。

## 3. 功能需求

需求优先级说明：P0 为 MVP 必须实现；P1 为 MVP 应实现但不影响核心实验闭环的次级能力。除非明确说明，以下需求均为 P0。

### 3.1 启动与应用导航

**FR-001 本机启动**  
系统必须提供独立启动入口。用户运行启动脚本后，系统启动本地 Web 服务，并提供本机浏览器访问地址。日常使用不应要求用户手动输入 Python 模块命令。

**FR-002 默认本机访问**  
系统默认只允许本机访问，不应在用户未主动开启局域网访问时向局域网其他设备开放服务。

**FR-003 页面导航**  
系统必须提供以下主要页面，并采用左侧固定导航栏与右侧独立工作区布局：
1. 实验中心；
2. 运行监控；
3. 实验结果；
4. 历史记录。

资源路径、Python 环境和局域网访问配置应位于次级设置入口。

**FR-004 页面状态一致性**  
多个浏览器客户端访问同一实例时，页面展示的任务状态、队列和历史记录必须来自同一后端状态，不得由各浏览器分别维护互相矛盾的任务状态。

### 3.2 实验中心与方案选择

**FR-010 预设方案列表**  
实验中心必须列出所有当前可用的预设实验方案，并展示：
- 实验名称；
- 数据集名称与语言；
- 数据集划分（如 test 或 dev）；
- 实验目的或简短说明；
- 使用的算法、模型及关键参数概览；
- 预置结果是否可用；
- 当前方案是否具备运行条件。

不得在实验中心展示数据集规模作为方案选择信息。

**FR-011 方案详情**  
用户选择方案后，系统必须展示该方案包含的实验变体、数据集与划分、算法 / 模型配置和评价设置。不得提供超出预设方案范围的自由配置控件。

**FR-012 预置结果入口**  
如果方案具有有效预置结果，用户必须能够直接打开结果，无需先运行实验或加载 Embedding 模型。

**FR-013 提交实验**  
用户可以从实验中心提交一个预设实验方案。系统必须检查该方案所需数据集、模型和核心环境是否可用；检查通过后创建任务并进入执行队列。

**FR-014 资源缺失的局部影响**  
某个数据集或模型缺失时，只应使依赖该资源的实验方案不可运行，不得因此阻止 TextMind 整体启动或使无关方案不可用。界面必须说明缺失资源及原因。

### 3.3 任务调度与运行监控

**FR-020 单任务执行**  
MVP 同一实例同一时间最多执行一个实验任务。其他已提交任务必须进入等待队列，按提交顺序执行；不提供优先级调整。

**FR-021 后端任务管理**  
任务队列、任务状态和运行生命周期必须由主机后端统一管理。浏览器关闭、刷新或客户端断开连接不得取消已提交任务。

**FR-022 任务状态**  
系统至少支持以下状态：
- `Pending`：等待中；
- `Preparing`：准备中；
- `Running`：运行中；
- `Cancelling`：取消中；
- `Completed`：已完成；
- `Failed`：已失败；
- `Cancelled`：已取消；
- `Interrupted`：已中断。

状态变化必须符合任务生命周期，不得将取消、失败或中断任务显示为正常完成。

**FR-023 运行阶段展示**  
运行监控必须展示当前任务、等待队列、任务状态、当前执行阶段、已完成阶段、待执行阶段及运行时间。无需展示整体百分比，也不要求实时详细日志流。

**FR-024 运行中取消**  
用户可以取消正在执行的任务。系统必须先将状态变为 `Cancelling`，再在安全停止点完成清理并变为 `Cancelled`。不得将强制终止底层进程作为常规取消方式。

**FR-025 运行中取消记录**  
运行中的任务被取消后必须保留运行记录，至少包含运行 ID、方案 ID、任务配置、开始时间、取消时间、已完成阶段、取消时所在阶段和可获得的部分运行信息。

**FR-026 等待任务取消**  
用户可以取消等待中的任务。系统应将该任务从队列移除，不生成实验运行记录。

**FR-027 失败记录**  
任务执行失败时必须保留失败记录，至少包含失败阶段、错误摘要、技术错误详情、运行时间和已完成阶段。失败任务不得被静默丢弃。

**FR-028 失败重试**  
用户重新运行失败方案时，系统必须创建新的实验运行和新的运行 ID；原失败记录保持不变。MVP 不提供自动重试。

**FR-029 正常关闭**  
服务正常关闭时，系统应尽可能请求当前运行任务在安全停止点结束，并保存相应运行状态；等待任务不应被误记为已完成。

**FR-030 异常退出恢复**  
服务重新启动时，系统必须检查持久化记录中未正常结束的任务，并将其标记为 `Interrupted`，保留可恢复的运行信息。MVP 不支持从中断点继续执行。

### 3.4 实验结果展示

**FR-040 结果页内容**  
单次实验结果页必须按以下信息组织：
1. 实验概览与运行状态；
2. 指标数值；
3. 可视化图表；
4. 实验配置；
5. 运行环境。

实验配置与运行环境可以折叠显示。

**FR-041 指标展示**  
系统必须沿用已有评价指标：P@K、R@K、MRR、NDCG@K。K 值及适用指标必须遵循对应实验方案的评价设置，不得为了界面统一而擅自改变。指标以数值表格展示。

**FR-042 耗时展示**  
系统必须展示实验报告已有的分阶段耗时口径，包括适用的：
- 数据集加载；
- 模型加载；
- 文档缓存加载；
- 语料编码；
- 查询缓存加载；
- 查询编码；
- 向量检索。

向量检索均值沿用实验报告口径，即单条查询端到端检索耗时，不包含查询编码。界面必须清楚区分各阶段，不能将不同阶段混成一个无法解释的总耗时。

**FR-043 图表展示**  
系统应展示与当前实验方案对应的已有图表类型，包括算法 / 模型指标对比、参数变化（例如 RRF 权重）和耗时对比。图表内容应来自该次运行的产物，不得把其他实验方案的图表错误关联到当前记录。

**FR-044 配置展示**  
结果页必须显示实际运行所使用的数据集及划分、算法、模型、关键参数和评价设置。

**FR-045 环境展示**  
结果页必须显示运行时可获得的操作系统、CPU 架构 / 型号、GPU、Python、PyTorch、CUDA（适用时）及关键依赖版本。不得记录主机名、用户名、设备序列号或 IP 地址等不必要的个人 / 设备标识。

**FR-046 导入记录的原始环境**  
查看导入记录时，必须展示记录中保存的原始运行时间、实验配置和设备环境，不得用当前查看设备的信息替代。

**FR-047 非目标信息不展示**  
MVP 结果页不展示查询级检索结果、query 级诊断分布、错误分析案例或实时详细日志流。此类内容属于后续扩展方向。

### 3.5 结果文件与 JSON 导入

**FR-050 独立运行目录**  
每次实验运行必须拥有独立运行 ID 和独立结果目录。JSON 主记录及该次运行生成的图表必须位于同一运行目录中。

**FR-051 JSON 主记录**  
每次运行必须生成一份结构化 JSON 记录。记录至少包含：
- 格式版本；
- 运行 ID 与实验方案 ID；
- 实验名称；
- 运行状态；
- 运行开始 / 结束时间及适用的取消 / 失败时间；
- 数据集标识与划分；
- 算法、模型及关键参数；
- 指标结果；
- 分阶段耗时；
- 运行环境；
- 图表相对路径列表；
- 失败或取消信息（适用时）。

具体字段名、类型和必填规则在技术设计阶段形成 JSON Schema，但不得遗漏以上语义信息。

**FR-052 图表相对路径**  
JSON 必须使用相对路径引用图表，不得依赖原机器的绝对路径。解析路径时必须限制在该运行记录目录范围内，避免路径越界访问。

**FR-053 预置结果**  
系统必须随软件提供当前预设方案对应的可浏览预置结果。预置结果应与用户重新运行产生的记录明确区分，且用户运行不得覆盖预置结果。

**FR-054 单份 JSON 导入**  
历史记录页面必须支持导入单份符合格式规范的 JSON 文件。导入操作只导入和查看既有结果，不触发实验重新运行。

**FR-055 导入文件复制**  
导入时，系统必须将 JSON 和可用的附属图表复制到 TextMind 自己的 results 目录，形成独立记录目录。导入完成后，查看记录不应依赖原始导入文件仍留在原位置。

**FR-056 缺失图表容错**  
JSON 有效但部分图表缺失或无法读取时，系统必须允许记录导入，并明确提示对应图表不可用。

**FR-057 格式版本校验**  
系统必须校验 JSON 格式版本。对于不兼容版本，必须拒绝导入并说明原因；不得静默丢弃未知字段后将不兼容记录伪装成完整记录。

**FR-058 导入时间元数据**  
导入记录必须保留原始实验时间。系统可以额外保存导入时间作为管理元数据，但导入时间不得覆盖原始运行时间。

**FR-059 导入限制**  
MVP 只支持单份 JSON 导入，不支持批量导入，也不支持再次导出已导入记录。

**FR-060 记录删除**  
TextMind 应用内不提供实验记录删除功能。用户通过操作系统文件管理器删除整个运行目录。系统文档必须说明删除 JSON 或图表的影响；删除预置结果后，应用不提供保护或恢复机制。

### 3.6 历史记录与比较

**FR-070 历史记录列表**  
历史记录页面必须统一展示本机运行记录、预置结果和已导入记录。列表至少展示实验名称、运行时间、状态、运行 ID 和一至两个代表性指标。

**FR-071 记录详情**  
用户点击历史记录后，可以打开对应的单次实验结果页。对于失败、取消或中断记录，结果页应明确显示其非完成状态及已有信息。

**FR-072 同方案比较**  
用户可以自行勾选至少两条属于同一实验方案的记录进行比较。系统不得默认自动选择最近几次运行。

**FR-073 比较范围限制**  
系统只支持同一实验方案内的历史比较，不支持不同实验方案之间的自由比较。

**FR-074 比较内容**  
比较视图必须展示适用指标、可用图表和运行配置差异。相同配置无需重复罗列；不同配置应突出显示。不同运行环境信息可供查看，以帮助解释运行差异。

**FR-075 比较数据限制**  
只有具备可比较指标的记录参与指标比较。失败、取消、中断或指标不完整的记录仍可查看，但系统必须清楚标示无法比较的字段及原因，不得伪造缺失值。

### 3.7 数据集、模型与资源管理

**FR-080 SciFact 内置**  
软件默认提供 SciFact 数据集并自动配置，不要求用户手动填写路径。随软件分发时必须保留来源、署名和适用许可证文本；正式打包前必须核对实际数据包及其许可证声明。当前调研记录标注许可证为 CC-BY-SA-4.0。

**FR-081 DuRetrieval 外置**  
软件不随包提供 DuRetrieval 数据集。软件必须提供来源、获取说明、目录约定和手动配置入口。当前实验采用 C-MTEB DuRetrieval 子集及 dev split，不得误用百度原始 8.09M 段落版本替代。

**FR-082 模型外置**  
软件不随包提供 Embedding 模型文件。README 必须列出预设方案所需模型、来源和准备方式。系统不得自动下载模型。

**FR-083 统一模型根目录**  
用户只需配置一个统一模型根目录。系统按预设模型名称在约定子目录中查找模型，不提供每个模型单独配置路径的入口。

**FR-084 资源可用性检查**  
系统必须检查数据集 / 模型路径、必要文件和基本可用性，并显示未配置、可用或不可用状态及明确原因。不得自动扫描磁盘寻找资源。

**FR-085 不管理外部文件**  
系统不得擅自复制、移动、重命名或整理用户自行准备的数据集和模型文件。

**FR-086 主机配置权限**  
数据集路径、模型根目录、Python 环境和网络访问开关由主机本地管理。局域网客户端可以查看资源状态，但不能修改上述主机配置。

### 3.8 Python 环境与脚本交付

**FR-090 环境准备说明**  
README 必须说明所需 Python 版本、第三方依赖、推荐模型及数据集准备方式。Python 与依赖版本必须锁定，并以现有可复现实验环境为核对依据。

**FR-091 依赖安装脚本**  
系统必须提供独立依赖安装脚本，由用户手动执行。建议脚本创建项目专用虚拟环境并安装锁定版本依赖，不得默认污染系统 Python 环境。

**FR-092 环境检查脚本**  
系统必须提供独立环境检查脚本，复用现有 test 脚本的检查逻辑，并将检查结果与错误信息输出到终端。

**FR-093 启动脚本**  
系统必须提供独立启动脚本。Windows 与 macOS 均应提供对应入口，底层检查和启动逻辑尽量共用 Python 实现。

**FR-094 启动预检**  
启动时必须检查 Python 环境和核心依赖。核心环境损坏或关键依赖缺失时应阻止服务启动并给出可理解的终端错误信息；单个数据集或模型缺失不得阻止服务启动，只影响相关实验的可用性。

**FR-095 手动资源准备**  
依赖安装脚本不得自动下载数据集或 Embedding 模型。数据集与模型由用户按 README 指引自行准备。

### 3.9 局域网访问

**FR-100 主动开启**  
局域网访问默认关闭。只有主机用户主动开启后，服务才允许局域网客户端连接。

**FR-101 临时访问码**  
开启局域网访问时，系统必须生成或启用临时访问码，并要求局域网客户端提供有效访问码后才能访问实例。关闭局域网访问后，当前访问码必须失效。

**FR-102 同实例共享**  
局域网客户端访问的是主机上的同一实例，共享实验任务队列、运行状态、历史记录和结果文件，不创建独立副本。

**FR-103 客户端权限**  
局域网客户端可以查看实验方案、提交实验、查看运行状态、取消任务、查看结果和导入 JSON；不能修改主机资源路径、Python 环境或局域网访问开关。

**FR-104 地址与连接提示**  
系统应向主机用户显示可用于局域网访问的主机 IPv4 地址和端口，并在连接失败、服务退出或网络地址变化时给出清楚提示。不得要求用户将 `0.0.0.0` 当作客户端访问地址。

**FR-105 网络安全边界**  
局域网访问仅面向可信私人局域网。系统必须明确提示访问码通过普通 HTTP 传输时不具备 TLS 加密保护，不应在公共 Wi-Fi 或不可信网络中开启。MVP 不提供公网 HTTPS、互联网访问或账号体系。

## 4. 外部接口需求

### 4.1 用户界面

- 系统通过浏览器提供交互界面。
- 主要导航固定在左侧，工作内容显示在右侧独立区域。
- 界面应以中文为主要语言；算法名、模型名、指标名和任务状态可保留通用英文术语。
- 指标以表格展示，图表以图片或等效图形方式展示。
- 运行状态、资源不可用、导入失败和网络错误必须有明确文字说明，不得只依赖颜色表达。

### 4.2 文件接口

- 输入：用户选择的单份 JSON 结果文件；用户配置的数据集目录和模型根目录。
- 输出：每次运行的 JSON 主记录及其图表文件；运行历史目录。
- 导入文件必须按格式版本和字段规则校验。
- 文件路径处理不得允许相对路径越界访问运行目录。

### 4.3 运行环境接口

- 主机需具备受支持的 Python 环境和锁定依赖。
- Embedding 模型按本地模型目录加载，不由 TextMind 自动下载。
- SciFact 由软件包提供；DuRetrieval 从用户配置的外部目录读取。

### 4.4 网络接口

- 本机访问使用 loopback 地址。
- 局域网访问仅在主机用户主动开启后启用。
- 局域网客户端使用主机 IPv4 地址与服务端口访问，并通过临时访问码完成访问控制。
- 本文不规定具体 HTTP API 路径、WebSocket / 轮询方式或会话令牌格式，这些属于技术设计内容。

## 5. 数据与业务规则

### 5.1 指标与实验口径

- 指标包括 P@K、R@K、MRR、NDCG@K；K ∈ {1, 5, 10, 100}，但具体方案只展示其实际计算并保存的指标。
- 指标聚合沿用已有实验宏平均口径。
- 无相关标注的 Query 按现有实验实现跳过并计数；当前报告实验未出现该情况。
- BM25 参数沿用 k1=1.2、b=0.75；中文使用 jieba 分词，英文使用小写字母数字切分。
- Dense 使用 SentenceTransformer，文档和查询向量 L2 归一化，以余弦相似度（内积）检索。
- Hybrid 使用 RRF，默认 k=60；加权 RRF 的权重组合按预设方案固定。
- DuRetrieval 的结果均来自 dev split。界面、预置结果说明和比较视图不得将其表述为独立测试集结论。

### 5.2 记录标识

- 实验方案 ID 在方案版本范围内保持稳定，用于归组多次运行。
- 每次运行 ID 必须唯一，不得仅以方案 ID 作为运行记录标识。
- 运行 ID 的具体格式、时间戳精度和冲突处理由技术设计确定。
- 预置结果也必须能被稳定识别，并与用户运行记录区分。

### 5.3 结果记录完整性

- JSON 是运行记录主体，图表是附属文件。
- 图表缺失不应使 JSON 主记录整体不可读。
- 运行失败或取消时，记录可以不包含完整指标，但必须明确状态和已有阶段信息。
- 不同实验方案的指标不可直接放在同一历史比较中。

## 6. 非功能需求

### 6.1 可复现性与一致性

**NFR-001** 每次运行记录必须保存足以识别实验条件的信息，包括数据集及划分、检索方法、模型 / revision（适用时）、参数、评价设置和运行环境。

**NFR-002** 预置结果必须来自项目已有实验产物，不能用未经实际运行的模拟指标冒充真实结果。

**NFR-003** 同一实例的所有客户端必须看到一致的任务状态和运行记录。

### 6.2 可靠性

**NFR-010** 浏览器刷新或关闭不得导致后端任务丢失或意外终止。

**NFR-011** 任务状态与结果记录必须持久化到本机存储；服务异常退出后能够识别未正常结束的任务并标记为中断。

**NFR-012** 导入图表失败、单个模型不可用或单个数据集缺失，不得破坏其他已有记录或阻止无关实验使用。

### 6.3 安全与隐私

**NFR-020** 默认本机访问；局域网访问必须由主机用户显式开启并受临时访问码保护。

**NFR-021** 记录中不得包含不必要的个人身份信息或设备标识，如用户名、主机名、设备序列号和 IP 地址。

**NFR-022** JSON 导入与图表路径解析必须进行格式校验和路径边界校验，避免读取运行目录之外的文件。

**NFR-023** 产品文档必须说明局域网访问的 HTTP / TLS 安全边界。

### 6.4 可维护性

**NFR-030** Web 界面不得复制实现一套独立检索算法；应复用现有 Python 检索与评价核心。

**NFR-031** 实验方案定义、实验执行、任务管理、结果序列化和 Web 展示应保持清晰边界，便于后续有限配置能力扩展。

**NFR-032** MVP 不引入与当前范围无关的通用插件系统或过度抽象。

### 6.5 可用性与可理解性

**NFR-040** 资源缺失、环境不满足、实验失败、取消、导入拒绝和网络连接失败时，系统必须提供可理解的错误摘要及必要处理指引。

**NFR-041** 任务状态不得只通过颜色区分；必须同时提供文本状态和阶段信息。

**NFR-042** 实验中心不展示数据集规模；结果页可展示理解实验所必需的数据集标识和划分信息。

### 6.6 兼容性

**NFR-050** MVP 必须提供 Windows 与 macOS 的安装 / 检查 / 启动入口。

**NFR-051** Web 页面应可在项目声明支持的现代浏览器中正常使用。具体浏览器最低版本在技术设计和测试计划中明确。

## 7. 验收标准

以下验收场景用于判断 MVP 是否满足本 SRS。具体测试数据和测试脚本可在测试计划中进一步细化。

| 验收 ID | 场景 | 通过条件 |
| --- | --- | --- |
| AT-001 | 默认启动 | 运行启动脚本后可通过本机浏览器访问；未开启局域网时其他设备不能访问 |
| AT-002 | 页面导航 | 四个主要页面和次级设置入口均可访问，布局符合约定 |
| AT-003 | 实验方案浏览 | 展示三类预设实验方案、数据集语言和划分，不展示数据集规模 |
| AT-004 | 预置结果 | 在不准备外置模型和 DuRetrieval 的情况下，仍可打开随软件提供且有效的预置结果 |
| AT-005 | 资源缺失 | 缺少 DuRetrieval 或某个模型时，仅相关方案不可运行，软件其他功能可用 |
| AT-006 | 任务排队 | 连续提交多个方案时最多一个任务运行，其余进入等待队列 |
| AT-007 | 阶段状态 | 运行监控能显示当前阶段、已完成阶段、待执行阶段和任务状态 |
| AT-008 | 取消运行中任务 | 状态经历取消中后变为已取消，且生成包含部分运行信息的记录 |
| AT-009 | 取消等待任务 | 等待任务从队列移除，且不生成运行记录 |
| AT-010 | 失败与重试 | 失败记录保留；重新运行创建新运行 ID，不覆盖旧记录 |
| AT-011 | 异常退出 | 模拟服务异常退出后重启，未正常结束的任务被标记为中断 |
| AT-012 | 结果展示 | 完成记录显示实际指标、耗时、图表、配置和运行环境；不显示 query 级结果和错误案例 |
| AT-013 | 记录导入 | 有效单份 JSON 导入后复制到 results 目录，原始实验时间和设备环境保持不变 |
| AT-014 | 缺失图表 | JSON 有效但图表缺失时仍能导入并提示图表不可用 |
| AT-015 | 不兼容版本 | 不兼容 JSON 被拒绝，并显示明确原因 |
| AT-016 | 历史比较 | 用户可选择同方案两条或更多记录比较；不同方案不能混合比较 |
| AT-017 | 文件管理 | 应用内没有删除记录功能，README 说明通过文件管理器删除的后果 |
| AT-018 | 局域网访问 | 开启后访问码有效；关闭后访问码失效；客户端可提交 / 取消任务但不能修改主机设置 |
| AT-019 | 脚本交付 | Windows 与 macOS 均有依赖安装、环境检查和启动入口；环境错误输出到终端 |
| AT-020 | 实验口径 | 预置方案和结果保留原始数据集划分、算法配置与指标口径，DuRetrieval 明确标注 dev |

## 8. 待技术设计明确的事项

以下事项不属于产品方向未决，不阻止本 SRS 进入需求评审；应在软件设计说明书（SDS）或实现方案中确定：

1. Web 框架、前端技术栈、API 组织方式及状态推送方式。
2. 任务队列、任务持久化和异常退出检测的具体机制。
3. 运行中安全取消的检查点及各实验阶段的可取消边界。
4. JSON Schema 的具体字段名、类型、必填规则、版本迁移策略。
5. 实验方案配置文件格式、方案 ID 命名和方案版本策略。
6. 运行 ID 的具体格式、时间戳精度及冲突处理。
7. results 目录层级、预置结果与用户运行记录的物理组织方式。
8. SciFact 数据包的实际分发内容、署名文件和许可证文本核对。
9. DuRetrieval 目录约定、模型子目录命名和资源完整性检查规则。
10. Python 最低版本、依赖锁定方式及 Windows / macOS 脚本实现。
11. 局域网临时访问码的生成、有效期、会话校验和安全存储方式。
12. 服务监听、防火墙提示、IP 变化检测和客户端断连处理。
13. 支持的浏览器及最低版本。
14. 图表生成、读取失败和记录部分损坏时的降级行为细节。

## 9. 需求变更原则

- 用户明确确认的产品决策是需求基线；技术实现建议不得未经确认自动扩大产品范围。
- 实现中发现需求冲突、原实验核心不支持或存在安全风险时，应先记录问题并提出影响分析。
- 需求变更应同步更新本 SRS、已确认决策或待处理事项，并评估对实现、测试和既有结果兼容性的影响。
- 任何新增功能不得以“顺手完善”为由自动进入 MVP。
