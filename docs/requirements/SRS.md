## 1. 引言

### 1.1 编写目的

本文定义 TextMind 实验演示型 MVP 的产品需求，作为后续系统设计、任务拆分、实现和验收的共同基线。开发过程中如需改变已确认需求，应先更新本文及相关决策记录，再实施变更。

### 1.2 产品范围

TextMind 是一个本地运行的文本检索实验台。用户通过浏览器浏览预设实验方案，选择其中一个实验变体运行，查看指标与图表，并管理实验运行历史。

MVP 的目标是把已有 BM25、Dense Retrieval 和 Hybrid Retrieval（RRF）实验能力封装成可交互、可观察、可比较的软件。MVP 采用预设方案，不提供自由组合算法、模型或参数的入口。实验方案是相关变体的归组容器；每个任务只执行一个实验变体。

### 1.3 术语

| 术语 | 定义 |
| --- | --- |
| 实验方案（Experiment Plan） | 具有稳定方案 ID 和版本的一组实验变体，用于浏览、归组和同方案比较，不是一次任务的执行单元 |
| 实验变体（Experiment Variant） | 一组固定的数据集、算法、模型和参数配置，具有稳定变体 ID；每次任务只执行一个变体 |
| 实验运行（Experiment Run） | 用户对一个实验变体发起的一次执行，具有独立运行 ID 和结果目录 |
| 预置结果（Preset Result） | 随软件提供、由项目已有实验生成的单变体结果记录，供用户直接浏览 |
| 参照结果（Reference Result） | 在某一方案中只用于图表或指标参照、但不作为该方案独立运行记录展示的预置结果 |
| 运行记录（Run Record） | 一次实验运行生成的 JSON 主记录及其附属图表 |
| Corpus | 待检索文档集合 |
| Queries | 用于检索的查询集合 |
| Qrels | Query 与相关文档之间的相关性标注 |
| 主机 | 启动 TextMind 服务、持有数据集和模型文件的计算机 |
| 客户端 | 通过浏览器访问 TextMind 的本机或局域网设备 |

## 2. 总体描述

### 2.1 产品视角

TextMind 是围绕现有 Python 检索实验核心构建的本地 Web 应用。浏览器负责展示和交互，主机服务负责实验调度、资源访问、执行、结果存储和局域网访问控制。

系统不依赖云服务。关闭浏览器不应终止已提交的实验任务；服务退出则会按任务生命周期规则处理正在执行的任务。

### 2.2 用户与使用环境

- 主要用户：希望演示、观察和比较文本检索算法实验的课程项目使用者。
- 主机环境：Windows 或 macOS；用户自行准备 Python 环境、DuRetrieval 数据集和所需 Embedding 模型。
- 客户端环境：通过现代浏览器访问主机提供的 Web 页面。
- 局域网访问面向用户信任的私人局域网，不面向公共网络或互联网。

### 2.3 产品路线与范围边界

本 SRS 只覆盖 A 阶段实验演示型 MVP。后续 B 阶段可以在稳定基础上增加有限的算法、模型和参数配置，但不属于本版本验收范围。

**本版本包含：**
- 本机 Web 服务与可选局域网访问。
- 预设实验方案和可浏览的预置结果。
- 单变体实验提交、单任务执行、等待队列、阶段状态与取消。
- 指标、耗时、图表、配置和运行环境展示。
- 运行历史、单份 JSON 导入、同方案历史比较。
- 数据集与模型资源检查。
- Python 环境检查、依赖安装和启动脚本。

**本版本不包含：**
- 个人知识库、文件管理、文档编辑或文件同步。
- AI 问答、摘要、笔记生成或聊天功能。
- 单条 Query 即时检索作为主要工作流。
- 查询级检索结果、错误分析案例或实时详细日志流。
- 任意算法 / 模型 / 参数自由组合、自动调参或自定义指标。
- 批量 JSON 导入、导出导入记录或应用内删除记录。
- 多任务并行、断点续跑、自动重试或任务优先级调整。
- 用户账号系统、公网访问、云端部署或互联网协作。

### 2.4 预设实验方案

MVP 预设实验必须沿用课程实验已完成的配置和结果，不新增研究内容。实验中心应展示数据集名称、语言和划分；数据集规模可以在方案详情或结果页展示，但不作为方案选择的主要信息。

三套方案初始版本均为 `v1`。以下方案 ID 和变体 ID 作为 MVP 的稳定标识。

| 方案 ID | 方案版本 | 名称 | 数据集与划分 | 变体数量 |
| --- | --- | --- | --- | ---: |
| `scifact-comparison` | `v1` | SciFact 英文检索方法与模型对比 | SciFact test | 9 |
| `duretrieval-comparison` | `v1` | DuRetrieval 中文检索方法对比 | DuRetrieval dev | 4 |
| `duretrieval-rrf-weight-sweep` | `v1` | DuRetrieval 加权 RRF 参数探索 | DuRetrieval dev | 4 个可运行变体，另有 1 个参照结果 |

所有预设变体统一使用 `top_k=100` 和评价 K 值 `{1, 5, 10, 100}`；Dense 与 Hybrid 统一使用 `batch_size=32` 和归一化向量。

#### 2.4.4 查询前缀

- Qwen3 Instruct 查询前缀：`Instruct: Given a web search query, retrieve relevant passages that answer the query\nQuery:`
- SciFact BGE-M3 自定义查询前缀：`Represent this sentence for searching relevant passages: `
- DuRetrieval bge-small-zh-v1.5 自定义检索前缀：`为这个句子生成表示以用于检索相关文章：`

运行时必须把完整前缀作为方案配置保存，不能只记录“有前缀”或“官方前缀”等标签。

## 3. 功能需求

需求优先级说明：P0 为 MVP 必须实现；P1 为 MVP 应实现但不影响核心实验闭环的次级能力。除非明确说明，以下需求均为 P0。

### 3.1 启动与应用导航

**FR-001 本机启动**  
系统必须提供独立启动入口。用户运行启动脚本后，系统启动本地 Web 服务，并提供本机浏览器访问地址。日常使用不应要求用户手动输入 Python 模块命令。

**FR-002 默认本机访问**  
系统默认只允许本机访问，不应在用户未主动开启局域网访问时向局域网其他设备开放服务。

**FR-003 页面导航**  
系统必须提供以下主要页面，并采用左侧固定导航栏与右侧独立工作区布局：
1. 实验中心；
2. 运行监控；
3. 实验结果；
4. 历史记录。

资源路径、Python 环境和局域网访问配置应位于次级设置入口。

**FR-004 页面状态一致性**  
多个浏览器客户端访问同一实例时，页面展示的任务状态、队列和历史记录必须来自同一后端状态，不得由各浏览器分别维护互相矛盾的任务状态。

### 3.2 实验中心与方案选择

**FR-010 预设方案列表**  
实验中心必须列出所有当前可用的预设实验方案，并展示：
- 实验名称；
- 数据集名称与语言；
- 数据集划分（如 test 或 dev）；
- 实验目的或简短说明；
- 方案包含的变体数量及可运行变体数量；
- 预置结果是否可用。

数据集规模可以在方案详情或结果页展示，不得作为方案列表的主要选择信息。

**FR-011 方案详情**  
用户选择方案后，系统必须展示该方案包含的实验变体、稳定变体 ID、数据集与划分、算法 / 模型配置、评价设置、预置结果和每个变体的当前可运行状态。不得提供超出预设方案范围的自由配置控件。

**FR-012 预置结果入口**  
用户必须能够直接打开任一有效预置结果，无需先运行实验或加载 Embedding 模型。加权 RRF 方案中的等权结果必须明确标记为参照结果。

**FR-013 提交单变体实验**
用户从方案中选择一个实验变体并提交运行。系统必须检查该变体所需数据集、模型和核心环境是否可用；检查通过后创建一个只执行该变体的任务并进入执行队列。

**FR-014 资源缺失的局部影响**  
某个数据集或模型缺失时，只应使依赖该资源的实验变体不可运行。同一方案中的其他可运行变体、预置结果和其他方案必须保持可用。界面必须列出缺失资源、受影响变体和原因。

**FR-015 参照结果限制**
参照结果可以用于指标或图表参照，但不得生成独立运行记录、历史条目或冒用新的运行 ID。参照结果不得被当作该方案的历史运行参与指标比较。

### 3.3 任务调度与运行监控

**FR-020 单任务执行**  
MVP 同一实例同一时间最多执行一个实验变体任务。其他已提交任务必须进入等待队列，按提交顺序执行；不提供优先级调整。

**FR-021 后端任务管理**  
任务队列、任务状态和运行生命周期必须由主机后端统一管理。浏览器关闭、刷新或客户端断开连接不得取消已提交任务。

**FR-022 任务状态**  
系统至少支持以下状态：
- `Pending`：等待中；
- `Preparing`：准备中；
- `Running`：运行中；
- `Cancelling`：取消中；
- `Completed`：已完成；
- `Failed`：已失败；
- `Cancelled`：已取消；
- `Interrupted`：已中断。

状态变化必须符合任务生命周期，不得将取消、失败或中断任务显示为正常完成。

**FR-023 运行阶段展示**  
运行监控必须展示当前任务所属方案、变体 ID、任务状态、等待队列、当前执行阶段、已完成阶段、待执行阶段及运行时间。无需展示整体百分比，也不要求实时详细日志流。

**FR-024 运行中取消**  
用户可以取消正在执行的任务。系统必须先将状态变为 `Cancelling`，在主要阶段边界检查取消请求，并在安全停止点完成清理后标记为 `Cancelled`。模型加载、批量编码等不可中断阶段结束前，任务保持 `Cancelling`；系统不得要求底层算子实时响应，也不得强制终止 Python 进程。

**FR-025 运行中取消记录**  
运行中的任务被取消后必须保留运行记录，至少包含运行 ID、方案 ID 及版本、变体 ID、任务配置、开始时间、取消时间、已完成阶段、取消时所在阶段和可获得的部分运行信息。

**FR-026 等待任务取消**  
用户可以取消等待中的任务。系统应将该任务从队列移除，不生成实验运行记录。

**FR-027 失败记录**  
任务执行失败时必须保留该变体的失败记录，至少包含失败阶段、错误摘要、技术错误详情、运行时间和已完成阶段。失败任务不得被静默丢弃，也不得影响其他变体已有记录。

**FR-028 失败重试**  
用户重新运行失败变体时，系统必须创建新的实验运行和新的运行 ID；原失败记录保持不变。MVP 不提供自动重试，不设置方案级“部分完成”状态。

**FR-029 正常关闭**  
服务正常关闭时，系统必须停止接受新任务并取消等待队列中的全部任务。等待任务不生成运行记录。正在执行的任务如果未完成，必须在关闭时标记为 `Interrupted`，不得标记为 `Completed`。

**FR-030 异常退出恢复**  
服务重新启动时，系统必须将异常退出前尚未正常结束的运行任务标记为 `Interrupted`，保留已有运行信息。旧等待队列不恢复：所有曾经处于 `Pending` 的任务必须取消并移除，且不生成运行记录。MVP 不支持从中断点继续执行。

**FR-031 队列取消提示**
服务正常关闭或重启导致等待任务取消后，系统必须在下次可访问界面中明确提示等待任务已被取消，避免用户误认为任务仍在等待或已经执行。

### 3.4 实验结果展示

**FR-040 结果页内容**  
单次变体运行结果页必须按以下信息组织：
1. 实验概览与运行状态；
2. 指标数值；
3. 可视化图表；
4. 实验配置；
5. 运行环境。

实验配置与运行环境可以折叠显示。

**FR-041 指标展示**  
系统必须沿用已有评价指标：P@K、R@K、MRR、NDCG@K。K 值及适用指标必须遵循对应实验变体的评价设置，不得为了界面统一而擅自改变。指标以数值表格展示。

**FR-042 耗时展示**  
系统必须展示实验报告已有的分阶段耗时口径，包括适用的：
- 数据集加载；
- 模型加载；
- 文档缓存加载；
- 语料编码；
- 查询缓存加载；
- 查询编码；
- BM25 检索；
- Dense 向量检索；
- RRF 融合。

系统必须展示“单查询检索均值”，即每条查询完成检索所耗时间的宏平均，不包含查询编码。BM25 统计 BM25 检索，Dense 统计向量检索，Hybrid 统计 BM25、Dense 检索与 RRF 融合。界面必须清楚区分各阶段，不得把单查询检索均值与查询编码或索引构建时间混在一起，也不得重复累加子阶段形成无法解释的耗时。

**FR-043 图表展示**  
单次运行结果页只展示该变体自身指标、分阶段耗时和该次运行实际产生的图表。单次运行目录中的图表不得引用其他变体数据。算法 / 模型对比、参数变化和跨运行耗时对比由历史比较页面根据用户选择生成，不写回单次运行 JSON。

**FR-044 配置展示**  
结果页必须显示方案 ID、方案版本、变体 ID，以及实际运行所使用的数据集及划分、算法、模型及 revision（适用时）、查询前缀、关键参数和评价设置。

**FR-045 环境展示**  
结果页必须显示运行时可获得的操作系统、CPU 架构 / 型号、GPU、Python、PyTorch、CUDA（适用时）及关键依赖版本。不得记录主机名、用户名、设备序列号或 IP 地址等不必要的个人 / 设备标识。

**FR-046 导入记录的原始环境**  
查看导入记录时，必须展示记录中保存的原始运行时间、实验配置和设备环境，不得用当前查看设备的信息替代。

**FR-047 非目标信息不展示**  
MVP 结果页不展示查询级检索结果、query 级诊断分布、错误分析案例或实时详细日志流。此类内容属于后续扩展方向。

### 3.5 结果文件与 JSON 导入

**FR-050 独立运行目录**  
每次实验运行必须拥有独立运行 ID 和独立结果目录。JSON 主记录及该次运行生成的图表必须位于同一运行目录中。结果按存储类别固定放置在：

- `results/presets/<run_id>/`：预置结果；
- `results/runs/<run_id>/`：本机运行结果；
- `results/imports/<run_id>/`：导入结果。

应用必须根据记录所在的顶层目录判断结果为预置、本机运行或导入，不在 JSON 中重复保存该来源。用户可将单个 JSON 移出目录，移出后的来源识别由用户自行负责。

**FR-051 JSON 主记录**  
每次运行必须生成一份结构化 JSON 记录。记录至少包含：
- 格式版本；
- 运行 ID、实验方案 ID、方案版本和变体 ID；
- 实验方案名称与实验变体名称；
- 运行状态；
- 运行开始 / 结束时间及适用的取消 / 失败时间；
- 数据集标识与划分；
- 算法、模型及关键参数；
- 指标结果；
- 分阶段耗时；
- 运行环境；
- 图表相对路径列表；
- 失败或取消信息（适用时）。

具体字段名、类型和必填规则在技术设计阶段形成 JSON Schema，但不得遗漏以上语义信息。

**FR-052 图表相对路径**  
JSON 必须使用相对路径引用图表，不得依赖原机器的绝对路径。解析路径时必须限制在该运行记录目录范围内，避免路径越界访问。

**FR-053 预置结果**  
系统必须随软件提供当前预设变体对应的可浏览预置结果。预置结果应与用户重新运行产生的记录明确区分，且用户运行不得覆盖预置结果。加权 RRF 方案中的等权参照结果必须复用方法对比方案的同一变体 ID 和预置结果，不生成新的运行记录。

**FR-054 单份 JSON 导入**  
历史记录页面必须支持导入单份符合格式规范的 JSON 文件。导入操作只导入和查看既有结果，不触发实验重新运行。

**FR-055 导入文件复制**  
导入时，系统必须将 JSON 和可用的附属图表复制到 `results/imports/<run_id>/`，形成独立记录目录，并保持原 JSON 内容不变。导入完成后，查看记录不应依赖原始导入文件仍留在原位置。

**FR-056 缺失图表容错**  
JSON 有效但部分图表缺失或无法读取时，系统必须允许记录导入，并明确提示对应图表不可用。

**FR-057 格式版本校验**  
系统必须校验 JSON 格式版本。对于不兼容版本，必须拒绝导入并说明原因；不得静默丢弃未知字段后将不兼容记录伪装成完整记录。

**FR-058 未知方案和变体**
格式版本兼容且核心字段有效时，即使当前应用不认识记录中的方案或变体，也必须允许导入和只读查看。页面应显示原始方案 ID、方案版本和变体 ID，不伪造名称。未知方案或变体不得参与历史比较。原始环境信息缺失时显示“未记录”，不阻止导入；指标、状态和运行时间等核心字段不符合 Schema 时仍须拒绝。

**FR-059 重复运行 ID**
导入时必须按 JSON 中的运行 ID 检查重复。相同运行 ID 已经存在时，必须拒绝本次导入，不覆盖已有记录，并提示冲突的运行 ID。导入过程不得静默生成新运行 ID，也不得修改原 JSON 内容。

**FR-060 导入限制**
MVP 只支持单份 JSON 导入，不支持批量导入，也不支持再次导出已导入记录。

**FR-061 记录删除**
TextMind 应用内不提供实验记录删除功能。用户通过操作系统文件管理器删除整个运行目录。系统文档必须说明删除 JSON 或图表的影响；删除预置结果后，应用不提供保护或恢复机制。

### 3.6 历史记录与比较

**FR-070 历史记录列表**  
历史记录页面必须统一展示本机运行记录、预置结果和已导入记录。列表至少展示实验方案名称、变体名称、方案版本、运行时间、状态、运行 ID 和一至两个代表性指标。加权 RRF 方案中的等权参照结果不得作为历史运行条目出现。

**FR-071 记录详情**  
用户点击历史记录后，可以打开对应的单次实验结果页。对于失败、取消或中断记录，结果页应明确显示其非完成状态及已有信息。

**FR-072 同方案比较**  
用户可以自行勾选至少两条属于同一方案 ID 和方案版本的记录进行比较。被比较记录可以对应不同变体，也可以对应同一变体的多次运行。系统不得默认自动选择最近几次运行。

**FR-073 比较范围限制**  
系统只支持方案 ID 和方案版本均相同的历史记录比较，不支持不同方案或不同方案版本之间的自由比较。

**FR-074 比较内容**  
比较视图必须按变体组织所选记录，展示适用指标、运行配置差异和环境差异，并根据所选记录生成算法 / 模型、参数或耗时对比图。相同配置无需重复罗列，不同配置应突出显示。比较图表是查看时生成的派生视图，不写回运行 JSON。

**FR-075 比较数据限制**  
只有具备可比较指标的记录参与指标比较。指标按名称和 K 值对齐；缺少对应指标时明确标记“不可比较”，不得填零或伪造结果。失败、取消、中断或指标不完整的记录仍可查看，但系统必须清楚标示无法比较的字段及原因。

**FR-076 参照结果比较**
加权 RRF 方案的等权参照结果可以作为比较页面的基线指标或参考线展示，但不得被计入选中的运行数量，不得生成独立比较行，也不得参与以运行 ID 为单位的统计。

### 3.7 数据集、模型与资源管理

**FR-080 SciFact 内置**  
软件默认提供 SciFact 数据集并自动配置，不要求用户手动填写路径。随软件分发时必须保留来源、署名和适用许可证文本；正式打包前必须核对实际数据包及其许可证声明。当前调研记录标注许可证为 CC-BY-SA-4.0。

**FR-081 DuRetrieval 外置**  
软件不随包提供 DuRetrieval 数据集。软件必须提供来源、获取说明、目录约定和手动配置入口。当前实验采用 C-MTEB DuRetrieval 子集及 dev split，不得误用百度原始 8.09M 段落版本替代。

**FR-082 模型外置**  
软件不随包提供 Embedding 模型文件。README 必须列出预设变体所需模型、来源、使用说明和准备方式。系统不得自动下载模型。

**FR-083 统一模型根目录**  
用户只需配置一个统一模型根目录。系统按预设模型名称在约定子目录中查找模型，不提供每个模型单独配置路径的入口。

**FR-084 资源可用性检查**  
系统必须按变体检查数据集 / 模型路径、必要文件和基本可用性，并显示未配置、可用或不可用状态及明确原因。缺少资源只禁用受影响变体，不得禁用同一方案中资源齐全的其他变体。不得自动扫描磁盘寻找资源。

**FR-085 不管理外部文件**  
系统不得擅自复制、移动、重命名或整理用户自行准备的数据集和模型文件。

**FR-086 主机配置权限**  
数据集路径、模型根目录、Python 环境和网络访问开关由主机本地管理。局域网客户端可以查看资源状态，但不能修改上述主机配置。

**FR-087 模型来源说明**
README 或随附资源说明必须明确预设模型的名称、来源和 revision 获取方式，便于用户准备与预置结果对应的本地模型。

### 3.8 Python 环境与脚本交付

**FR-090 环境准备说明**  
README 必须说明所需 Python 版本、第三方依赖、推荐模型及数据集准备方式。Python 与依赖版本必须锁定，并以现有可复现实验环境为核对依据。

**FR-091 依赖安装脚本**  
系统必须提供独立依赖安装脚本，由用户手动执行。建议脚本创建项目专用虚拟环境并安装锁定版本依赖，不得默认污染系统 Python 环境。

**FR-092 环境检查脚本**  
系统必须提供独立环境检查脚本，复用现有 test 脚本的检查逻辑，并将检查结果与错误信息输出到终端。

**FR-093 启动脚本**  
系统必须提供独立启动脚本。Windows 与 macOS 均应提供对应入口，底层检查和启动逻辑尽量共用 Python 实现。

**FR-094 启动预检**  
启动时必须检查 Python 环境和核心依赖。核心环境损坏或关键依赖缺失时应阻止服务启动并给出可理解的终端错误信息；单个数据集或模型缺失不得阻止服务启动，只影响依赖该资源的变体可用性。

**FR-095 手动资源准备**  
依赖安装脚本不得自动下载数据集或 Embedding 模型。数据集与模型由用户按 README 指引自行准备。

### 3.9 局域网访问

**FR-100 主动开启**  
局域网访问默认关闭。只有主机用户主动开启后，服务才允许局域网客户端连接。

**FR-101 临时访问码**  
开启局域网访问时，系统必须生成或启用临时访问码，并要求局域网客户端提供有效访问码后才能访问实例。关闭局域网访问后，当前访问码必须失效。

**FR-102 同实例共享**  
局域网客户端访问的是主机上的同一实例，共享实验任务队列、运行状态、历史记录和结果文件，不创建独立副本。

**FR-103 客户端权限**  
局域网客户端可以查看实验方案、提交单个变体实验、查看运行状态、取消任务和查看结果；不能修改主机资源路径、Python 环境或局域网访问开关。JSON 导入权限由主机本地使用场景承担，MVP 不向局域网客户端开放该操作。

**FR-104 地址与连接提示**  
系统应向主机用户显示可用于局域网访问的主机 IPv4 地址和端口，并在连接失败、服务退出或网络地址变化时给出清楚提示。不得要求用户将 `0.0.0.0` 当作客户端访问地址。

**FR-105 网络安全边界**  
局域网访问仅面向可信私人局域网。系统必须明确提示访问码通过普通 HTTP 传输时不具备 TLS 加密保护，不应在公共 Wi-Fi 或不可信网络中开启。MVP 不提供公网 HTTPS、互联网访问或账号体系。

## 4. 外部接口需求

### 4.1 用户界面

- 系统通过浏览器提供交互界面。
- 主要导航固定在左侧，工作内容显示在右侧独立区域。
- 界面应以中文为主要语言；算法名、模型名、指标名和任务状态可保留通用英文术语。
- 指标以表格展示，图表以图片或等效图形方式展示。
- 运行状态、资源不可用、导入失败和网络错误必须有明确文字说明，不得只依赖颜色表达。

### 4.2 文件接口

- 输入：用户选择的单份 JSON 结果文件；用户配置的数据集目录和模型根目录。
- 输出：每次运行的 JSON 主记录及其图表文件，分别存放在 `presets`、`runs`、`imports` 三类结果目录下。
- 导入文件必须按格式版本和字段规则校验。
- 文件路径处理不得允许相对路径越界访问运行目录。
- 相同运行 ID 的导入必须被拒绝，不得覆盖已有记录。
- 导入 JSON 不保存应用管理字段，包括结果来源和导入时间。

### 4.3 运行环境接口

- 主机需具备受支持的 Python 环境和锁定依赖。
- Embedding 模型按本地模型目录加载，不由 TextMind 自动下载。
- SciFact 由软件包提供；DuRetrieval 从用户配置的外部目录读取。

### 4.4 网络接口

- 本机访问使用 loopback 地址。
- 局域网访问仅在主机用户主动开启后启用。
- 局域网客户端使用主机 IPv4 地址与服务端口访问，并通过临时访问码完成访问控制。
- 本文不规定具体 HTTP API 路径、WebSocket / 轮询方式或会话令牌格式，这些属于技术设计内容。

## 5. 数据与业务规则

### 5.1 指标与实验口径

- 指标包括 P@K、R@K、MRR、NDCG@K；当前预设变体使用 K ∈ {1, 5, 10, 100}。
- 指标聚合沿用已有实验宏平均口径。
- 无相关标注的 Query 按现有实验实现跳过并计数；当前报告实验未出现该情况。
- BM25 参数沿用 k1=1.2、b=0.75；中文使用 jieba 分词，英文使用小写字母数字切分。
- Dense 使用 SentenceTransformer，文档和查询向量 L2 归一化，以余弦相似度（内积）检索。
- Hybrid 使用 RRF，当前预设变体统一 k=60；加权 RRF 的权重组合按变体固定。
- DuRetrieval 的结果均来自 dev split。界面、预置结果说明和比较视图不得将其表述为独立测试集结论。

### 5.2 记录标识

- 实验方案 ID 用于方案归组，方案版本在语义变化时必须更新。
- 实验变体 ID 在对应方案版本内保持稳定，用于识别配置和比较对应变体。
- 每次运行 ID 必须唯一，不得以方案 ID 或变体 ID 代替运行记录标识。
- 运行 ID 的具体格式、时间戳精度和冲突处理由技术设计确定。
- 预置结果、用户运行记录和导入记录由 `results/presets`、`results/runs` 和 `results/imports` 顶层目录明确区分，JSON 不重复保存来源字段。

### 5.3 结果记录完整性

- JSON 是运行记录主体，图表是附属文件。
- 图表缺失不应使 JSON 主记录整体不可读。
- 运行失败或取消时，记录可以不包含完整指标，但必须明确状态和已有阶段信息。
- 只有同一方案 ID 和方案版本的记录才可进行历史比较。
- 加权 RRF 方案的等权参照结果不构成运行记录，不计入历史条数和选中运行数量。

### 5.4 方案版本

- 方案新增、删除或修改变体，或修改变体关键配置时，必须产生新的方案版本。
- 已有运行记录保持原方案版本和配置，不随方案定义更新而改写。
- 方案列表必须显示当前版本；历史记录必须显示记录所属版本。

## 6. 非功能需求

### 6.1 可复现性与一致性

**NFR-001** 每次运行记录必须保存足以识别实验条件的信息，包括方案 ID 与版本、变体 ID、数据集及划分、检索方法、模型 / revision（适用时）、参数、评价设置和运行环境。

**NFR-002** 预置结果必须来自项目已有实验产物，不能用未经实际运行的模拟指标冒充真实结果。

**NFR-003** 同一实例的所有客户端必须看到一致的任务状态和运行记录。

### 6.2 可靠性

**NFR-010** 浏览器刷新或关闭不得导致后端任务丢失或意外终止。

**NFR-011** 任务状态与结果记录必须持久化到本机存储；服务重启后必须取消旧等待任务，并将未正常结束的运行任务标记为中断。

**NFR-012** 导入图表失败、单个模型不可用或单个数据集缺失，不得破坏其他已有记录，也不得阻止资源齐全的变体使用。

### 6.3 安全与隐私

**NFR-020** 默认本机访问；局域网访问必须由主机用户显式开启并受临时访问码保护。

**NFR-021** 记录中不得包含不必要的个人身份信息或设备标识，如用户名、主机名、设备序列号和 IP 地址。

**NFR-022** JSON 导入与图表路径解析必须进行格式校验和路径边界校验，避免读取运行目录之外的文件。

**NFR-023** 产品文档必须说明局域网访问的 HTTP / TLS 安全边界。

### 6.4 可维护性

**NFR-030** Web 界面不得复制实现一套独立检索算法；应复用现有 Python 检索与评价核心。

**NFR-031** 实验方案定义、实验执行、任务管理、结果序列化和 Web 展示应保持清晰边界，便于后续有限配置能力扩展。

**NFR-032** MVP 不引入与当前范围无关的通用插件系统或过度抽象。

### 6.5 可用性与可理解性

**NFR-040** 资源缺失、环境不满足、实验失败、取消、导入拒绝和网络连接失败时，系统必须提供可理解的错误摘要及必要处理指引。

**NFR-041** 任务状态不得只通过颜色区分；必须同时提供文本状态和阶段信息。

**NFR-042** 方案列表不把数据集规模作为主要选择信息；方案详情和结果页可以展示有助于理解实验范围的数据集规模、标识和划分信息。

### 6.6 兼容性

**NFR-050** MVP 必须提供 Windows 与 macOS 的安装 / 检查 / 启动入口。

**NFR-051** Web 页面应可在项目声明支持的现代浏览器中正常使用。具体浏览器最低版本在技术设计和测试计划中明确。

## 7. 验收标准

以下验收场景用于判断 MVP 是否满足本 SRS。具体测试数据和测试脚本可在测试计划中进一步细化。

| 验收 ID | 场景 | 通过条件 |
| --- | --- | --- |
| AT-001 | 默认启动 | 运行启动脚本后可通过本机浏览器访问；未开启局域网时其他设备不能访问 |
| AT-002 | 页面导航 | 四个主要页面和次级设置入口均可访问，布局符合约定 |
| AT-003 | 实验方案浏览 | 展示三套方案、稳定方案 ID、方案版本、数据集语言和划分；规模信息不在列表主信息中 |
| AT-004 | 变体映射 | 三套方案展示 17 个唯一变体 ID；SciFact 9 个、DuRetrieval 对比 4 个、RRF 可运行变体 4 个及 1 个参照结果 |
| AT-005 | 预置结果 | 不准备外置模型和 DuRetrieval 时仍可打开预置结果；RRF 等权参照被明确标识 |
| AT-006 | 资源缺失 | 缺少资源时只禁用受影响变体；同方案其他变体及预置结果继续可用，并列出缺失资源 |
| AT-007 | 单变体任务 | 用户选择一个变体后只创建并执行这一个变体，不隐式执行同方案其他变体 |
| AT-008 | 任务排队 | 连续提交多个变体任务时最多一个运行，其余按提交顺序等待 |
| AT-009 | 浏览器断连 | 浏览器刷新、关闭或客户端断连不取消已提交任务 |
| AT-010 | 阶段状态 | 运行监控显示方案、变体 ID、任务状态、当前阶段、已完成阶段、待执行阶段和运行时间 |
| AT-011 | 取消运行中任务 | 状态先变为 `Cancelling`，在阶段边界停止并变为 `Cancelled`，保留已有运行信息 |
| AT-012 | 取消等待任务 | 等待任务从队列移除且不生成运行记录 |
| AT-013 | 正常关闭 | 服务停止接收新任务并取消全部等待任务；未完成运行标记为 `Interrupted` |
| AT-014 | 重启清队列 | 模拟正常或异常重启后，旧等待任务不恢复且不生成运行记录；未完成运行标记为 `Interrupted` |
| AT-015 | 失败与重试 | 单变体失败只影响该记录；重新运行创建新运行 ID，不覆盖失败记录 |
| AT-016 | 结果展示 | 完成记录显示指标、耗时、当前运行图表、配置、环境、方案与变体标识；不显示 query 级结果 |
| AT-017 | 耗时口径 | 单查询检索均值、查询编码和各检索子阶段分别展示，口径与本文第 3.4 节一致 |
| AT-018 | 单运行图表 | 单次运行目录只引用该变体自身产物，不包含其他变体数据 |
| AT-019 | JSON 记录 | JSON 含格式版本、运行 ID、方案 ID 与版本、变体 ID、状态、时间、配置、指标、耗时、环境和图表路径；不保存结果来源或导入时间 |
| AT-020 | 记录导入 | 有效单份 JSON 导入到 `results/imports/<run_id>/` 并保持原 JSON 内容不变，原始实验时间和环境保持不变 |
| AT-021 | 缺失图表 | JSON 有效但图表缺失时仍可导入并提示图表不可用 |
| AT-022 | 不兼容版本 | 不兼容 JSON 被拒绝并显示明确原因 |
| AT-023 | 未知方案或变体 | 兼容 JSON 可只读导入并显示原始 ID，但禁止参与历史比较 |
| AT-024 | 重复运行 ID | 重复导入相同运行 ID 被拒绝，已有记录不被覆盖 |
| AT-025 | 路径越界 | 图表相对路径越出运行目录时拒绝读取，并显示明确错误 |
| AT-026 | 历史比较 | 只可选择方案 ID 和方案版本相同的记录；可比较不同变体或同变体多次运行 |
| AT-027 | 比较内容 | 指标按名称和 K 对齐，缺失值标记不可比较；对比图按所选记录生成且不写回 JSON |
| AT-028 | 历史列表 | 根据 `presets`、`runs`、`imports` 目录统一展示三类记录，并显示变体、版本、状态和代表性指标 |
| AT-029 | 文件管理 | 应用内没有删除记录功能，README 说明通过文件管理器删除的后果 |
| AT-030 | 局域网访问 | 开启后访问码有效；关闭后访问码失效；客户端可提交 / 取消变体任务但不能修改主机设置 |
| AT-031 | 多客户端一致性 | 两个客户端看到同一任务、队列、状态和历史记录 |
| AT-032 | 队列取消提示 | 正常关闭或重启清理等待队列后，用户能看到等待任务已被取消的明确提示 |
| AT-033 | 脚本交付 | Windows 与 macOS 均有依赖安装、环境检查和启动入口；环境错误输出到终端 |
| AT-034 | 禁止自动下载 | 在断网或资源未配置时，应用不自行下载模型或数据集，并给出资源准备提示 |
| AT-035 | SciFact 许可证 | 软件包包含 SciFact 来源、署名和适用许可证文本 |
| AT-036 | 实验口径 | 预置变体保留原始数据集划分、算法配置、查询前缀和指标口径；DuRetrieval 明确标注 dev |

## 8. 待技术设计明确的事项

以下事项不影响本 SRS 已确认的产品行为，应在软件设计说明书（SDS）或实现方案中确定：

1. Web 框架、前端技术栈、API 组织方式及状态推送方式。
2. 任务队列持久化、正常关闭清队列、异常退出检测和中断标记的具体机制。
3. 阶段边界取消检查点的实现方式及各实验阶段边界。
4. JSON Schema 的具体字段名、类型、必填规则、版本迁移策略。
5. 实验方案配置文件格式，以及本文冻结的方案 ID、变体 ID 和版本的具体存储方式。
6. 运行 ID 的具体格式、时间戳精度及冲突处理。
7. `presets`、`runs`、`imports` 固定分类下的具体目录命名、迁移兼容和异常处理。
8. SciFact 数据包的实际分发内容、署名文件和许可证文本核对。
9. DuRetrieval 目录约定、模型子目录命名和资源完整性检查规则。
10. Python 最低版本、依赖锁定方式及 Windows / macOS 脚本实现。
11. 局域网临时访问码的生成、有效期、会话校验和安全存储方式。
12. 服务监听、防火墙提示、IP 变化检测和客户端断连处理。
13. 支持的浏览器及最低版本。
14. 单运行图表生成、比较图按需生成、读取失败和记录部分损坏时的降级行为细节。
15. 未知方案或变体记录的 Schema 校验边界和只读展示方式。

## 9. 需求变更原则

- 用户明确确认的产品决策是需求基线；技术实现建议不得未经确认自动扩大产品范围。
- 实现中发现需求冲突、原实验核心不支持或存在安全风险时，应先记录问题并提出影响分析。
- 需求变更应同步更新本 SRS、已确认决策或待处理事项，并评估对实现、测试和既有结果兼容性的影响。
- 任何新增功能不得以“顺手完善”为由自动进入 MVP。
