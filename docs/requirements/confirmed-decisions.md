# TextMind 已确认的需求共识

> 状态：阶段性决策记录。本文保留此前产品需求讨论形成的共识，但**当前课程项目的实际实现范围以 [项目范围与阶段目标](../project-scope.md) 为准**。如果本文中的知识管理产品需求与当前项目范围冲突，应将其视为未来产品方向，而不是当前交付要求。

## 0. 当前阶段的范围决策

当前只优先实现最基础的文本检索实验能力：

- 获取公开文本检索数据集。
- 使用不同检索算法和 Embedding 模型处理同一数据集。
- 使用统一评价指标评估检索效果和耗时。
- 保存并比较不同实验结果。

当前允许使用 Python 脚本或 CLI，不要求 GUI，不实现知识库管理、文件浏览、AI 问答、摘要和笔记生成。

此前讨论的知识库中心、工作台、AI 知识加工和桌面应用方向暂时保留，不作为当前阶段的开发前提。实验平台本身也先不追求完整产品化。

## 1. 此前形成的产品方向（暂缓实现）

TextMind 曾被设想为本地优先的个人知识管理与 AI 辅助学习系统，以知识库为中心，而不是以聊天记录或单篇文档为中心。

项目设想包含两个主要模块：
- **知识管理工作台**：日常资料管理、检索和 AI 知识加工。
- **检索实验室**：数据集、算法配置、实验运行、指标评估和结果比较。

两者共用底层检索实现，但实验室的实验索引、配置和结果与日常工作台隔离。核心工作流为“文档 → 检索 → AI 加工 → Markdown 成果 → 再利用”。

以上为未来产品方向记录，当前不要求实现。

## 2. 此前讨论的知识库组织方案（暂缓实现）

- 支持多个独立知识库；一个知识库对应文件系统中的一个真实目录。
- 支持新建知识库和打开已有目录。
- 已有目录可初始化为知识库；如果已有 `.textmind/`，读取元数据并恢复原知识库。
- 同一个目录重复打开时应识别为同一个知识库。
- 多个知识库完全独立，不共享知识库数据，不跨库检索，不建立跨库链接或统一索引。
- 全局模型配置可以共享，但不因此形成知识库数据关联。
- 用户目录是知识库载体；`.textmind/` 保存内部状态，例如元数据、索引和缓存。
- 原始文本文件是事实来源，数据库、元数据和索引属于可重建的派生数据。
- 如果 `.textmind/` 存在但损坏，应进入修复或重建流程，而不是直接当作新知识库。

## 3. 此前讨论的文件管理与同步方案（暂缓实现）

- 采用导入式管理：导入时将文件复制到知识库目录，知识库中的副本成为工作副本。
- 用户可以通过 Finder、VS Code 等外部工具直接修改知识库文件。
- TextMind 只做轻量文件管理，不定位为完整文本编辑器。
- 不采用实时文件监听。每次打开程序或知识库时检查变化，并支持手动同步。
- 采用增量同步：新增、修改、重命名、移动、删除时更新索引；未变化时不重复处理；索引损坏时根据原始文件重建。
- 移除或重置知识库数据时，只删除 `.textmind/` 内部数据，不删除用户文件和 AI 成果。

## 4. 此前讨论的文件格式与知识成果方案（暂缓实现）

- 首版支持 TXT 和 Markdown。
- 知识库内部只保存纯文本笔记。
- 导入 TXT、Markdown 时原样复制，不主动改写或统一重写。
- 未来扩展 PDF、EPUB、DOCX 等格式时，进入知识库前也需要转换为纯文本笔记。
- AI 生成成果统一使用 Markdown，保存在当前知识库的 `AI_note/` 目录。
- AI 成果与原始笔记分开保存，不自动覆盖原始文件。
- AI 成果可以参与知识库检索，但用户可以控制是否纳入。
- 首版不保留多轮对话历史。

## 5. 此前讨论的 AI 知识加工方案（暂缓实现）

- AI 采用用户主动发起的方式，不擅自扫描或处理整个知识库。
- 任务输入方式包括单文档处理、多文档处理和检索结果处理。
- 任务形式采用内置任务 + 自定义任务。
- 知识库问答优先依据检索结果回答，并提供原文出处。

## 6. 当前仍可复用的检索与评价共识

以下内容与当前算法实验目标直接相关，可以作为实现讨论的基础，但具体实现仍应通过实验验证：

- 优先比较 BM25、Dense Retrieval；Hybrid Retrieval 可作为后续扩展。
- BM25 是关键词检索基线；Dense Retrieval 使用 Embedding 模型生成向量。
- Hybrid Retrieval 初步考虑 BM25 + Dense Retrieval + RRF。
- 不同检索方法应使用相同数据集、查询集合和评价规则，保证比较条件一致。
- 核心评价指标为 Precision@K、Recall@K、MRR、NDCG@K 和检索耗时。
- 模型加载时间、索引构建时间与正式检索耗时分开记录。
- 正式计时前进行预热；每条 Query 重复执行多次并报告平均值和中位数。
- 不应将 LLM 生成回答的时间混入检索耗时。

## 7. 历史文本分块设想（当前暂不作为实现要求）

- Markdown 曾考虑按标题层级分块。
- 无标题 Markdown 和 TXT 曾考虑按段落分块，超长段落再拆分。
- 曾计划保留标题路径、来源文件和原文位置等元数据。
- 当前实验应优先尊重公开数据集原有的文档 / Passage 单位，不为适配未来知识库而擅自重新分块。
