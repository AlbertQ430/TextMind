# TextMind 已确认的产品决策

> 本文记录当前讨论中已经确认的决策。未确认的设想应放在 [当前待讨论事项](open-questions.md)，不要将建议误写成需求。

## 1. 产品定位与路线

- TextMind 当前定位为**文本检索实验台**，将已有检索实验能力封装成可交互、可观察、可比较的软件。
- 产品路线采用 A（实验演示型）逐步演进到 B（有限实验配置型）。
- 不建设 C（通用实验研究平台）。
- MVP 首先实现 A；B 是后续逐步开放的能力。
- A 是 B 的受限模式，底层实验执行流程应尽量共用。

## 2. MVP 的核心工作流

- MVP 以整套数据集上的预设基准实验为主体。
- 用户选择预设实验方案、运行实验并查看指标、耗时和结果。
- 单条 Query 即时检索不作为 MVP 主体。
- 实验方案使用项目内置的数据集、算法和模型组合；MVP 暂不提供自由配置入口。

## 3. 预置结果与重新运行

- 采用“预置结果 + 支持重新运行”的方式。
- 预置结果供用户快速浏览，不需要每次打开软件都等待模型加载和完整实验执行。
- 用户可以主动重新运行预设实验，执行真实检索与评价流程。
- 必须明确区分预置结果和实际运行结果。
- 每次运行产生独立结果，不覆盖预置结果。

## 4. 后续有限配置方向

MVP 稳定后逐步考虑：
- 选择已支持的算法与 Embedding 模型。
- 调整有限范围内的参数，例如 BM25 k1 / b、RRF 权重。
- 保存运行历史并查看、比较实验结果。
- 未来可视需求增加可选数据集。

## 5. 明确不纳入当前路线

- 个人知识库管理、文件浏览、文件同步。
- AI 问答、摘要、笔记生成和聊天历史。
- 任意第三方模型路径、用户自定义检索器和通用插件系统。
- 任意检索器组合、自动调参、复杂实验组和自定义指标。
- 面向研究人员的通用实验研究平台。

## 6. 仍可复用的实验原则

- 不同方法的比较应明确数据集、查询集合、Qrels、评价规则和关键参数。
- 区分模型加载、索引 / 语料编码、查询编码、检索和评价等阶段耗时。
- 实验结果应记录配置、运行环境、指标和必要的耗时信息。
- 缓存命中情况需要可识别，避免混淆不同运行条件下的耗时。
- 对 dev split 上的参数探索应明确标注，不将其表述为独立测试集泛化结论。

## 7. 决策状态约定

- “已确认”仅表示用户明确认可的方向。
- 技术实现建议、尚未讨论的交互细节和实现取舍，不自动成为产品需求。
- 完整 SRS 尚未冻结；本文件是阶段性决策记录。
