# TextMind 已确认的产品决策

> 本文记录当前讨论中已经确认的决策。未确认的设想应放在 [当前待讨论事项](open-questions.md)，不要将建议误写成需求。

## 1. 产品定位与路线

- TextMind 当前定位为**文本检索实验台**，将已有检索实验能力封装成可交互、可观察、可比较的软件。
- 产品路线采用 A（实验演示型）逐步演进到 B（有限实验配置型）。
- 不建设 C（通用实验研究平台）。
- MVP 首先实现 A；B 是后续逐步开放的能力。
- A 是 B 的受限模式，底层实验执行流程应尽量共用。

## 2. MVP 的核心工作流与页面结构

- MVP 以整套数据集上的预设基准实验为主体。
- 用户选择预设实验方案、运行实验并查看指标、耗时和结果。
- 单条 Query 即时检索不作为 MVP 主体。
- 实验方案使用项目内置的数据集、算法和模型组合；MVP 暂不提供自由配置入口。
- 主要页面采用**左侧固定导航栏 + 右侧独立工作区**的布局。
- 主要页面分为：
  1. **实验中心**：浏览预设实验方案、选择并启动实验。
  2. **运行监控**：查看当前任务、等待队列、运行阶段和取消任务。
  3. **实验结果**：查看单次运行的指标、图表、检索结果及详情。
  4. **历史记录**：浏览历史运行记录、导入 JSON，并比较同一实验方案的多次运行。
- **设置**作为次级入口，集中放置资源路径、Python 环境和局域网访问等配置。
- 以上是页面结构与导航方向，不代表页面内部的全部交互细节已经冻结。
- 预设实验沿用课程实验阶段已经完成的实验，不额外扩展新的算法研究内容。
- 预设实验按数据集与实验目的组织，覆盖 SciFact 英文检索实验、DuRetrieval 中文检索实验，以及 DuRetrieval 加权 RRF 参数探索；具体方案条目应映射到已有实验配置、结果 JSON 与图表。
- 实验中心不展示数据集规模；保留数据集名称、语言及必要的数据集划分信息（例如 DuRetrieval dev split）。

## 3. 本地 Web 与局域网访问

- 软件采用**本地 Web 应用**形态，不依赖云服务器。
- 用户在运行 TextMind 的主机上启动服务，通过浏览器访问。
- 支持可选的局域网访问，其他设备可通过主机的局域网地址访问同一个 TextMind 实例。
- 不做公网访问、云端部署和多用户账号系统。
- 实验、数据集、模型和结果均由运行服务的主机负责；浏览器客户端不直接访问主机文件系统。
- 默认仅允许本机访问；局域网访问由用户主动开启，客户端通过主机局域网 IPv4 地址和端口访问。
- 开启局域网访问时使用临时访问码；关闭后访问码失效。
- 局域网客户端可以查看结果、查看运行状态、提交实验和取消实验；不能修改主机资源路径、Python 环境等主机配置，也不能控制局域网访问开关。
- 多个客户端共享同一个 TextMind 实例、任务队列和结果数据；不提供公网访问、云端部署或多用户账号系统。
- 服务端默认仅监听本机；开启局域网访问后才对局域网提供服务。

## 4. 实验任务调度

- MVP 采用单任务执行机制：同一时间只运行一个实验。
- 其他实验任务进入等待队列。
- 实验任务由后端统一管理，不由浏览器页面各自维护。
- 多个客户端可以同时查看同一实例的任务状态和历史结果。
- 支持取消正在运行的任务；取消过程先进入“取消中”，在安全停止后标记为“已取消”，并保留运行记录。
- 等待中的任务允许取消；取消后直接从队列移除，不生成运行记录。
- 任务状态至少包括等待中、准备中、运行中、取消中、已完成、已失败、已取消和已中断。
- 失败实验重新运行时创建新的运行记录，原失败记录保持不变。
- 取消、失败和中断的记录不得显示为正常完成的实验。

## 5. 预置结果与重新运行

- 采用“预置结果 + 支持重新运行”的方式。
- 预置结果供用户快速浏览，不需要每次打开软件都等待模型加载和完整实验执行。
- 用户可以主动重新运行预设实验，执行真实检索与评价流程。
- 必须明确区分预置结果和实际运行结果。
- 每次运行产生独立结果，不覆盖预置结果。

## 6. 实验运行交互

- 运行过程采用**阶段式状态展示**，不要求将整体进度量化为百分比。
- 至少展示当前所处的实验阶段、已完成阶段和待执行阶段；不要求整体百分比进度或实时详细日志流。
- 展示当前任务、等待队列、运行阶段和已运行时间。
- 用户可以取消正在运行的实验；取消通过安全停止机制完成，不要求强制立即终止当前底层操作。
- 正在运行的任务取消后保留记录；等待中的任务取消后不保留记录。
- 失败记录包含失败阶段、错误摘要、技术错误详情和运行时间。
- 失败实验重试按一次新的实验运行处理，生成新的运行 ID 和独立记录。
- 浏览器关闭不影响后端实验执行；服务正常关闭时尽可能停止任务，服务异常退出后将未正常结束的任务标记为中断。
- MVP 不支持断点续跑。

## 7. 实验结果、图表与 JSON 记录

- 每次实验运行都生成一份独立 JSON 记录。
- 软件支持导入单份符合格式规范的 JSON，以查看其中的实验结果。
- JSON 记录结构化实验配置、指标、耗时、运行状态、运行时间、格式版本和实验环境等信息。
- 实验环境信息用于描述运行条件，例如操作系统、CPU 架构 / 型号、GPU 型号、Python、PyTorch、CUDA（适用时）及关键依赖版本；不记录主机名、用户名、设备序列号、IP 地址等不必要的个人或设备标识。
- 每次运行生成的图表作为独立图片文件保存；JSON 通过**相对路径**引用对应图表。
- 结果页面沿用课程实验中的指标数值和图表，不另建评价体系；指标数值以表格展示，可视化展示适用于当前实验方案的已有图表。
- 单次结果页面依次组织实验概览、指标数值、可视化结果、实验配置和运行环境；配置与环境信息可以折叠。
- 实验信息描述实验实际发生时的配置和设备环境。导入记录继续显示原始运行时间、实验配置和原始设备环境，不以当前查看设备或导入时间替代。
- MVP 不展示查询级检索结果和错误分析案例；作为后续扩展方向。
- 导入 JSON 时尝试按相对路径加载图表。若图片文件缺失或无法读取，应提示图表不可用，但不能导致整个实验记录导入失败。
- 导入 JSON 时，将 JSON 和其可用的附属图表复制到 TextMind 自己的 results 目录，形成独立记录目录；缺失的图表不阻止导入。
- 导入记录保留原始实验时间、配置和设备环境，不用导入时间覆盖实验运行时间。
- 导入记录可以查看，并参与同一实验方案的历史比较。
- 暂不支持批量导入，也不支持将已导入的记录再次导出。
- JSON 格式版本不兼容时拒绝导入，并向用户说明原因。
- 删除实验记录由用户通过操作系统文件管理器完成，TextMind 应用内不提供删除记录功能。
- 每次运行的 JSON 与图表放在同一个运行目录中。JSON 是记录主体，图表是附属文件；results/README.md 说明两者关系及目录管理方式。
- 预置结果也作为文件提供；results/README.md 应说明其用途和删除后果。应用不提供预置结果保护或恢复功能。

### 7.1 运行标识与实验方案标识

- 实验方案 ID 应稳定，用于识别同一个预设实验方案。
- 每次运行使用独立的运行 ID；运行时间 / 时间戳可作为运行 ID 的主要组成部分。
- 不应使用每次运行的时间戳替代实验方案 ID，否则同一方案的多次运行无法自然归组比较。
- 时间戳精度和冲突处理方式属于实现细节，需保证运行 ID 唯一。

### 7.2 指标与比较

- 指标沿用现有实验评价体系：P@K、R@K、MRR、NDCG@K，以及实验耗时。
- 具体 K 值沿用对应实验方案的评价设置，不为界面统一而擅自改变。
- 可视化覆盖算法对比、Embedding 模型对比、参数变化（例如 RRF 权重）和耗时对比。
- 历史记录列表展示实验名称、运行时间、状态、运行 ID 和代表性指标；本机运行记录与导入记录放在同一列表。
- 用户自行选择至少两条同一实验方案的记录进行比较，不自动选择最近运行。
- 比较页面复用单次结果的指标和图表展示；只突出显示运行配置之间的差异。
- 历史比较限定在同一实验方案内，不提供不同实验方案之间的自由比较。
- 不提供复杂筛选、自定义指标、自动分析报告或应用内删除记录功能。

## 8. 数据集、模型与资源路径管理

- SciFact 作为小规模英文数据集，默认随软件提供并自动配置。
- DuRetrieval 不随软件提供；软件展示数据集来源和获取说明，由用户自行获取并手动配置数据集目录。
- 当前阶段不随软件提供 Embedding 模型文件；用户自行准备模型。
- 模型采用**统一模型根目录**：用户配置一次根目录，TextMind 按预设模型名称在对应子目录中查找模型。
- 不提供每个模型单独指定路径的例外配置。用户自行通过文件管理器调整模型文件组织，再修改统一根目录。
- 用户手动配置外部数据集目录和模型根目录；TextMind 检查路径、必要文件及资源可用性，并在路径失效或资源不完整时给出明确提示。
- 不自动扫描磁盘寻找数据集或模型，不自动下载资源，不负责复制、移动或整理资源文件。
- 资源路径由运行服务的主机配置。局域网客户端可以查看资源状态，但不能任意修改主机资源路径。

## 9. Python 环境管理

- README 说明所需 Python 环境、第三方依赖、推荐 Embedding 模型及完整使用步骤。
- 提供独立依赖安装脚本，由用户手动运行；脚本创建项目专用 Python 虚拟环境并安装锁定版本的依赖。
- 提供独立环境检查脚本，复用现有 test 脚本的检查逻辑；检查结果与错误信息输出到终端。
- 提供独立启动脚本，用户通过脚本启动本地 Web 服务；日常启动不要求用户手动输入 Python 命令。
- Windows 与 macOS 提供适配各自系统的脚本入口，底层检查与启动逻辑尽量共用 Python 实现。
- 启动时执行必要检查。Python 环境或核心依赖不满足时阻止启动；单个数据集或模型缺失时，软件仍可启动，但对应实验标记为不可用并说明原因。
- 不自动下载模型或数据集；模型由用户自行准备。

## 10. 数据集与运行环境分发

- SciFact 默认随软件提供。
- DuRetrieval 不随软件提供；软件提供数据集来源和获取说明。
- SciFact 的分发需附带来源、署名和许可证说明。现有数据集调研记录标注其许可证为 CC-BY-SA-4.0。
- 当前阶段不随软件提供 Embedding 模型文件。
- Python 版本和依赖版本应结合现有已验证实验环境确定，并通过依赖锁定文件固定；具体版本号属于交付设计阶段的核对事项。

## 11. 后续有限配置方向

MVP 稳定后逐步考虑：
- 选择已支持的算法与 Embedding 模型。
- 调整有限范围内的参数，例如 BM25 k1 / b、RRF 权重。
- 保存运行历史并查看、比较实验结果。
- 未来可视需求增加可选数据集。

## 12. 明确不纳入当前路线

- 个人知识库管理、文件浏览、文件同步。
- AI 问答、摘要、笔记生成和聊天历史。
- 任意第三方模型路径、用户自定义检索器和通用插件系统。
- 任意检索器组合、自动调参、复杂实验组和自定义指标。
- 面向研究人员的通用实验研究平台。
- 云端部署、公网访问和多用户账号系统。
