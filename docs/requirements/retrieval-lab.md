# TextMind 检索实验室需求约定

> 状态：阶段性共识。本文记录已经讨论并基本确定的方向；具体数据集版本、指标计算细节和实现方式仍待决定。

## 1. 定位与目标

检索实验室是 TextMind 的独立模块，与知识管理工作台并列。它是小型信息检索实验平台，而不只是算法演示页面。

核心闭环：

**数据集 → 实验配置 → 实验运行 → 结果评估 → 结果比较 → 将合适配置应用到工作台**

实验室与工作台共用底层检索服务，但实验配置、实验索引和实验结果独立保存。实验室不得修改工作台正在使用的索引或检索配置。

## 2. 数据集

### 2.1 数据集来源

支持三类实验语料：
1. 公开数据集。
2. 用户导入的自定义数据集。
3. 用户当前已有的 TextMind 知识库。

公开数据集不打包进安装程序。界面可以展示名称、语言、规模、来源和下载信息，由用户选择下载或导入并在本地使用。公开数据集应保留来源和版本信息。

### 2.2 公开数据集候选

| 数据集 | 初步用途 | 状态 |
| --- | --- | --- |
| BEIR / SciFact | 英文开发与基础验证 | 候选 |
| DuRetrieval | 中文正式测试集候选 | 候选 |
| T2Retrieval | 后续扩展 | 候选 |

以上只是候选方向，不代表已确定最终采用的具体版本。版本、许可证、下载方式和标注结构仍需核实。

### 2.3 自定义数据集格式

初步采用以下标准文件结构：

```text
MyDataset/
├── corpus.jsonl
├── queries.jsonl
├── qrels.tsv
└── metadata.json
```

- **Corpus**：文档集合。
- **Queries**：查询集合。
- **Qrels**：查询与相关文档之间的相关性标注，建议支持等级标注，例如 0/1/2。
- **Metadata**：数据集名称、语言、描述、版本等信息。

通过唯一 ID 关联文档、查询和标注，并在导入时进行格式校验。

数据集用途区分：
- **正式评价数据集**：Corpus、Queries、Qrels 完整，可以计算标准监督评价指标。
- **普通检索语料**：缺少 Queries 或 Qrels 时，仍可运行检索、查看结果和耗时，但不显示缺乏标注依据的监督评价指标。

首版不开发人工标注界面。

### 2.4 使用现有知识库作为实验语料

允许直接使用当前知识库作为实验语料：
- 读取知识库文本和分块结果，不复制原始文件。
- 实验室建立独立实验索引，不影响工作台索引。
- 实验可以调整分块策略、检索算法和参数。
- 实验配置与结果独立保存，不修改知识库本身。
- 如果没有 Queries 和 Qrels，只能查看检索结果和耗时，不能计算标准监督评价指标。

**语料快照首版不实现。** 现有知识库实验主要用于个人调试配置，用户接受笔记修改后历史实验无法完全复现的情况。实验记录仍应保存当次结果、知识库标识、文件数量、Chunk 数量和相关配置等基本信息。历史结果不能被后续运行覆盖。

如果数据集被删除，历史实验记录仍应保留结果和数据集基本信息，并标记原数据集不可用。

## 3. 检索算法与配置

首版优先支持：
- **BM25**：关键词检索基线。
- **Dense Search**：基于 Embedding 的语义检索。
- **Hybrid Search**：融合关键词检索与语义检索，初步考虑 RRF。

Reranker 后置，不作为首版重点。

区分两类配置：
- **算法配置**：检索方法、模型、算法参数等。
- **实验配置**：数据集、算法配置、分块参数、评价指标等。

算法配置可以复用于多个实验，例如不同 BM25 参数、不同 Dense 模型或不同 RRF 配置。

首版以用户手动添加多个配置为主，不开发复杂的网格搜索或自动参数搜索。

## 4. 实验运行模式

支持两种运行模式：

### 4.1 单次实验

一个数据集、一种算法配置和一组评价指标。

### 4.2 批量对比实验

在同一个数据集下添加多个算法配置并统一运行比较。

批量对比中的各组实验应使用相同的数据集、查询集合和评价指标，以保证比较条件一致；算法参数可以不同。

实验室允许调整分块策略，以支持两类实验：
- 固定分块策略，比较检索算法。
- 改变分块策略，比较检索效果。

## 5. 评价指标与结果分析

目前确定的核心指标：
- Precision@K
- Recall@K
- MRR
- NDCG@K
- 检索耗时

支持不同 K 值，例如 Precision@5、Recall@10 和 NDCG@10。

结果分析需要包含：
1. 总体指标结果。
2. 不同算法或配置之间的比较。
3. 单条 Query 的检索结果与排名详情。
4. 对应的相关性标注（如果数据集提供 Qrels）。
5. 检索耗时。

无 Qrels 时，不展示 Precision、Recall、MRR、NDCG 等依赖相关性标注的监督评价指标。

### 5.1 结果展示形式

当前倾向：
- 每个指标分别使用柱状图比较不同检索配置。
- 提供精确数值表。
- 提供单条 Query 详情，按需查看，不默认占据主要展示区域。
- 支持选择 K 值。
- 支持选择不同实验记录进行比较。

### 5.2 耗时测量

采用端到端检索耗时，不将 Query 编码与索引召回拆分为独立的核心指标：
- 模型加载时间单独记录，不计入检索耗时。
- 索引构建时间单独记录，不计入检索耗时。
- 正式计时前进行预热。
- 每条 Query 重复执行 3 次。
- 记录平均检索耗时和中位检索耗时。
- 同一批实验尽可能复用已加载的模型实例。
- 检索耗时不包括后续 LLM 生成回答的时间。

## 6. 实验记录与复现

区分实验配置和实验记录：
- **实验配置**描述一次实验如何运行。
- **实验记录**描述某一次实际运行的参数和结果。

同一实验配置可以运行多次，每次运行产生独立记录。新运行不得覆盖旧实验结果。

实验记录至少保留：
- 实验名称。
- 数据集名称、版本和规模。
- 算法与模型名称、版本或标识。
- 分块参数。
- 算法参数。
- 评价指标及结果。
- 检索结果。
- 开始时间、结束时间和运行耗时。
- 模型加载时间和索引构建时间等辅助信息。
- 运行环境信息，例如操作系统、Python 版本和关键依赖版本。

对现有知识库语料，不承诺通过快照实现严格复现；记录实验时的知识库标识和基本规模信息即可。

## 7. 配置应用与导出

- 实验室结果可以用于复制配置。
- 可以将合适的配置应用到当前知识库或设为全局默认配置。
- 应用配置不修改历史实验记录。
- 实验配置、评价指标、单条查询结果和对比数据倾向支持 CSV / JSON 导出。

具体导出字段和交互方式尚未确定。
