# 检索实验与执行约定

> 本文描述 TextMind 已有检索实验核心及软件化时应保留的实验约定。它不是完整 SRS，也不规定 GUI 的具体交互。

## 1. 实验目标

在明确的数据集、查询集合和评价规则下，比较不同检索方法与 Embedding 模型的效果和运行表现。

基本流程：

**实验方案 → 数据集 → 检索方法 / 模型 → 检索结果 → 指标计算 → 结构化结果**

## 2. 数据集

实验数据通常由以下部分组成：

- **Corpus**：待检索文档或 Passage。
- **Queries**：检索查询。
- **Qrels**：Query 与相关文档之间的相关性标注。

数据集应记录来源、版本、语言、划分方式和规模。数据转换应保留原始 ID 与相关性等级。

缺少 Qrels 的数据可用于功能演示或查看检索结果，但不能计算依赖人工相关性标注的标准指标。

当前实验数据集与来源见 [datasets.md](../datasets.md)。

## 3. 已有检索方法

- **BM25**：关键词检索基线。
- **Dense Retrieval**：使用 Embedding 模型将 Query 和文档编码为向量，再按相似度检索。
- **Hybrid Retrieval**：融合 BM25 与 Dense Retrieval，当前实验采用 RRF。

已有模型包括 Qwen3-Embedding-0.6B、BGE-M3、bge-small-zh-v1.5 和 all-MiniLM-L6-v2。软件 MVP 采用哪些固定组合，由预设实验方案确定。

## 4. 比较原则

- 各实验组使用匹配的数据集版本、Corpus、Queries、Qrels 和数据划分。
- 固定或明确记录 Top-K、文本预处理和评价实现。
- 比较 Embedding 模型时，尽量保持模型以外的条件一致。
- 明确 BM25 与 Dense 在索引构建和检索流程上的差异。
- 记录模型名称 / 版本、关键参数、运行环境和数据集标识。
- 不把模型加载、语料编码、查询编码、检索和评价耗时混为一谈。

## 5. 评价指标

已有实验使用：
- Precision@K
- Recall@K
- MRR
- NDCG@K
- 分阶段耗时

具体 K 值、聚合方式和无相关文档 Query 的处理规则，应以当前评价代码和实验记录为准；如需调整，必须同步更新测试与结果说明。

## 6. 结构化实验结果

现有实验会保存结构化结果，并生成汇总表、图表和错误分析材料。软件化应优先复用现有结果格式与实验执行逻辑。

每次运行至少应能关联：
- 实验方案 / 数据集标识。
- 检索方法、模型和关键参数。
- 指标结果。
- 运行环境与运行信息。
- 可获得的分阶段耗时。

GUI 需要在此基础上提供读取、展示和历史浏览能力。具体字段、版本兼容和结果目录组织仍待技术设计确认。
