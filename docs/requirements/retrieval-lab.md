# 文本检索实验约定

> 当前阶段文档。本文件只约定算法实验所需的最小流程，不要求实现 GUI 或完整实验管理产品。

## 1. 实验目标

在相同数据集、查询集合和评价规则下，比较不同检索算法与 Embedding 模型的检索效果和运行表现。

实验基本流程：

**数据集 → 检索方法 / 模型 → 检索结果 → 指标计算 → 结果比较**

## 2. 数据集

当前优先使用包含以下三类数据的数据集：

- **Corpus**：待检索文档或 Passage。
- **Queries**：检索查询。
- **Qrels**：Query 与相关文档之间的相关性标注。

数据集需要记录来源、版本、语言、许可证、划分方式和规模。导入后统一转换为项目内部格式，但应保留原始 ID 和相关性等级。

缺少 Qrels 的数据仍可用于功能调试和查看检索结果，但不能计算依赖人工相关性标注的标准指标。

公开数据集候选、规模和获取方式见 [datasets.md](../datasets.md)。目前尚未最终选定正式数据集。

## 3. 检索方法

优先实现：

1. **BM25**：关键词检索基线。
2. **Dense Retrieval**：使用 Embedding 模型将 Query 和文档编码为向量，再按相似度检索。
3. **不同 Embedding 模型对比**：固定数据集、检索流程和评价方式，只替换向量模型。

如果时间和实现进度允许，再增加：

4. **Hybrid Retrieval**：融合 BM25 与 Dense Retrieval，初步考虑 RRF。

Reranker、模型微调和复杂自动调参暂不纳入基础实现。

## 4. 公平比较原则

- 各实验组使用相同的数据集版本、Corpus、Queries、Qrels 和数据划分。
- 固定检索 Top-K、文本预处理和评价实现。
- 比较 Embedding 模型时，除模型本身外尽量保持其他条件一致。
- 比较 BM25 与 Dense 时，明确说明两者索引构建与检索流程的差异。
- 记录模型名称、版本、关键参数、运行环境和数据集标识。
- 不把模型加载、索引构建和检索耗时混为一谈。

## 5. 评价指标

首批核心指标：

- Precision@K
- Recall@K
- MRR
- NDCG@K
- 检索耗时

具体 K 值、指标聚合方式、无相关文档 Query 的处理规则，需要在实现评价模块前统一确定，并通过测试用例验证。

耗时至少分别记录：

- 模型加载时间。
- 索引构建时间。
- 正式检索时间。

正式计时前预热；重复执行 Query 并报告平均值和中位数。重复次数应在所有对比组中保持一致。

## 6. 实验结果

最小实验结果至少包含：

- 数据集名称、版本和规模。
- 检索方法与模型名称 / 版本。
- 关键参数。
- 各评价指标结果。
- 模型加载、索引构建和检索耗时。
- 运行环境信息。

首版只需将结果保存为结构化文件（例如 JSON / CSV），并能生成比较表格或图表。暂不要求数据库、历史实验管理界面或 GUI。
