# TextMind 当前待讨论事项

> 本文件记录软件化需求探索中尚未决定的问题。这里只列讨论议题，不代表已经形成需求或技术方案。

## 1. 实验方案与预置实验

- MVP 内置哪些预设基准实验，以及每个实验包含哪些方法 / 模型。
- 每个实验方案的目的、背景、数据集说明和比较边界如何介绍。
- 是否展示预计耗时、资源需求和数据集规模。
- 预置结果具体选择哪些已有运行结果，以及如何标记其来源和环境。

## 2. 实验运行细节

- 阶段状态如何呈现，阶段内部是否需要补充文字说明。
- 取消实验时如何安全停止当前阶段、清理临时资源并保存取消记录。
- 失败记录保留哪些错误信息，是否提供重试入口。
- 缓存策略如何向用户解释；如何区分冷启动与缓存命中后的耗时。
- 运行结果展示哪些阶段耗时，以及各阶段耗时的统计口径。

## 3. JSON 与图表文件规范

- JSON schema 的具体字段、格式版本策略和兼容规则。
- 时间戳运行 ID 的精度与冲突处理方式。
- 每次运行的图表种类、命名规则和文件目录组织方式。
- 导入 JSON 时相对路径的解析基准，以及图片缺失 / 损坏时的提示方式。
- 导入时如何校验文件格式、实验方案 ID 和必要字段。
- 删除 JSON 后，附属图表文件是否同步删除，以及如何避免误删被其他记录引用的文件。

## 4. 结果呈现与历史比较

- 历史记录列表需要展示哪些摘要信息。
- 同一实验方案的比较界面默认展示哪些指标和耗时。
- 是否允许用户选择参与比较的具体运行记录。
- 是否需要展开查看查询级结果或错误分析。
- 配置不同的同方案记录如何突出显示差异。

## 5. 数据集与运行环境交付

- SciFact 随软件分发时的目录组织、来源说明和 CC-BY-SA-4.0 许可证文件如何放置。
- DuRetrieval 的下载说明、目录约定和数据完整性检查方式。
- Python 版本、依赖版本及安装 / 环境检查流程。
- Embedding 模型由用户自行准备时，模型获取、路径配置和缺失提示如何设计。
- GUI 打包方式，以及是否要求用户预先安装 Python 环境。

## 6. 技术架构

- GUI 技术栈和应用打包方式。
- 实验核心与 GUI 的调用边界、任务状态传递和取消机制。
- 现有实验 JSON 结果格式是否足够支持软件展示与历史记录。
- 如何在不破坏实验复现性的前提下管理模型、向量缓存和运行产物。

## 7. 当前明确不讨论的方向

- 通用插件系统、任意第三方检索器和模型路径。
- 自动调参、批量参数搜索和自定义评价指标。
- 个人知识库管理、AI 问答与笔记加工。
- 将单条 Query 即时检索改成 MVP 的主要工作流。

完整 SRS 尚未冻结；讨论应围绕已确认的 MVP 边界逐步推进。
