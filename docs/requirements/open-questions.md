# TextMind 当前待讨论事项

> 本文件记录软件化需求探索中尚未决定的问题。这里只列讨论议题，不代表已经形成需求或技术方案。

## 1. 实验运行体验

- 是否需要显示分阶段进度（模型加载、语料编码、查询编码、检索、评价）。
- 运行过程中是否支持取消、失败重试，以及失败信息如何呈现。
- 缓存策略如何向用户解释；如何区分冷启动与缓存命中后的耗时。
- 运行结果是否需要显示每个阶段的详细耗时，还是只展示核心耗时。

## 2. 实验结果与历史记录

- 历史记录列表需要展示哪些摘要信息。
- 是否支持删除单次运行记录。
- MVP 是否需要在同一实验方案内比较多次运行结果。
- 结果文件的组织方式、保留策略与兼容性如何设计。
- 预置结果与用户运行结果在界面上如何区分。

## 3. 结果呈现

- 默认展示哪些核心指标、图表和检索案例。
- 是否允许展开查看查询级结果或错误分析。
- 是否需要提供实验方案的背景说明，帮助用户理解比较目的与结论边界。

## 4. 实验方案

- MVP 内置哪些预设基准实验，以及每个实验包含哪些方法 / 模型。
- 实验方案是否需要展示预计耗时、资源需求和数据集规模。
- 未来开放 B 阶段配置能力时，具体开放哪些参数和选择范围。

## 5. 技术与交付

- GUI 技术栈和应用打包方式。
- 实验核心与 GUI 的调用边界、任务状态传递方式。
- 现有实验 JSON 结果格式是否足够支持软件展示与历史记录。
- 如何在不破坏实验复现性的前提下管理模型、向量缓存和运行产物。

## 6. 当前明确不讨论的方向

- 通用插件系统、任意第三方检索器和模型路径。
- 自动调参、批量参数搜索和自定义评价指标。
- 个人知识库管理、AI 问答与笔记加工。
- 将单条 Query 即时检索改成 MVP 的主要工作流。

完整 SRS 尚未冻结；讨论应围绕已确认的 MVP 边界逐步推进。
