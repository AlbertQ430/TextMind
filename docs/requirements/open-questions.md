# TextMind SRS 与技术设计待处理事项

> 核心产品方向与 MVP 范围已基本确定。SRS 草案见 [SRS.md](SRS.md)。本文件只跟踪需求评审后需要补齐的规范和技术设计事项，不重新开启已确认的产品方向讨论。

## 1. 需求评审前核对

- 将 SRS 中的三个预设方案 ID 与实际实验配置、预置结果 JSON 和图表文件逐项核对。
- 核对 SciFact 各实验变体：Qwen3 无前缀 / Instruct、BGE-M3 无前缀 / 自定义前缀、all-MiniLM、BM25，以及三种已有 Qwen3 Hybrid 配置。
- 核对 DuRetrieval 对比方案和加权 RRF 扫描方案的配置、数据划分及图表映射。
- 评审 SRS 中的功能需求、非功能需求和验收标准；确认无遗漏或与已确认决策冲突的内容。

## 2. 文件与数据规范

- 定义 JSON Schema 的具体字段名、类型、必需字段、可选字段、格式版本和兼容策略。
- 定义实验方案 ID、运行 ID 的格式、版本策略及唯一性保证。
- 定义预置结果、用户运行记录、导入记录的目录组织。
- 定义图表命名、相对路径解析基准、导入校验和缺失图表提示。
- 编写 results/README.md，说明记录目录结构、JSON 与图表关系，以及用户通过文件管理器删除记录的后果。

## 3. 资源与交付规范

- 确认 SciFact 随软件分发时的实际数据包、目录组织、来源 / 署名文件和许可证文本。
- 明确 DuRetrieval 的获取说明、目录约定和完整性检查规则；确保使用 C-MTEB 子集及约定的 dev split。
- 明确统一模型根目录下各预设模型的子目录命名和必要文件检查规则。
- 根据现有实验环境核对支持的 Python 版本、依赖锁定文件和安装脚本行为。
- 确认 Windows 与 macOS 的依赖安装、环境检查和启动脚本入口及 README 使用说明。

## 4. 技术设计阶段处理

- 选择 Web 框架与前端技术栈，定义前后端接口和客户端状态同步方式。
- 明确实验核心、Web 后端、任务队列、结果序列化和结果存储的模块边界。
- 设计任务持久化、异常退出检测、服务正常关闭和运行中安全取消机制。
- 设计本机 / 局域网监听、临时访问码、防火墙提示、IP 变化和客户端断连处理。
- 明确缓存复用、运行产物生成和预置结果打包策略。
- 明确支持的浏览器及最低版本。

## 5. 明确不纳入 MVP

- 查询级检索结果、query 级诊断分布和错误分析案例展示。
- 实时详细日志流、整体百分比进度、自动重试和断点续跑。
- 多任务并行、任务优先级调整。
- 批量导入 JSON、再次导出导入记录、应用内删除记录。
- 复杂筛选、自定义指标、自动生成实验分析报告。
- 通用插件系统、任意第三方检索器和模型路径、自动调参。
- 个人知识库管理、AI 问答与笔记加工。
- 单条 Query 即时检索作为 MVP 的主要工作流。
- 云端部署、公网访问和多用户账号系统。

## 6. 阶段说明

- SRS 草案 v0.1 已建立，下一步先进行需求评审和修订。
- 需求评审通过后，再进入软件设计说明书（SDS）与开发计划阶段。
- 本文件中的技术事项不代表技术方案已经选定；具体实现应在设计阶段结合现有代码和平台约束确定。
