## 1. 任务定义

### 1.1 目标

把 `results/presets`、`results/runs`、`results/imports` 中的终态运行记录接入 Web 应用，提供安全的单运行结果详情、三类来源统一历史列表和严格限定在同方案版本内的按需比较。

### 1.2 范围

包含：

- 三类结果目录的统一扫描、来源识别和单记录读取。
- 损坏、缺失、重复 Run ID 和目录/JSON ID 不一致的隔离显示。
- 单运行结果页：概览、状态、指标、14 项耗时、配置、环境、单运行图表和错误信息。
- 历史列表：来源、方案、变体、版本、时间、状态、Run ID 和代表性指标。
- 等权 RRF 参照结果识别、历史隐藏和比较基线支持。
- 同方案版本比较：选择校验、指标对齐、配置/环境差异和比较图。
- 比较图按需在内存生成，不写入任何运行目录。
- 安全读取和返回运行目录内图表，不向客户端暴露绝对路径。
- `records.changed` SSE 事件和历史页刷新。
- 结果与历史页面的空状态、损坏记录状态和非完成状态。

不包含：

- JSON 导入接口、上传和导入目录写入。
- 预置结果构建脚本。
- 资源路径、环境检查和设置页。
- LAN 访问码和权限控制。
- 删除记录、导出记录、query 级结果或错误案例展示。
- 修改运行记录 Schema、任务状态机或既有 JSON。

## 2. 结果目录与读取模型

### 2.1 来源

稳定来源标识：

| 目录 | `source` |
| --- | --- |
| `results/presets` | `presets` |
| `results/runs` | `runs` |
| `results/imports` | `imports` |

来源只由记录所在顶层目录决定。`run.json` 内不得增加 `source`、`result_source` 或 `import_time`。

### 2.2 扫描

- 只扫描三类来源目录的一级 `<run_id>/run.json`。
- 跳过隐藏目录，特别是 `results/runs/.staging`。
- 来源目录不存在时返回空列表，不创建目录。
- 有效记录按 `started_at` 倒序、`run_id` 升序稳定排列。
- 目录名必须与 JSON `run_id` 一致。
- 同一 Run ID 出现在多个来源时视为冲突，不得任意选择一个。
- 单条记录损坏不得阻止其他历史记录显示。
- 损坏或冲突记录的展示只能包含 Run ID、来源、稳定错误码和简短原因，不返回绝对路径。
- 记录合法但图表缺失时，记录仍可查看；图表逐项标记不可用。
- 读取 `run.json` 和图表时必须拒绝解析后越出对应运行目录的路径，包括符号链接。

### 2.3 参照结果

- 根据 _PlanCatalog_ 中 `ReferenceVariant` 的来源关系和源变体 `preset_run_id` 识别等权 RRF 参照运行。
- 参照运行不作为普通历史条目显示。
- 参照运行可直接查看，但不计入比较选择数量、不生成独立比较行。
- 比较加权 RRF 方案时，若对应参照运行可用，可作为单独基线返回并在比较图中作为参考。
- 参照结果来自不同 `plan_id/version` 属于 `ReferenceVariant` 明确定义的基线例外，不得放宽普通选中记录的同方案版本限制。

## 3. API

### 3.1 路由

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/v1/runs` | 有效历史摘要、不可用记录和来源 |
| `GET` | `/api/v1/runs/{run_id}` | 单运行完整记录、来源和图表可用性 |
| `POST` | `/api/v1/runs/compare` | 校验选择并返回同方案比较数据 |
| `GET` | `/api/v1/runs/compare/chart?runs=id1,id2` | 按选择在内存生成 PNG |
| `GET` | `/api/v1/runs/{run_id}/charts/{chart_index}` | 返回该记录第 `chart_index` 个安全图表，0 起始 |

固定路径必须先于 `{run_id}` 动态路径注册，避免 `compare` 被当作 Run ID。

### 3.2 历史列表

`GET /api/v1/runs` 顶层至少返回：

```json
{
  "records": [
    {
      "run_id": "...",
      "source": "runs",
      "plan_id": "...",
      "plan_version": "v1",
      "variant_id": "...",
      "plan_name": "...",
      "variant_name": "...",
      "status": "Completed",
      "started_at": "...",
      "finished_at": "...",
      "metrics": {"P@1": 0.5, "MRR": 0.7},
      "comparison_eligible": true
    }
  ],
  "unavailable": [
    {
      "run_id": "...",
      "source": "imports",
      "code": "RUN_RECORD_INVALID",
      "message": "运行记录无效"
    }
  ]
}
```

- `records` 不包含等权 RRF 参照运行。
- `unavailable` 不包含绝对路径和技术堆栈。
- `metrics` 可为 `null`，不得补零或伪造。
- 未知但可合法读取的导入记录仍可出现在历史中，`comparison_eligible=false`。

### 3.3 单运行

`GET /api/v1/runs/{run_id}` 返回：

```json
{
  "run": {"format_version": "1.0", "...": "原样记录字段"},
  "source": "presets",
  "known_plan": true,
  "comparison_eligible": true,
  "charts": [
    {
      "index": 0,
      "id": "metrics",
      "title": "指标",
      "available": true,
      "url": "/api/v1/runs/<run_id>/charts/0"
    }
  ]
}
```

- `run` 是符合 Schema 的记录视图，不得插入来源字段或修改原文件。
- 未知方案或变体显示原始 ID，不伪造名称，不参与比较。
- 非 Completed 状态返回该状态下已有字段，缺失指标保持 `null`。
- 图表缺失时 `available=false`，不返回可读取 URL。

### 3.4 比较请求

`POST /api/v1/runs/compare` 请求体：

```json
{"run_ids": ["run-a", "run-b"]}
```

规则：

- 至少 2 个，去重后仍至少 2 个。
- 所有选中记录必须存在、可读且不处于 Run ID 冲突状态。
- 所有选中记录的 `plan_id` 和 `plan_version` 必须相同。
- 选中记录必须是当前方案目录已知的复现变体。
- 选中记录必须为 `Completed` 且 `metrics` 非空。
- 等权 RRF 参照运行不得出现在 `run_ids` 中；应作为自动基线。
- 不自动补选记录，不按变体去重。
- 同一变体的多次运行作为独立行。
- 结果保持请求中的 Run ID 顺序。

比较响应至少包含：

- 方案 ID、方案版本。
- 每条选中记录的 Run ID、来源、变体 ID/名称、指标、配置和环境。
- `metric_columns`：按指标名称和 K 稳定排序的并集。
- `rows`：每条记录按列返回数值或 `null`，并列出不可比较原因。
- `config_differences`：仅返回不同配置；键路径稳定，比较保留 JSON 类型。
- `environment_differences`：仅返回不同环境；不得推断因果。
- `baseline`：可用时为参照运行摘要和指标，否则为 `null`。
- `chart_url`：带 Run ID 的图表地址。

缺失指标只能返回 `null` 和“不可比较”，不得写 0。

### 3.5 比较图

- `GET /api/v1/runs/compare/chart?runs=id1,id2` 使用与 POST 相同的选择和校验规则。
- 只允许已完成且有指标的选择。
- 返回 `image/png`，文件头和可解码性必须有效。
- 图表按所选记录分组展示可对齐指标；有 RRF 参照时显示为基线。
- 全程使用内存缓冲，不创建临时 PNG、不写入结果目录、不修改 JSON。
- 无可对齐指标时返回明确 422，不生成空图。

### 3.6 单运行图表

- `chart_index` 是记录 `charts` 数组中的位置，不接收客户端文件路径。
- 只有解析后仍位于对应运行目录且文件可读时返回 `image/png`。
- 缺失、越界、符号链接逃逸或不可读均不返回文件内容。

### 3.7 错误

| HTTP | `code` | 场景 |
| --- | --- | --- |
| `404` | `RUN_NOT_FOUND` | 三类来源均不存在该 Run ID |
| `409` | `RUN_ID_CONFLICT` | 同一 Run ID 出现在多个来源 |
| `409` | `RUN_UNAVAILABLE` | `run.json` 缺失、损坏或目录 ID 不一致 |
| `404` | `CHART_NOT_FOUND` | 图表索引不存在 |
| `404` | `CHART_UNAVAILABLE` | 图表文件缺失或不可读 |
| `409` | `CHART_UNSAFE` | 图表路径或符号链接越界 |
| `422` | `COMPARE_SELECTION_INVALID` | 数量、重复、方案版本或记录资格不合法 |
| `422` | `COMPARE_NO_METRICS` | 无共同可对齐指标 |

错误沿用 T-006 统一结构。`POST /api/v1/runs/compare` 必须校验 CSRF；只读 GET 图表接口不使用 CSRF。

## 4. 页面

### 4.1 结果页 `/results/{run_id}`

按以下顺序展示：

1. 方案、变体、状态、来源、Run ID、开始/结束时间和非完成状态错误。
2. 指标表；只显示记录中的聚合指标。
3. 14 项耗时表；`null` 显示“不适用”，适用零值显示 `0 ms`。
4. 图表；只显示该记录中可用产物，缺失项显示“图表不可用”。
5. 配置与环境，可折叠。

耗时展示补充规则：

- 以毫秒显示，同时保留记录中的秒值口径。
- `corpus_encode_seconds=0.0` 和 `query_encode_seconds=0.0` 标注缓存命中语义。
- 索引构建父项及子项采用层级分组，不做无法解释的重复求和。
- `retrieval_mean_seconds` 明确标注“不包含查询编码”。

不得展示 query 级检索结果、错误案例或实时日志。

### 4.2 历史页 `/history`

- 展示三类来源统一列表，并明确来源标签。
- 展示方案名称、变体名称、方案版本、时间、状态、Run ID 和代表性指标。
- 等权 RRF 参照运行不进入普通历史列表。
- 损坏或冲突记录显示在“不可用记录”区域，不提供详情读取。
- 只有有比较资格的记录可勾选。
- 页面交互阻止不同方案版本混选；服务端仍必须重复校验。
- 空目录显示明确空状态，不显示虚假示例记录。
- 监听 `records.changed`，事件到达后从 `/api/v1/runs` 重新加载，不依赖浏览器本地演练数据。

### 4.3 比较页 `/compare?runs=id1,id2`

- 无选择、选择不足或组合非法时显示明确错误和返回历史页入口。
- 展示每条记录作为独立变体运行行。
- 指标缺失使用“不可比较”。
- 相同配置隐藏，不同配置突出显示；环境差异单独分组。
- 展示内存生成的比较图。
- 页面和 API 均不得提供删除按钮或删除接口。

## 5. SSE

- 结果集合新增、删除、损坏状态变化时发送 `records.changed`。
- 事件载荷只包含一个无敏感信息的刷新提示，不需要把全部历史塞入 SSE。
- 结果集合未变化时不得持续发送 `records.changed`。
- 外部移动或删除运行目录后，下一次轮询应能检测变化。
- 现有 `snapshot`、`task.updated`、`queue.updated` 和心跳行为保持不变。
