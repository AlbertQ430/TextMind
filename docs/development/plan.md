## 1. 计划原则

- 一次只激活一个开发任务，DSH 不为未激活任务提前写实现。
- 任务文件只在该任务成为当前执行任务前创建为“准备”状态。
- 每个任务完成后由 Codex 运行验收；通过后创建并激活下一个任务。
- 数据结构、任务状态和结果发布等底层契约先于 UI 实现。
- 不在一个任务中混合多个独立模块，避免返工时牵涉过大。
- 所有任务都必须映射到至少一条 SRS 验收标准。

## 2. 里程碑

- T-001 工程骨架、依赖和环境检查。

完成标准：可通过服务层提交、排队、运行、取消和恢复任务，并可靠生成终态 JSON。

完成标准：用户可通过本机 Web UI 完成 MVP 主流程。

### M3 资源、局域网与交付

- T-009 设置、资源检查、预置结果构建和发布资产。

完成标准：SRS 的 36 条验收标准具备完整实现证据。

## 7. 阶段验收门

每个任务进入“完成”前，Codex 必须：

1. 复核任务差异只涉及允许范围。
2. 复跑 DSH 报告的测试。
3. 运行适用的静态检查、编译或构建。
4. 核对 SRS/SDS 和任务接口一致。
5. 在任务文件写入具体验收证据。
6. 更新本计划、任务索引和当前执行任务。

## 8. 变更规则

- 任务依赖变化时，先更新本计划。
- 接口变化时，先更新任务文件和 SDS 或形成明确接口补充。
- 新增任务不得静默插入；必须分配新的 T-ID 并说明依赖与验收。
- 接口稳定前不创建高度细节化的后续任务文件。
