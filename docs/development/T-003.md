## 1. 任务定义

从现有 CLI 和检索核心中抽取可复用的单变体执行器，使 BM25、Dense 和 Hybrid 使用统一的数据加载、阶段报告、边界取消、指标评价和精确耗时口径，并向后续任务返回可组装的执行结果。

## 2. 接口契约

### 2.1 阶段

生命周期阶段按顺序固定为：

1. `prepare`
2. `load_dataset`
3. `load_model`
4. `build_index`
5. `encode_queries`
6. `retrieve`
7. `evaluate`

阶段定义包含名称、中文显示名和对当前方法是否适用。BM25 的 `load_model`、`encode_queries` 不适用；Dense 不包含 BM25 子阶段；Hybrid 包含适用的全部阶段。

### 2.2 阶段回调

```python
def report_stage(event: StageEvent) -> None: ...
```

`StageEvent` 至少包含：

- `stage`
- `event`：`started` / `completed` / `skipped`
- `timestamp`：带时区时间

执行器必须在每个适用阶段开始和结束、以及跳过阶段时调用回调。回调失败不得静默吞掉。

### 2.3 取消令牌

```python
class CancellationToken(Protocol):
    def raise_if_cancelled(self, stage: str) -> None: ...
```

- 每个阶段开始前和结束后调用。
- 取消在阶段边界生效。
- 不终止线程或子进程。
- 当前不可中断操作完成后才进入下一检查点。
- 提供 `NeverCancel` 默认实现供 CLI 和测试使用。

### 2.4 执行接口

```python
class ExperimentExecutor:
    def execute(
        self,
        plan: PlanDefinition,
        variant: RunVariant,
        report_stage: Callable[[StageEvent], None],
        cancellation: CancellationToken,
    ) -> ExecutionResult: ...
```

`ExecutionResult` 至少包含：

- `dataset`
- `variant_config`
- `metrics`
- `num_queries`
- `num_skipped`
- `timing`
- `environment`
- `stage_progress`

`ExecutionResult` 不包含 Run ID、运行状态、图表或结果来源，由后续任务负责组装。

### 2.5 依赖注入

为支持无真实模型的测试，执行器必须允许注入：

- `model_loader(model_spec, device) -> Encoder`
- `dataset_loader(plan) -> RetrievalDataset`
- `device_resolver() -> str`

默认实现可使用 SentenceTransformer 和现有数据集加载器，但 FakeEncoder 测试不得触发真实模型或网络。

## 3. 计时契约

### 3.1 固定字段

必须输出 T-002 定义的全部字段：

- `dataset_load_seconds`
- `model_load_seconds`
- `index_build_seconds`
- `doc_cache_load_seconds`
- `corpus_encode_seconds`
- `query_cache_load_seconds`
- `query_encode_seconds`
- `bm25_search_total_seconds`
- `dense_search_total_seconds`
- `rrf_fusion_seconds`
- `retrieval_total_seconds`
- `retrieval_mean_seconds`
- `retrieval_median_seconds`
- `evaluation_seconds`

字段值为非负数字或 `null`。`0.0` 只表示适用阶段缓存命中或实际耗时可忽略；不适用必须为 `null`。

### 3.2 精确计时点

- 数据集：加载器调用到引用完整性校验完成。
- 模型：模型构造前到加载完成。
- 总索引：`retriever.fit()` 前后。
- 文档缓存：`DenseRetriever.fit()` 内部缓存读取段。
- 语料编码：仅缓存未命中时 `_encode(texts)`。
- 查询缓存：`DenseRetriever.encode_queries()` 内部缓存读取段。
- 查询编码：仅缓存未命中时 `_encode(queries)`。
- BM25 检索：逐查询 `BM25Retriever.search()`。
- Dense 检索：逐查询 `DenseRetriever.search_vector()`。
- RRF：逐查询 `HybridRetriever.rrf_fuse()`。
- 评价：`evaluate()` 前后。

### 3.3 聚合约束

- Dense 查询缓存加载不得计入查询编码。
- 查询缓存命中时 `query_encode_seconds=0.0`。
- BM25 的模型与编码字段为 `null`。
- Hybrid 检索总耗时等于逐查询 BM25、Dense、RRF 耗时之和。
- `retrieval_mean_seconds` 和 `retrieval_median_seconds` 基于逐查询端到端检索耗时，不含查询编码。
- `index_build_seconds` 是父级耗时，不能与缓存/编码子项再次累加。

Hybrid 汇总必须满足：

```text
retrieval_total_seconds
≈ bm25_search_total_seconds
 + dense_search_total_seconds
 + rrf_fusion_seconds
```

#### 接口实现

- `StageEvent(stage, event, timestamp)`：校验阶段名、事件类型和时区；执行器在每个适用阶段开始/结束、不适用阶段跳过时调用回调；回调异常直接传播，不静默吞掉。
- 阶段顺序固定为 `prepare → load_dataset → load_model → build_index → encode_queries → retrieve → evaluate`；BM25 的 `load_model`、`encode_queries` 报告为 `skipped` 并写入 `not_applicable`。
- `CancellationToken.raise_if_cancelled(stage)` 在每阶段开始前和结束后各调用一次；`RunCancelled` 携带取消阶段和已完成阶段；取消不终止线程，已在阶段边界的检查点生效。
- `ExperimentExecutor.execute(plan, variant, report_stage, cancellation=None) -> ExecutionResult`：只执行传入的单个变体；结果含 `dataset`、`variant_config`、`metrics`、`num_queries`、`num_skipped`、`timing`、`environment`、`stage_progress`，不含 Run ID、状态、图表或来源字段。
- 依赖注入：`model_loader(model_spec, device)`、`dataset_loader(plan)`、`device_resolver()`；默认实现分别为 SentenceTransformer 加载、本地 SciFact/DuRetrieval 加载、`auto → mps/cuda/cpu` 解析。FakeEncoder 测试不触发真实模型或网络。
- 计时口径：
  - BM25：`model_load_seconds`、`doc_cache_*`、`corpus_encode_seconds`、`query_cache_*`、`query_encode_seconds`、`dense_search_total_seconds`、`rrf_fusion_seconds` 均为 `null`。
  - Dense：`doc_cache_load_seconds`/`corpus_encode_seconds` 取 `DenseRetriever.fit` 内部计时；`query_cache_load_seconds`/`query_encode_seconds` 取 `encode_queries` 内部计时；缓存命中时对应编码字段为 `0.0`。
  - Hybrid：先批量编码查询，再逐查询执行 BM25 检索、Dense 向量检索和 `rrf_fuse`，三段耗时分别累计并保证 `retrieval_total_seconds` 等于三子项之和；查询编码不计入检索耗时。
  - `retrieval_mean_seconds`/`retrieval_median_seconds` 基于逐查询端到端耗时；`index_build_seconds` 为父级，不与缓存/编码子项重复累加。
- 环境信息：只输出 `os`、`os_version`、`platform`、`python`、`cpu_arch`、`cpu_model`、`device`、`gpu` 与 6 个依赖版本；不含主机名、用户名、IP、当前工作目录或模型绝对路径。
- CLI：参数、校验、打印格式保持不变；结果 JSON 沿用旧字段名（`load_seconds`、`index_seconds`、`vector_search_total_seconds`、`search_*` 等）。CLI 将自由参数包装为临时 `PlanDefinition`/`RunVariant`（`preset` 字段为占位值），不写运行记录。
- 实现说明：Hybrid 执行未调用 `HybridRetriever.search_batch`，而是复用同一 `rrf_fuse` 与子检索器逐查询执行，以便把查询编码与检索计时分离；未复制融合算法。
