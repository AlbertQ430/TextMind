## 1. 任务定义

### 1.1 目标

建立冻结的运行时方案目录，并通过 JSON Schema 与 Pydantic 模型固定方案配置和单变体运行记录的结构、边界与兼容版本，为执行器、任务队列、结果仓库和 Web 层提供共同契约。

### 1.2 范围

包含：

- 3 个方案、`v1` 版本和 17 个唯一变体。
- SciFact 与 DuRetrieval 数据集定义。
- BM25、Dense、Hybrid 条件配置。
- 预置结果 ID 与现有结果来源映射。
- RRF 等权参照项。
- `plan_catalog.schema.json`。
- `run_record.schema.json`。
- Pydantic 方案模型和运行记录模型。
- 配置与记录边界校验及单元测试。

不包含：

- 数据集或模型加载。
- 实验执行和检索调用。
- SQLite、任务队列或结果文件写入。
- 预置结果转换。
- 页面、API、LAN 或图表生成。

### 1.3 允许修改

## 2. 方案目录契约

### 2.1 方案与变体标识

`config/plans.json` 必须包含：

| 方案 ID | 版本 | 数据集划分 | 唯一变体数 |
| --- | --- | --- | ---: |
| `scifact-comparison` | `v1` | SciFact test | 9 |
| `duretrieval-comparison` | `v1` | DuRetrieval dev | 4 |
| `duretrieval-rrf-weight-sweep` | `v1` | DuRetrieval dev | 4 个运行变体 + 1 个参照项 |

17 个唯一变体 ID 必须与 [SRS §2.4](../requirements/SRS.md) 完全一致。方案内可按展示顺序保存变体，但测试必须按集合校验，不能依赖文件顺序。

### 2.2 公共字段

方案目录顶层：

- `schema_version=1`
- `plans`

方案：

- `plan_id`
- `plan_version`
- `name`
- `description`
- `dataset`
- `evaluation`
- `variants`

数据集：

- `name`
- `language`
- `split`

评价：

- `top_k=100`
- `k_values=[1,5,10,100]`

运行变体：

- `variant_id`
- `name`
- `kind="run"`
- `method`
- `preset_run_id`
- `preset_source`
- 方法相关配置

参照项：

- `variant_id`
- `name`
- `kind="reference"`
- `source_plan_id`
- `source_plan_version`
- `source_variant_id`

### 2.3 方法配置

BM25：

- `k1=1.2`
- `b=0.75`
- `tokenizer="simple"` 或 `"jieba"`

Dense：

- `model.name`
- `model.directory_name`
- `model.revision`，允许为 `null`，已有预置结果应保留原 revision
- `query_prefix`
- `batch_size=32`
- `normalize_embeddings=true`

Hybrid：

- 包含 Dense 与 BM25 配置
- `rrf_k=60`
- `rrf_weights` 长度为 2
- 权重有限、非负且不能全为 0

查询前缀必须保存完整字符串，不得只保存显示标签：

- Qwen3：`Instruct: Given a web search query, retrieve relevant passages that answer the query\nQuery:`；其中 `\n` 必须解析为真实换行字符。
- SciFact BGE-M3：`Represent this sentence for searching relevant passages: `；必须保留末尾空格。
- DuRetrieval bge-small：`为这个句子生成表示以用于检索相关文章：`

### 2.4 稳定预置标识

- `preset_run_id` 使用 `preset-<variant_id>`。
- `preset_source` 指向现有 `data/evaluation/*.json`。
- 同一 `preset_run_id` 和 `preset_source` 在全部方案中必须唯一，等权 Hybrid 参照除外。
- 等权 Hybrid 参照只复用 `duretrieval-hybrid-bge-small-prefix-equal`，不生成第二条来源记录。

### 2.5 加载接口

```python
def load_plan_catalog(path: Path | str | None = None) -> PlanCatalog: ...
```

- 默认读取项目 `config/plans.json`。
- 返回不可变方案定义。
- 配置无效时抛出包含字段路径的 `PlanCatalogError`。
- 不加载数据集、模型或预置结果文件。

## 3. 运行记录契约

### 3.1 模型接口

```python
class RunRecord(BaseModel): ...

def parse_run_record(data: dict) -> RunRecord: ...
```

要求：

- Pydantic v2。
- 生成记录使用 `extra="forbid"`。
- `format_version` 固定为 `"1.0"`。
- 状态只允许 `Completed`、`Failed`、`Cancelled`、`Interrupted`。
- 时间使用带时区的 ISO 8601；解析后必须含时区。
- `run_id` 匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`。
- `plan_version` 必须非空。
- 不包含 `source`、`result_source`、`import_time` 或等价来源/导入时间字段。

### 3.2 必需语义

记录包含：

- 格式版本、运行 ID、方案 ID 与版本、变体 ID。
- 方案和变体名称快照。
- 状态、阶段进度、开始和结束时间。
- 数据集标识、划分、规模和查询数量。
- 完整变体配置。
- 指标、查询覆盖和分阶段耗时。
- 运行环境。
- 图表相对路径列表。
- 失败、取消或中断错误信息。

### 3.3 终态约束

- `Completed` 必须包含 `metrics`、`num_queries`、`num_skipped`。
- `Failed`、`Cancelled`、`Interrupted` 必须包含 `error`。
- `Completed` 的 `error` 必须为 `null`。
- 未知指标不得补零；缺少适用指标字段可以省略。
- `charts` 可为空；每个路径必须是记录目录内的 POSIX 相对路径，不得为绝对路径、`..`、空字符串或包含反斜杠。

### 3.4 计时字段

`TimingRecord` 至少包含以下键；不适用时为 `null`：

- `dataset_load_seconds`
- `model_load_seconds`
- `index_build_seconds`
- `doc_cache_load_seconds`
- `corpus_encode_seconds`
- `query_cache_load_seconds`
- `query_encode_seconds`
- `bm25_search_total_seconds`
- `dense_search_total_seconds`
- `rrf_fusion_seconds`
- `retrieval_total_seconds`
- `retrieval_mean_seconds`
- `retrieval_median_seconds`
- `evaluation_seconds`

所有数值必须非负。BM25、Dense、Hybrid 的条件约束在后续执行器任务中验证；本任务只固定字段和基础类型。

### 3.5 JSON Schema

- `plan_catalog.schema.json` 使用 JSON Schema Draft 2020-12。
- `run_record.schema.json` 使用 JSON Schema Draft 2020-12。
- Schema 与 Pydantic 字段、枚举、约束保持一致。
- Schema 本身必须能通过 `Draft202012Validator.check_schema`。

## 4. 实现约束

#### 接口实现

- `load_plan_catalog(path=None) -> PlanCatalog`：默认读取 `config/plans.json`；先按 `plan_catalog.schema.json` 校验，再由 Pydantic 做跨字段校验；任何失败抛出 `PlanCatalogError`，消息含 `$.plans[0].variants[1].model` 形式的字段路径；不加载数据集、模型或预置结果文件。
- 方案目录交叉校验：方案 ID/版本唯一且必须为 3 个冻结方案 `v1`；17 个唯一运行变体集合与 SRS §2.4 一致；方案内变体 ID 唯一；`preset_run_id == "preset-<variant_id>"` 且全局唯一；`preset_source` 全局唯一；`top_k >= max(k_values)`；BM25 `k1 >= 0`、`b ∈ [0,1]`；`rrf_weights` 长度为 2、有限非负且不全为 0；参照项来源方案/版本/变体必须存在且复用同 ID。
- 变体模型按 `method` 强制条件字段：BM25 必须有 `k1/b/tokenizer` 且禁止模型字段；Dense 必须有 `model/query_prefix/batch_size/normalize_embeddings`；Hybrid 必须同时包含两组字段和 `rrf_k/rrf_weights`。
- 前缀以完整字符串保存：Qwen3 Instruct 含真实换行（JSON `\n`）；BGE-M3 前缀保留末尾空格；bge-small 中文前缀保留全角冒号。
- `RunRecord`：`format_version` 固定 `"1.0"`；`run_id` 匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`；状态限定四种；时间使用 `AwareDatetime`（缺时区拒绝）；`extra="forbid"`，因此 `source`、`result_source`、`import_time` 等字段被拒绝。
- 终态约束：`Completed` 必须有 `metrics/num_queries/num_skipped` 且 `error` 为 `null`；`Failed/Cancelled/Interrupted` 必须有 `error`。

- `parse_run_record(data)`：非对象直接拒绝；先 JSON Schema（含 `FormatChecker`），再 Pydantic；错误消息含 `$.charts[0].path` 形式的路径。

  - 参照项 `variant_id` 必须与 `source_variant_id` 相同，落实 SRS“复用同 ID 预置结果、不复制运行 ID”。

#### 接口实现

- 逐方案集合校验：每个方案的运行变体 ID 集合必须精确等于 `EXPECTED_PLAN_VARIANTS[plan_id]`，参照项集合必须精确等于 `EXPECTED_REFERENCE_VARIANTS[plan_id]`（`scifact-comparison`、`duretrieval-comparison` 为空，`duretrieval-rrf-weight-sweep` 仅含等权参照）。错误消息列出缺少与多出的变体。
- `Completed` 终态：`metrics` 非空对象、`num_queries`/`num_skipped` 为整数、`error` 为 `null`；Pydantic 与 Schema 双重执行。
- `Cancelled` 终态：`cancelled_at` 必须为带时区的日期时间；缺失或 `null` 均拒绝。
- 时间约束：Schema 的 `dateTime` 同时使用 `format: date-time` 与时区正则，不依赖可选 `rfc3339-validator` 即可独立拒绝无时区值；Pydantic 仍用 `AwareDatetime`。
- 图表路径：Schema 的 `not.anyOf` 覆盖绝对路径、反斜杠、`..`、`.`、双斜杠、尾斜杠、盘符和纯空白；Pydantic 使用相同规则的分段检查。两层对同一非法输入给出相同拒绝结果。
