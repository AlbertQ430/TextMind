## 1. 任务定义

### 1.1 目标

在本地历史页提供单份 JSON 导入。导入必须限制大小、拒绝重复键和无效 Schema，按 Run ID 检查三类结果目录中的冲突，将原始 JSON 字节原子发布到 `results/imports/<run_id>/run.json`，并保持原始时间、配置和环境不变。

### 1.2 范围

包含：

- 单文件 JSON 导入服务和原子目录发布。
- 文件大小、扩展名、UTF-8、严格 JSON 和重复键校验。
- 格式版本、Run ID 和运行记录 Schema 校验。
- 三类来源中的重复 Run ID 检查。
- 未知方案/变体的只读导入。
- 图表相对路径安全校验和缺失提示。
- 历史页导入控件、错误提示和 `records.changed` 刷新。
- `results/README.md` 文件管理说明。

不包含：

- 批量导入、多记录导入、导出或记录删除。
- 局域网导入权限；T-010 负责限制 LAN 客户端。
- 修改 JSON 内容、补写来源/导入时间或生成侧车文件。
- 上传或 ZIP 解包附属图表。
- 自动扫描用户磁盘寻找原始图表文件。

### 1.3 单文件与图表边界

浏览器只上传单份 JSON，本应用不会获知或访问上传者原始目录。因此：

- 本任务的“可用附属图表”数量为 0，系统不尝试根据 JSON 相对路径读取客户端原机文件。
- JSON 中的安全相对图表路径原样保留，导入成功后逐项提示“图表未随 JSON 导入，当前不可用”。
- 用户之后可以自行把图表复制到对应 `results/imports/<run_id>/charts/`；结果页每次读取时重新检测，T-007 的目录边界和可读性规则继续生效。
- 这不改变 JSON Schema，也不阻止缺失图表的有效记录导入。

该边界与已确认的“单独移动一份 JSON 由用户负责、缺失图表代价可接受”一致。

## 2. 导入服务

### 2.1 输入

```python
ImportService.import_json(
    filename: str | None,
    content: bytes,
) -> ImportResult
```

- `filename` 只用于确认 `.json` 扩展名，不作为服务器路径。
- 上限固定为 `5 * 1024 * 1024` 字节（5 MiB）；超过上限拒绝。
- 必须拒绝多文件请求、空文件和错误扩展名。
- 服务不得将上传内容写到结果目录之外。

### 2.2 顺序

1. 检查文件数量、大小和扩展名。
2. 严格按 UTF-8 解码。
3. 使用拒绝重复键的 JSON 解析器；检测所有嵌套对象。
4. 拒绝 `NaN`、`Infinity` 等非标准 JSON 常量。
5. 要求顶层为对象，读取并检查 `format_version == "1.0"`。
6. 解析 Run ID，并检查 `presets`、`runs`、`imports` 中是否已有同名目录；冲突在写入前拒绝。
7. 使用现有 `parse_run_record()` 执行完整 Schema 校验。
8. 在 `results/imports/.tmp-*` 创建独占暂存目录。
9. 将原始 `content` 字节原样写为暂存目录的 `run.json`，不得重新序列化或换行转换。
10. 写入成功后再次确认目标目录不存在。
11. 通过目录重命名原子发布为 `results/imports/<run_id>`。
12. 返回成功结果和缺失图表提示。

失败时必须删除本次创建的暂存目录，不得留下部分导入。已有导入目录不得被覆盖。

### 2.3 重复键

- 任意层级对象出现重复键均拒绝，不使用“最后一个值覆盖前值”的行为。
- 错误只返回重复键名和简短说明，不返回绝对路径或原始 JSON。

### 2.4 路径

- 继续使用 `RunRecord` 的图表相对路径约束：拒绝绝对路径、盘符、反斜杠、空段、`.` 和 `..`。
- 导入阶段不拼接或读取任何用户源磁盘路径。
- 发布后解析图表文件时仍必须限制在 `results/imports/<run_id>` 内，符号链接逃逸不可读取。
- 不安全路径使整份导入失败，不允许跳过非法图表后接受记录。

### 2.5 成功结果

```json
{
  "run_id": "...",
  "source": "imports",
  "record_url": "/results/...",
  "bytes_written": 1234,
  "charts_imported": 0,
  "missing_charts": [
    {"id": "metrics", "title": "指标"}
  ],
  "warnings": [
    "图表 metrics 未随 JSON 导入，当前不可用"
  ]
}
```

- 不返回服务器绝对路径。
- 不向 `run.json` 增加任何管理字段。
- 导入后的记录通过现有 `ResultCatalog` 读取，来源为 `imports`。

### 2.6 错误

| HTTP | `code` | 场景 |
| --- | --- | --- |
| `422` | `IMPORT_FILE_REQUIRED` | 没有文件或文件数量不是 1 |
| `422` | `IMPORT_FILE_INVALID` | 空文件或非 `.json` 文件名 |
| `413` | `IMPORT_TOO_LARGE` | 超过 5 MiB |
| `422` | `IMPORT_INVALID_ENCODING` | 非 UTF-8 |
| `422` | `IMPORT_DUPLICATE_KEY` | 任意层级重复键 |
| `422` | `IMPORT_INVALID_JSON` | JSON 语法或非标准常量错误 |
| `422` | `IMPORT_VERSION_UNSUPPORTED` | `format_version` 不兼容 |
| `422` | `IMPORT_SCHEMA_INVALID` | 字段、类型、状态或核心数据不符合 Schema |
| `422` | `IMPORT_PATH_INVALID` | 图表路径非法或越界 |
| `409` | `IMPORT_RUN_ID_CONFLICT` | 三类目录中已存在同名 Run ID |
| `500` | `IMPORT_WRITE_FAILED` | 暂存或原子发布失败，已清理暂存 |

错误沿用统一结构；必要时在 `details` 返回字段级摘要，但不能返回绝对路径、上传临时路径或原始 JSON 全文。

## 3. Web API

### 3.1 路由

```text
POST /api/v1/imports
Content-Type: multipart/form-data
字段：file（必须恰好一个）
```

- 必须通过本机会话和 CSRF 校验。
- 请求体和响应为 `Cache-Control: no-store`。
- 只允许 Local App 使用；LAN 权限在 T-010 强制。
- 不接受批量字段、目录上传或额外路径参数。

### 3.2 页面

历史页新增“导入单个 JSON”面板：

- 文件选择器只接受 `.json`。
- 提交时使用 `FormData` 和 `X-CSRF-Token`。
- 不在前端修改 JSON 或推测 Run ID。
- 提交按钮防重复点击。
- 成功时显示 Run ID、缺失图表数量和警告。
- 失败时显示后端错误摘要和处理建议。
- 成功后清空文件选择并重新加载历史。
- 不提供导出或删除按钮。

#### 接口实现

- 导入顺序：文件数量（路由）→ 扩展名 → 大小（>5 MiB → 413）→ UTF-8 严格解码 → 拒绝重复键与 `NaN`/`Infinity` → 顶层对象与 `format_version=1.0` → Run ID 格式 → 图表路径安全 → 三类目录冲突 → `parse_run_record()` → 暂存目录写入原始字节并 `fsync` → 再次确认目标不存在 → `os.rename` 原子发布。
- 重复键：`json.loads(object_pairs_hook=...)` 检测所有嵌套对象，返回 `IMPORT_DUPLICATE_KEY` 与重复键名。
- 非标准常量：`parse_constant` 拒绝 `NaN`/`Infinity`，返回 `IMPORT_INVALID_JSON`。
- 冲突：检查 `presets`、`runs`、`imports` 下同名目录（目录存在或符号链接即冲突，包括损坏/不可用目录），写入前和发布前各检查一次；返回 409 `IMPORT_RUN_ID_CONFLICT`，不覆盖已有目录。
- 原子性：每次导入创建独占 `.tmp-<hex>` 目录，失败时删除；成功后目录重命名为最终目录，历史扫描跳过隐藏暂存目录。
- 图表：沿用 `RunRecord` 相对路径约束并显式检查绝对路径、盘符、反斜杠、空段、`.`、`..`；非法路径整份导入失败（`IMPORT_PATH_INVALID`）。缺失图表不阻止导入，返回 `missing_charts`、`warnings` 与 `charts_imported=0`。
- 未知方案/变体：Schema 合法即可导入，历史中只读展示且 `comparison_eligible=false`（沿用 T-007 规则）。
- 接口：`POST /api/v1/imports` 使用 `multipart/form-data` 字段 `file`，必须恰好一个文件；必须通过 CSRF；响应 201 与统一错误结构，`Cache-Control: no-store`。所有上传对象在 `finally` 中关闭，避免临时文件泄漏。
- 页面：历史页“导入单个 JSON”面板，文件选择器 `accept=".json,application/json"`；JS 使用 `FormData` 和 `X-CSRF-Token` 提交，按钮防重复点击；成功显示 Run ID、字节数、缺失图表数与警告，清空文件并重新加载历史；失败显示后端错误摘要。无导出或删除入口。

#### 实现摘要

按 R1 返工要求修复 4 类边界：

1. 图表路径拒绝所有 ASCII 控制字符（含 NUL）；`ResultCatalog.chart_file()` 防御性捕获路径解析的 `ValueError`/`OSError` 并映射为 `CHART_UNSAFE`/`CHART_UNAVAILABLE`，`_is_readable()` 同时捕获 `ValueError`，已有畸形记录不再导致 500。

3. JSON 解析与 Schema 校验的 `RecursionError` 分别转换为 422 `IMPORT_INVALID_JSON` / `IMPORT_SCHEMA_INVALID`，深层嵌套不再冒泡为 500。
4. `ImportService` 增加实例级互斥锁，冲突检查、Schema 校验和发布串行执行；`os.rename` 的 `EEXIST`/`ENOTEMPTY`/`EISDIR`/`ENOTDIR` 映射为 409 `IMPORT_RUN_ID_CONFLICT`，第二个并发导入不返回 500、不覆盖、不残留暂存。

#### 接口实现

- `unsafe_chart_path()`：在空路径检查后拒绝 `ord(ch) < 32` 或 `== 127` 的任意字符（NUL、换行、制表符等）。
- `chart_file()`：`Path(raw)`、`resolve()` 与文件检查包在 `try/except (ValueError, OSError)` 中；解析失败 → `ChartUnsafe`，文件访问失败 → `ChartUnavailable`；`chart_available()` 返回 `False`，结果页显示“图表不可用”，API 返回 409/404 而非 500。
- 非有限浮点：`json.loads(parse_float=_finite_float)`，`math.isfinite` 失败抛 `_InvalidConstant` → `IMPORT_INVALID_JSON`。
- 深层嵌套：`json.loads` 的 `RecursionError` → `IMPORT_INVALID_JSON`；`parse_run_record` 的 `RecursionError` → `IMPORT_SCHEMA_INVALID`。
- 并发：`ImportService._lock` 包裹“冲突检查 + Schema 校验 + 发布”；`_publish` 的 `os.rename` 对 `EEXIST`/`ENOTEMPTY`/`EISDIR`/`ENOTDIR` 映射 409；`finally` 清理暂存目录。
- 兼容：成功路径、字节一致性、原子发布和错误码契约保持不变。
