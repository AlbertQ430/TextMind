## 1. 任务定义

### 1.1 目标

实现单实例、单工作线程的后端任务系统：持久化等待任务、执行状态、阶段进度、取消请求、正常关闭清队列、启动恢复和队列取消提示，并通过终态发布接口与结果 JSON 发布解耦。

### 1.2 范围

包含：

- SQLite 任务表与 notices 表。
- 任务模型、状态枚举和合法状态转换。
- 单工作线程和 FIFO 队列。

- 等待任务取消、运行任务阶段边界取消。

- 异常重启删除遗留 Pending、生成队列取消提示并将活跃任务交给恢复流程。

## 2. 数据模型

### 2.1 任务状态

```python
class TaskStatus(StrEnum):
    PENDING = "Pending"
    PREPARING = "Preparing"
    RUNNING = "Running"
    CANCELLING = "Cancelling"
    COMPLETED = "Completed"
    FAILED = "Failed"
    CANCELLED = "Cancelled"
    INTERRUPTED = "Interrupted"
```

允许转换：

```text
Pending -> Preparing -> Running -> Completed
Pending -> deleted
Preparing/Running -> Failed
Preparing/Running -> Cancelling -> Cancelled
Preparing/Running/Cancelling -> Failed（取消期间执行器抛普通异常时）
Preparing/Running/Cancelling -> Interrupted
```

非法转换抛出明确错误，不得静默覆盖。

### 2.2 `TaskRecord`

至少包含：

- `run_id`
- `plan_id`
- `plan_version`
- `variant_id`
- `status`
- `current_stage`
- `completed_stages`
- `submitted_at`
- `started_at`
- `ended_at`
- `cancel_requested`
- `config_snapshot`
- `error_summary`

`run_id` 使用 UTC 时间和随机后缀生成，匹配 T-002 的 Run ID 规则。

### 2.3 SQLite

- 数据库默认 `data/app/textmind.db`。
- 启用 WAL 和 foreign keys。
- 初始化幂等，可重复执行。
- `tasks` 与 `notices` 字段遵循 SDS §7.3。
- 时间保存为 UTC ISO 8601。
- `completed_stages` 和 `config_snapshot` 保存为 JSON 文本。

## 3. 终态发布接口

T-004 不写运行 JSON。定义可注入接口供 T-005 实现：

```python
class TerminalPublisher(Protocol):
    def publish_completed(self, task: TaskRecord, execution) -> None: ...
    def publish_failed(self, task: TaskRecord, error: BaseException) -> None: ...
    def publish_cancelled(self, task: TaskRecord, cancelled: RunCancelled) -> None: ...
    def publish_interrupted(self, task: TaskRecord, reason: str) -> None: ...
```

提交顺序：

1. 组装终态上下文。
2. 调用 `TerminalPublisher` 发布规范结果。
3. 发布成功后，在 SQLite 中提交同一终态。
4. 广播或通知外部观察者。

发布器抛错时，SQLite 任务保持非终态，并记录存储错误。T-004 不得提前标记 Completed、Failed、Cancelled 或 Interrupted。

## 4. 服务接口

```python
class TaskService:
    def start(self) -> None: ...
    def submit(self, plan_id: str, plan_version: str, variant_id: str) -> str: ...
    def get(self, run_id: str) -> TaskRecord: ...
    def list_tasks(self) -> list[TaskRecord]: ...
    def cancel(self, run_id: str) -> None: ...
    def stop_normal(self, reason: str = "服务关闭") -> None: ...
```

- `submit()` 从 T-002 方案目录解析唯一变体，生成 Run ID、保存配置快照和 Pending 状态。
- 返回值为 Run ID。
- 同一实例只允许一个工作线程。
- 等待顺序按提交时间，再按 SQLite 插入顺序。
- 浏览器、HTTP 或客户端断连不在本任务范围，服务 API 不因无观察者而取消任务。

## 5. 取消

### 5.1 等待任务

- 删除任务行。
- 不生成运行记录。
- 不调用 TerminalPublisher。

### 5.2 运行任务

- 状态设为 `Cancelling`，设置取消事件。
- 当前执行器阶段继续运行，直到下一个阶段边界。
- 执行器抛出 `RunCancelled` 后，调用 `publish_cancelled()`。
- 发布成功后 SQLite 状态改为 `Cancelled`。
- 重复取消为幂等操作；终态任务取消返回明确冲突。

## 6. 关闭与恢复

### 6.1 正常关闭

1. 停止接受新任务。
2. 单事务统计并删除全部 Pending，必要时插入 `queue_cancelled_on_shutdown` notice。
3. 若当前任务活跃，撤销其终态发布权并调用 `publish_interrupted()`。
4. 发布成功后提交 SQLite Interrupted。
5. 停止工作线程，释放实例锁。

### 6.2 启动恢复

1. 获取实例文件锁。
2. 初始化 SQLite。
3. 单事务删除遗留 Pending；数量大于 0 时插入 `queue_cancelled_on_restart` notice。
4. 查询遗留 Preparing/Running/Cancelling。
5. 通过 TerminalPublisher 发布 Interrupted。
6. 发布成功后更新 SQLite Interrupted，再恢复接单。

如果一个实例锁无法获取，拒绝启动第二个任务服务。

## 7. Notices

`TaskRepository` 提供：

- 读取全部未确认 notices。
- 确认并删除指定 notice。
- 将多个同类提示合并展示由后续 Web 层完成。

服务层必须保证“删除 Pending”和“插入 notice”在同一事务内。

#### 接口实现

- `TaskStatus` 与 `ALLOWED_TRANSITIONS` 严格按 SDS §7.2；非法转换抛出 `TaskStateError`，终态任务取消抛出 `TaskConflictError`。`Pending` 取消通过删除任务行实现，不写入 `Cancelled` 行。
- `TaskRecord` 含任务定义要求的所有字段；`generate_run_id()` 生成 `YYYYMMDDTHHMMSSffffffZ-<6 位小写字母数字>`，符合 T-002 Run ID 规则。
- `TaskRepository`：默认 `data/app/textmind.db`；`initialize()` 幂等建表并启用 WAL，每次连接启用 `foreign_keys`；`tasks`/`notices` 字段与 SDS §7.3 一致；时间保存为 UTC ISO 8601；`completed_stages`/`config_snapshot` 保存为 JSON 文本；每个操作使用独立连接，供工作线程和请求线程共享。
- 队列顺序：`next_pending()` 和 `list_tasks()` 均按 `submitted_at, rowid` 排序，保证同一时间提交时按插入顺序 FIFO。
- 阶段更新：`update_stage()` 只更新 `current_stage`/`completed_stages`，终态任务的阶段事件被忽略，避免取消后阶段回写。
- 单事务保证：`delete_all_pending_with_notice(kind)` 在同一事务中统计并删除 Pending、插入 notice；数量为 0 时不插入。
- `InstanceLock`：POSIX 使用 `flock`，Windows 使用 `msvcrt.locking`；第二个实例获取失败抛出 `InstanceLockError`；服务停止时释放锁。
- `TaskService.start()`：获取实例锁 → 初始化 SQLite → 删除遗留 Pending 并写 `queue_cancelled_on_restart` → 将遗留 Preparing/Running/Cancelling 发布为 Interrupted → 开始接单并启动单个 daemon 工作线程。
- `TaskService.submit()`：只接受 `RunVariant`，参照项或未知方案/变体抛出 `TaskSubmitError`；生成 Run ID，保存包含方案信息、数据集、评价参数和完整变体配置的快照，写入 Pending 后唤醒工作线程。
- 取消：Pending 直接删除任务行且不调用发布器；Preparing/Running 先转 `Cancelling` 并设置取消事件，执行器在下一边界抛 `RunCancelled`；Cancelling 重复取消幂等；终态任务取消返回冲突。
- 终态顺序：先调用 `TerminalPublisher` 发布，发布成功后才在 SQLite 提交同一终态；发布器抛错时任务保持非终态并写入 `error_summary`，不提前标记 Completed/Failed/Cancelled/Interrupted。
- 正常关闭：停止接单 → 单事务删除 Pending 并写 `queue_cancelled_on_shutdown` → 撤销当前任务发布权并发布 Interrupted → 停止并等待工作线程 → 兜底处理关闭期间被取走的活跃任务 → 释放锁。
- 启动恢复：删除遗留 Pending 并写 `queue_cancelled_on_restart`，对活跃任务逐个发布 Interrupted 后再提交 SQLite 终态；重复启动幂等。

#### 接口实现

- 终态互斥：`cancel()`、`_finish_completed()`、`_finish_failed()`、`_finish_cancelled()`、`_interrupt_one()` 均在 `_publish_lock` 内完成状态读取、发布器调用和 SQLite 终态提交。
- `_publish_and_finalize()`：先 `ensure_transition(current, target)`，再调用发布器，最后条件提交终态；任何一步失败都写入 `error_summary` 并保持非终态，不吞掉不一致。
- 取消优先规则：
  - 状态为 `Cancelling` 或 `cancel_requested=True` 时，成功结果改走 `publish_cancelled()` → `Cancelled`。
  - 取消期间执行器抛普通异常：`Cancelling -> Failed`，保留 `cancel_requested=True` 和异常摘要。
- 并发转换：写事务使用 `BEGIN IMMEDIATE` 串行化；`UPDATE ... WHERE run_id=? AND status=?` 校验影响行数；并发取消同一 Running 任务时仅第一次转换成功，其余按幂等返回或明确冲突。
- `Pending` 删除使用条件删除；若工作线程已取走任务，`cancel()` 捕获冲突后转为运行中取消路径。
- 发布失败仍保持非终态：发布器抛错时任务停留在 `Running`/`Cancelling`，`error_summary` 记录“终态发布失败”。
