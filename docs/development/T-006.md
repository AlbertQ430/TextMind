## 3. 本机会话与 CSRF

### 3.1 会话

- Local App 首次访问页面或 `/api/v1/session` 时创建 `local_authenticated` 会话。
- 会话 ID 高熵随机，保存在内存。
- Cookie 名 `textmind_session`，host-only，`HttpOnly`、`SameSite=Strict`、`Path=/`。
- HTTP 下不设置 `Secure`。
- 服务重启后内存会话失效。

### 3.2 CSRF

- 每个会话生成独立 CSRF Token。
- Token 由服务端保存哈希或等价安全形式，并与会话 ID 绑定。
- 页面通过 meta/表单提供 Token。
- JSON 修改请求使用 `X-CSRF-Token`。
- 所有 `POST/PUT/PATCH/DELETE` 必须校验 CSRF 和同源请求。
- 失败返回 `403`，不执行业务写入。
- Token 不写 Cookie、URL、日志或结果 JSON。

## 6. SSE

- 使用 Cookie 会话鉴权。
- 连接后发送 `snapshot`。
- 任务或队列变化发送 `task.updated` / `queue.updated`。
- 每 15 秒心跳。
- 客户端断线不影响任务。
- 连续失败时前端退化为 2 秒轮询 `/api/v1/tasks`。
- 不发送 CSRF Token、文件绝对路径或敏感环境信息。

实现可轮询任务服务快照并在变化时推送，无需新增外部消息服务。

## 7. 前端

- Jinja2 服务端渲染 + 原生 JavaScript/CSS。
- 不引入 Node.js、CDN 或前端构建。
- 所有动态文本使用 `textContent` 或 Jinja 自动转义。
- 按钮提交前从 meta 读取 CSRF Token。
- 状态用文字和视觉共同表达。
- 窄屏折叠导航。
- 任务提交按钮防重复点击，但服务端仍以每次有效请求为独立运行。

#### 接口实现

- `create_app(context=None)`：默认构建 `AppContext`（真实方案目录、临时/默认任务库、执行器、发布器、会话存储），但不启动线程、不访问数据库；`lifespan` 只调用一次 `context.start()` / `context.stop()`；`AppContext.start/stop` 幂等。
- 会话：中间件为每个无 Cookie 请求创建 `local_authenticated` 会话；Cookie 名 `textmind_session`，`HttpOnly; Path=/; SameSite=strict`，HTTP 下不设置 `Secure`；已存在的 Cookie 复用会话；服务重启（新 `SessionStore`）后旧 Cookie 不再有效。`GET /api/v1/session` 返回会话范围与 CSRF Token，并带 `Cache-Control: no-store`。
- CSRF：所有 `POST/PUT/PATCH/DELETE` 校验 `X-CSRF-Token` 与同源 `Origin`；Token 使用 `hmac.compare_digest` 常量时间比较；失败返回 403 `CSRF_INVALID`，不执行业务写入；Token 不写入 Cookie、URL 或日志。
- API：`/api/v1/health`、`/api/v1/session`、`/api/v1/plans`、`/api/v1/plans/{plan_id}`、`POST/GET /api/v1/tasks`、`GET /api/v1/tasks/{run_id}`、`POST /api/v1/tasks/{run_id}/cancel`、`GET /api/v1/events`；错误统一为 `{"error": {code, message, request_id}}`，映射 404/409/422/403。
- 任务提交只接受 `plan_id/plan_version/variant_id`；参照变体、未知方案或变体返回 422；取消 Pending 返回 `Deleted`，终态取消返回 409。
- 页面：`/` 307 重定向 `/plans`；实验中心展示三套方案与变体数量，方案详情展示变体配置、预置标识、资源状态“待资源检查”和运行按钮；`/monitor` 提供实时任务视图；`/results`、`/results/{run_id}`、`/history`、`/settings` 为明确占位页，不含伪造数据。
- SSE：连接先发送 `snapshot`，任务/队列变化发送 `task.updated`，每 15 秒发送 `: ping` 心跳；服务端每 0.5 秒轮询任务快照；断线只结束当前流；载荷不含 CSRF Token、Cookie 或绝对路径。
- 前端：Jinja2 + 原生 JS/CSS，无 CDN；动态文本一律 `textContent`；运行按钮防重复点击；SSE 连续失败 3 次后切换为 2 秒轮询 `/api/v1/tasks`；取消后按钮显示“无法立即取消”说明。

#### 接口实现

- `RequestValidationError` → 422 `VALIDATION_ERROR`，`details` 为 `"variant_id: Field required"` 形式的字段明细。
- 未知 API 路径 → 404 `NOT_FOUND`；方法不允许 → 405 `METHOD_NOT_ALLOWED`；其他框架 HTTP 错误映射 `BAD_REQUEST`/`UNAUTHORIZED`/`FORBIDDEN`/`CONFLICT`/`HTTP_ERROR`；API 路径未处理异常 → 500 `INTERNAL_ERROR` 并写应用日志。
- 非 `/api/` 路径的框架 404/405 保持纯文本响应，页面路由自行返回 Jinja 占位页。
- 同源：`Origin.scheme == request.url.scheme`、`hostname` 小写相等、`port` 相等；缺省端口按 80/443 归一化；无 Origin 视为同源（非浏览器客户端）。
