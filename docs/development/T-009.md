## 1. 任务定义

### 1.1 目标

实现主机设置与按变体资源检查，使缺少外置数据集或模型时只禁用对应变体；把设置接入执行器的本地离线加载路径；提供可复现的 17 条预置结果构建脚本；补齐 SciFact 来源、署名、许可证和模型准备说明。

### 1.2 范围

包含：

- `data/app/settings.json` 的读取、默认值、Schema 校验和原子更新。
- 模型根目录、DuRetrieval 目录和设备设置。
- 设置页和 `GET/PUT /api/v1/settings`。
- 按数据集、模型和变体计算资源状态。
- 方案 API/页面显示可用状态，缺资源时禁用受影响运行按钮。
- 提交 API 的后端资源门禁。
- 执行器按设置使用本地 SciFact、DuRetrieval 和模型目录，不自动下载。
- 17 个预置运行记录的离线构建、单运行图表和校验。
- `settings.changed` SSE 事件及设置相关页面刷新。
- SciFact NOTICE、来源和许可证文件。
- 模型来源、revision、目录约定和准备说明。

不包含：

- LAN 监听、访问码和网络开关键；T-010 实现。
- 自动下载数据集或模型。
- 自动扫描磁盘寻找可用资源。
- 修改、复制或整理用户模型/数据集文件。
- 结果导入、删除、比较规则变更。
- 发布安装包本身；T-011 执行双平台发布验收。

## 2. 设置模型

### 2.1 文件

路径：

```text
data/app/settings.json
```

初始结构：

```json
{
  "schema_version": 1,
  "model_root": null,
  "duretrieval_root": null,
  "device": "auto",
  "network": {
    "lan_enabled": false,
    "local_port": 8765,
    "lan_port": 8766
  }
}
```

- 文件不存在时返回默认值，不要求启动时立即写文件。
- 文件存在时严格校验未知字段、类型、端口范围、`local_port != lan_port` 和设备枚举。
- 设置文件损坏时不得静默覆盖；页面和 API 返回明确错误，预设结果仍可读取。
- 保存使用同目录临时文件、flush/fsync 和原子替换。
- `settings.json` 不保存访问码、会话、令牌、任务状态或资源扫描结果。
- `model_root`、`duretrieval_root` 保存规范化绝对路径；不存在也允许保存，由资源检查报告。

### 2.2 设备

支持：

- `auto`
- `cpu`
- `cuda`
- `mps`

资源/环境摘要显示实际生效设备。显式 `cuda`/`mps` 不可用时把依赖模型的变体标为不可运行；不得悄悄回退到 CPU。`auto` 按现有设备解析器选择。

### 2.3 网络字段

- T-009 只读取、校验和保留网络字段。
- 设置页显示“局域网开关由后续任务实现”，不得伪造开关。
- 不新增 enable/disable API；T-010 负责监听和访问码。

## 3. 设置 API

### 3.1 GET `/api/v1/settings`

返回：

```json
{
  "settings": {"schema_version": 1, "...": "..."},
  "resources": {
    "datasets": [],
    "models": [],
    "device": {"configured": "auto", "effective": "cpu", "available": true}
  },
  "environment": {
    "python": "3.11.x",
    "platform": "...",
    "dependencies": {"fastapi": "..."}
  }
}
```

- 不返回访问码、主机名、用户名、IP 或模型绝对文件路径列表。
- 可返回用户配置的根目录，因为本机设置页需要编辑；LAN 权限由 T-010。
- 环境版本通过已安装包元数据读取，不加载 torch 模型。

### 3.2 PUT `/api/v1/settings`

请求只接受：

```json
{
  "model_root": "/path/to/models",
  "duretrieval_root": "/path/to/duretrieval",
  "device": "auto"
}
```

- 字段不可缺失；路径可传 `null`。
- 使用 CSRF 和统一错误结构。
- 网络字段由服务端保留，不允许此接口修改。
- 保存后返回与 GET 相同的最新快照。
- 正在运行的任务不重新加载资源；后续任务使用新设置。

### 3.3 错误

| HTTP | `code` | 场景 |
| --- | --- | --- |
| `422` | `SETTINGS_INVALID` | 设置或请求字段非法 |
| `409` | `SETTINGS_READ_ONLY` | 尝试通过本接口修改网络字段 |
| `500` | `SETTINGS_WRITE_FAILED` | 原子写入失败 |

## 4. 资源检查

### 4.1 数据集

SciFact 内置路径：

```text
data/raw/scifact/
  corpus.jsonl
  queries.jsonl
  qrels/test.tsv
```

DuRetrieval 使用设置中的 `duretrieval_root`：

```text
<duretrieval_root>/
  corpus.jsonl
  queries.jsonl
  qrels_dev.tsv
```

- 必需文件必须存在且非空。
- 未配置、路径不存在、文件缺失、不可读分别给出明确原因。
- 不得自动创建、下载、复制或移动数据文件。
- DuRetrieval 状态必须明确标注 `dev` 划分。

### 4.2 模型

模型目录固定为：

```text
<model_root>/<variant.model.directory_name>/
```

基本检查：

- 目录存在且可读。
- `config.json` 存在且非空。
- 存在 `model.safetensors`、`pytorch_model.bin`、`model.safetensors.index.json` 或 `pytorch_model.bin.index.json` 之一。
- 分片索引引用的权重文件均存在。
- 至少存在 `tokenizer.json`，或同时存在 `tokenizer_config.json` 和词表相关文件。
- 不加载模型权重进行 Web 请求级检查。

状态：

- `available`
- `not_configured`
- `missing`
- `invalid`

原因文本不得包含主机名、用户名或设备 IP。

### 4.3 变体

- BM25 需要方案数据集。
- Dense / Hybrid 需要方案数据集和对应模型。
- 显式不可用设备使所有 Dense / Hybrid 不可运行。
- ReferenceVariant 显示“参照结果，无需运行资源”。
- 一个变体缺资源不得影响其他变体和预置结果。

变体状态结构至少包含：

```json
{
  "state": "available",
  "summary": "资源可用",
  "missing": []
}
```

`missing` 使用稳定资源标识和可理解中文说明，不返回绝对路径。

## 5. 方案与提交

### 5.1 方案 API/页面

- `/api/v1/plans` 增加每方案可运行变体数量。
- `/api/v1/plans/{plan_id}` 的每个 run variant 返回真实资源状态。
- `/plans` 和 `/plans/{plan_id}` 显示可用数量和资源原因。
- 只有资源可用的运行变体启用“运行”按钮。
- 预置结果仍可直接打开，不依赖当前资源。
- 设置变化后，资源依赖页面重新加载。

### 5.2 后端门禁

- `POST /api/v1/tasks` 在提交前检查同一资源状态。
- 资源不可用时返回 409 `RESOURCE_UNAVAILABLE`，不得创建 Pending 行。
- 未知方案/变体和参照结果仍返回既有 422 语义。
- 仅在前端禁用按钮不视为满足验收。

## 6. 离线执行器

- SciFact 数据路径固定为应用内置目录。
- DuRetrieval 数据路径来自当前设置。
- Dense/Hybrid 模型只从 `<model_root>/<directory_name>` 加载。
- 向 SentenceTransformer 传入本地目录并启用本地文件模式，禁止按 Hub 名称联网下载。
- `device` 来自设置：
  - `auto` 使用现有设备解析；
  - 显式值不可用时任务不应被提交。
- 资源在任务提交时检查，执行阶段再次按本地路径读取；设置变化不得改变已运行任务的路径对象。
- 不修改检索算法、缓存格式、指标或计时口径。

## 7. 预置结果构建

### 7.1 脚本

新增：

```bash
.venv/bin/python scripts/build_presets.py --output <dir>
.venv/bin/python scripts/build_presets.py --check-assets-only
```

- 默认输出 `results/presets`。
- 已存在目标目录时默认拒绝覆盖；显式 `--force` 才允许替换本脚本生成的预置目录。
- 构建和校验失败返回非零退出码。

### 7.2 映射

对 `config/plans.json` 的每个 `RunVariant.preset_source`：

1. 读取原始 JSON，不修改原文件。
2. 校验数据方法、模型名、revision、查询前缀、BM25/RRF 参数、top_k、k_values 与方案一致。
3. 生成稳定 `preset_run_id`。
4. 复制原始 metrics、num_queries、num_skipped 和 environment。
5. 按 SDS §8.5.3 映射旧 timing。
6. dataset 使用方案名称/划分和原始规模。
7. variant_config 使用方案配置并补 `top_k`、`k_values` 和实际模型 revision。
8. 生成 metrics/timing 单运行图表。
9. 成功图表进入 `charts`，失败图不补预期路径。
10. 通过 `RunRecord` Schema 后原子发布。

旧结果没有正式起止时间：

- 使用源文件 `mtime`（UTC）作为归档结束时间。
- 开始时间使用以下精确推导，缺失项按 0 处理：

```text
archived_duration =
    dataset_load_seconds
  + model_load_seconds
  + index_build_seconds
  + query_cache_load_seconds
  + query_encode_seconds
  + retrieval_total_seconds

started_at = finished_at - archived_duration
```

- 父级 `index_build_seconds` 已包含文档缓存/语料编码或方法索引准备，不再重复加子项。
- 旧结果没有 evaluation 耗时，推导开始时间不额外猜测该值。
- 不修改原始 timing，不把推导时间写回源文件。
- 构建输出和 README 必须提示这是归档时间推导。

### 7.3 输出与一致性

- 17 个唯一 RunVariant 各生成一份预置记录。
- RRF 等权 ReferenceVariant 复用 `duretrieval-comparison` 的同一预置记录，不新增第 18 条运行。
- DuRetrieval 预置记录必须保留 `split=dev`。
- 所有生成记录通过 Schema，图表路径安全且只含本变体数据。
- 重复构建结果稳定；不得修改 `data/evaluation/*.json`。
- 任一变体映射失败时输出变体 ID 和原因，最终退出非零。
