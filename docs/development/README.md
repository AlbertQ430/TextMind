# TextMind 开发协作索引

本目录用于 Codex 与 DeepSeek Harness（DSH）的文档化协同开发。

## 1. 核心规则

- 根目录 [AGENTS.md](../../AGENTS.md) 定义角色、状态流转和验收规则。
- 每个开发任务使用一个 `T-xxx.md`。
- 同一个任务文件同时保存任务定义、实现交接和验收结论。
- 需求基线是冻结的 [SRS v0.2](../requirements/SRS.md)。
- 设计基线是评审通过的 [SDS v0.1](../design/SDS.md)。
- 验收追溯见 [SRS 至 SDS 矩阵](../design/srs-v0.2-traceability.md)。

## 2. 任务状态

| 状态 | 含义 | 进入该状态的负责人 |
| --- | --- | --- |
| 准备 | 任务已定义，可由 DSH 实现 | Codex |
| 待验收 | DSH 已实现和自测，等待 Codex 核验 | DSH |
| 返工 | Codex 发现缺陷或缺少证据，需要 DSH 修改 | Codex |
| 完成 | Codex 已完成验收，任务关闭 | Codex |

## 3. 工作流程

1. Codex 根据 SRS、SDS 和追溯矩阵创建 `T-xxx.md`，状态设为“准备”。
2. DSH 只实现任务允许范围内的代码和测试。
3. DSH 追加实现交接 R*n*，提供真实测试证据，将状态改为“待验收”。
4. Codex 检查差异并复跑测试，在任务文件追加验收结论 R*n*。
5. 不通过时写“返工”，DSH 修改后进入下一轮“待验收”。
6. 通过时将状态改为“完成”，并更新本索引。

## 4. 任务文件命名

```text
T-001.md
T-002.md
T-003.md
```

- 编号按创建顺序递增，不复用已删除或废弃编号。
- 新任务从 [TEMPLATE.md](TEMPLATE.md) 复制。
- 任务文件标题必须包含任务 ID 和简短名称。

## 6. 开发启动前置条件

具体任务拆分前，应先确认：

- 当前 Git 工作区没有未归属的修改。
- 依赖版本和安装方式具备可验证方案。
- 当前阶段的验收命令可实际运行。
- 任务之间没有未记录的接口依赖。

## 7. 禁止事项

- 不使用聊天中的口头结论替代任务文件。
- 不在任务文件之外维护第二份实现交接或验收报告。
- 不让 DSH 自行降低验收标准或扩大任务范围。
- 不在未说明原因的情况下跳过失败检查。
- 不直接把复杂需求整体交给 DSH 而不拆分任务边界。
