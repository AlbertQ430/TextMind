## 1. 任务定义

### 1.1 目标

补齐发布前缺失的双平台启动入口、可重复构建的发布包和端到端验收证据，使 SRS 的 36 条验收标准均有明确实现证据或真实人工验收记录。

本任务不是功能扩张。端到端验收发现业务缺陷时，应先在任务文件中记录复现、影响和建议修复范围；未经 Codex 确认不得顺带修改核心业务行为。

### 1.2 范围

包含：

- macOS `start.command` 与 Windows `start.bat` 双击启动入口。
- README 的 Windows / macOS 安装、环境检查和启动命令。
- 声明浏览器支持范围及发布验收矩阵。
- 可重复构建的发布 ZIP、固定顶层目录和文件清单。
- 发布包必须包含 SciFact 原始数据、来源/署名、许可证和结果目录说明。
- 从发布包解压后的真实进程启动冒烟测试。
- 通过 Web API 完成一次真实 SciFact BM25 运行并核对结果文件。
- 补齐 AT-001 至 AT-036 的实现验收证据。

不包含：

- 公网访问、HTTPS、账号体系或新的局域网功能。
- 随包分发 Embedding 模型或 DuRetrieval 数据。
- 改变任务状态机、结果 Schema、检索算法或既有 API。
- 自动安装依赖、自动下载资源或自动打开浏览器。
- 推送远程仓库、创建 PR 或发布正式版本。

## 2. 接口契约

### 2.1 双平台启动入口

`start.command`：

- 从自身所在目录定位项目根目录，不依赖用户当前工作目录。
- 使用 `.venv/bin/python scripts/start.py`。
- `.venv` 或项目内 Python 缺失时，以非零退出码结束，并在终端给出运行 `scripts/install.py` 的指引。
- 不自动创建虚拟环境、不自动安装依赖。

`start.bat`：

- 从 `%~dp0` 定位项目根目录，不依赖当前工作目录。
- 使用 `.venv\Scripts\python.exe scripts\start.py`。
- 缺少虚拟环境时，以非零退出码结束，并在终端给出运行 `scripts/install.py` 的指引。
- 不自动创建虚拟环境、不自动安装依赖。

README 必须分别给出 Windows 与 macOS 的：

- Python 3.11 入口和 `scripts/install.py` 调用方式。
- `scripts/check_env.py` 调用方式。
- `scripts/start.py` 或双击入口的启动方式。

### 2.2 发布包

新增命令：

```bash
.venv/bin/python scripts/package_release.py --check
.venv/bin/python scripts/package_release.py --output dist/textmind-0.1.0.zip
```

`--check`：

- 只读检查必需文件和发布排除项。
- 成功返回 0；缺失或不应发布的内容存在时返回非零并输出具体路径。

`--output`：

- 调用同一检查，然后构建 ZIP。
- ZIP 顶层目录固定为 `textmind-0.1.0/`。
- 不得包含 `.git/`、`.venv/`、`data/app/`、`logs/`、`.DS_Store`、`__pycache__/`、`*.pyc`、`results/runs/`、`results/imports/` 或 `dist/`。
- 必须包含 `README.md`、`NOTICE.md`、`requirements.lock`、`pyproject.toml`、`start.command`、`start.bat`、`scripts/`、`src/`、`config/`、`schemas/`、`data/raw/scifact/`、`data/evaluation/`、`resources/scifact/`、`results/README.md` 和相关 `docs/`。
- 必须在暂存目录运行现有预置构建逻辑，将 17 条 `results/presets/<run_id>/` 记录及图表放入 ZIP；不得把本机 `results/runs/` 或 `results/imports/` 带入发布包。
- 必须生成包内 `MANIFEST.txt`，按 POSIX 相对路径排序，记录除 `MANIFEST.txt` 外每个文件的 SHA-256。
- 输出成功信息时打印最终 SHA-256；重复输入相同文件应产生一致的归档条目顺序。

README 与 SDS §18.3 必须一致声明该支持范围。人工验收不能只记录“浏览器可用”，必须写明实际浏览器和版本。

### 2.4 端到端启动与运行

自动化测试必须从发布 ZIP 解压后的目录启动真实 Uvicorn 进程，不得直接用当前仓库根目录作为被测目录。

最低检查：

- 进程在空闲端口启动后，`GET /api/v1/health` 返回 200。
- `/plans`、`/monitor`、`/history`、`/settings` 可访问。
- Local 会话创建、CSRF 和页面导航正常。
- 提交 `scifact-bm25`，轮询到 `Completed`。
- 生成 `results/runs/<run_id>/run.json` 和记录中声明的全部图表。
- `run.json` 通过正式 Schema 校验，任务状态与记录状态一致。
- 测试结束后正常停止服务并回收线程/进程。

测试不得写入当前工作区的 `data/app/`、`logs/` 或 `results/`。

### 2.5 禁止自动下载

- `scripts/install.py` 只安装 `requirements.lock` 中声明的 Python 依赖。
- 应用运行时模型加载必须继续使用本地目录和 `local_files_only=True`。
- 缺少模型或 DuRetrieval 时只禁用受影响变体，页面显示准备提示。
- 交付测试必须阻止应用主动访问外部资源；不得仅通过阅读 README 声称满足。

#### 接口实现

- `start.command`：`dirname "$0"` 定位根目录；`.venv/bin/python` 不存在时输出 `scripts/install.py` 指引并 `exit 1`；存在时 `exec .venv/bin/python scripts/start.py "$@"`。
- `start.bat`：`cd /d "%~dp0"`；`.venv\Scripts\python.exe` 不存在时输出指引并 `exit /b 1`；存在时转发 `%*`；纯 ASCII，Python 以文本读取断言。
- `package_release.py`：
  - `check_release(root)` 返回缺失/为空路径列表；`--check` 输出并返回非零。
  - `build_release(output)`：显式复制必需文件与目录 → 暂存目录调用 `build_presets.build_all` 生成 17 条预置 → 扫描禁止项 → 生成 `MANIFEST.txt`（相对路径排序，`sha256  path`）→ 按序写入 ZIP（固定 `ZipInfo` 时间戳、`start.command` 0755）→ 返回 ZIP SHA-256。
  - 顶层目录固定 `textmind-0.1.0/`；相同输入条目顺序一致。
- `test_e2e_smoke.py`：`package_release.build_release` → 解压 → `subprocess` 启动 `scripts/start.py --port <free>`（`sys.executable`，cwd=解压目录）→ 轮询 health → 会话/CSRF → 五页面 → 提交 `scifact-bm25` 轮询 `Completed` → 校验 `run.json`、图表、状态一致与工作区未被写入 → 终止进程并回收管道。
